### Р-01 · Отдельное приложение: сайт-PWA и сервер комнат на Cloudflare
31.10.2026

Комнаты споров с друзьями — отдельное приложение, не модуль «Фишек» и не семьи (Ш-182). Общая комната с разных телефонов разных людей требует сервера с первого дня: друг в чужой репо данных писать не может. Сервер — Cloudflare Worker, объект на комнату (Durable Object на SQLite), как сервер покера «Фишек»; бесплатного плана хватает. Сервер — источник истины: ставка, исход, жребий — по времени сервера, действия по одному. Сайт — Vite + React + TypeScript, PWA на GitHub Pages. Выбор владельца по рекомендации сессии Штаба 31.10 (Ш-182, Ш-183).

### Р-11 · Журнал комнаты только дописывается; «История»; закрыть, а не удалить

**Почему:** спорам нужна память — кто что ставил и почему так решили; удаление задним числом — повод для нового спора.

**Цена:** журнал растёт; комнаты маленькие — для SQLite объекта это незаметно.

### Р-13 · Двойное нажатие «Создать»: номер комнаты и ключ ведущего — из номера запроса
31.10.2026

- **Как было:** задача #2 требовала, чтобы повтор создания с тем же номером запроса дал ту же комнату и тот же ответ, а ключ телефона хранился только хешем — вместе эти два требования не выполнить случайным ключом.
- **Решено:** телефон шлёт номер запроса `requestId` (ULID); номер комнаты (время из `requestId` + 16 знаков HMAC) и ключ ведущего выводятся HMAC-SHA-256 паролем компании из `requestId` (`server/src/keys.ts`). На сервере — только хеш ключа, `requestId` не хранится; из номера комнаты он не восстанавливается.
- **Почему:** повтор отдаёт тот же ключ без хранения ключа в открытом виде.
- **Цена:** ключ ведущего может вычислить тот, кто знает и пароль компании, и номер запроса, — номер есть только на телефоне ведущего, поэтому телефон держит его как ключ. Пароль компании сменили — повтор старого запроса создания получит отказ; созданные комнаты работают (ключи проверяются по хешу).
- **Миграция:** нет.

Сделал исполнитель в #2 (PR #7) без записи решения; ревьюер отметил оговоркой; владелец согласился слиянием, записано сессией Штаба.

### Р-15 · Вход по ссылке: пять уточнений сервера
31.10.2026

- **Как было:** задача #4 не говорила, как сервер ведёт себя в пяти случаях входа по ссылке; исполнитель решил их сам и назвал в отчёте PR #10 («Не описано в документах»).
- **Решено:**
  1. Повтор той же заявки (двойное нажатие, ответ потерялся) отдаёт тот же ключ: ключ заявки выводится HMAC секретом комнаты (`secret`, заводится при первой заявке) из номера запроса заявки; хранится только хеш — как при создании (Р-13), но без пароля компании: вход от него не зависит.
  2. Занято имя участника и имя ждущей заявки; имя отклонённой заявки свободно.
  3. Решение по заявке не отменяется: отклонённого не впустить (подаёт заявку заново), впущенного не отклонить.
  4. «Ссылку для другого устройства» с «отвязать прежние» может взять и сам участник, не только ведущий; после её использования гаснут и прежние неиспользованные ссылки этого участника — украденный телефон не получит новый ключ.
  5. Использованная ссылка для другого устройства второй раз не срабатывает, даже повтором того же запроса.
- **Почему:** 1 — повтор без хранения ключа в открытом виде; 2–3 — журнал только дописывается (Р-11), спорить о задним числом изменённом решении нельзя; 4 — потерявший телефон участник может спасти себя сам; 5 — так в задаче #4: «второй раз токен не срабатывает».
- **Цена:** ошибочно отклонённый подаёт заявку заново; потерял ответ на «ссылку для устройства» — нужна новая ссылка.
- **Миграция:** нет.

Сделал исполнитель в #4 (PR #10) без записи решения; владелец согласился слиянием; записать поручено задачей #5.

### Р-16 · Свои исходы события: «Другое» последним, без повторов
31.10.2026

- **Как было:** свои исходы события — любой список; если случилось то, чего в нём нет, утвердить нечего.
- **Решено:** к своим исходам (не к «Да / Нет») сервер добавляет последним «Другое (ничего из перечисленного)», на него можно ставить; выпал он, а ставок на него нет — «без игры», ставки возвращаются. Одинаковые варианты сервер не принимает. Пересечение вариантов по смыслу машина не ловит — от него «Как проверяем» и возражение.
- **Почему:** человек: «свои исходы должны покрывать всё пространство возможных исходов»; проверить полноту по тексту нельзя — «Другое» делает список полным всегда.
- **Цена:** в каждом событии со своими исходами — лишний вариант.
- **Миграция:** нет (записей событий ещё нет).

Решение владельца из задачи #16 (блок «Решение»).

### Р-18 · Связь в открытой комнате — опрос раз в 5 секунд, без WebSocket в этапе 2
31.10.2026
