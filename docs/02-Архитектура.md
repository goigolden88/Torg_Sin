# Архитектура

Источник истины для кода: имена, модель, правила. Отступление — вслух и до кода (`CLAUDE.md`). Модель и правила — из ТЗ (Штаб, `docs/замыслы/Тотализатор.md`, Ш-182…Ш-191); имена полей — черновик, уточняет этап 1 и каждый следующий в этом файле.

## Устройство

```
Телефон или компьютер (сайт-PWA на GitHub Pages)     Сервер (Cloudflare Worker)
  React + TypeScript, IndexedDB: журнал        ⇄    объект Room на комнату (SQLite)
  своих комнат, «Мои комнаты», копия                  над правилами src/rules/
  адрес сервера — «Настройки» и ссылка                реестр комнат, будильник к срокам и суду
                                                      запасная обёртка: Node + SQLite (те же тесты)
```

- **Один репо:** сайт (`src/`), сервер (`server/`), общие правила (`src/rules/` — чистые функции, ими пользуются и экран, и сервер; ни DOM, ни Cloudflare). Публичный — данных в нём нет.
- **Сервер — источник истины** (Р-01). Ставка, исход, жребий — только на сервере, по времени сервера; объект комнаты обрабатывает действия по одному — гонок «две ставки в последнюю секунду» нет. Телефон без сети показывает последнее известное; ставить без сети нельзя.
- **Связь:** запрос-ответ; открытая комната и событие спрашивают сервер раз в 5 секунд, пока экран открыт и вкладка видна (`usePoll`); WebSocket в этапе 2 не делаем (Р-18). Версия протокола `PROTOCOL_VERSION` (`src/rules/protocol.ts`) — в каждом ответе и сообщении; не та версия — экран просит обновить страницу.
- **Хранилище за интерфейсом** `RoomStorage` (get, put, list, setAlarm) — две реализации: Cloudflare (`server/src/index.ts`) и Node (`server/node/`, этап 1). Правила о Cloudflare не знают (Р-02).
- **Создание комнаты** — по паролю компании (секрет Worker'а `ROOM_PASSWORD`); вход — по ссылке, без пароля, впускает ведущий (Р-03).
- **Адрес сервера** — `DEFAULT_SERVER` (`src/rules/address.ts`, `https://torg-sin.goigolden88.workers.dev`); свой — в «Настройках» (localStorage `torgsin.server`) и в ссылке комнаты: при переезде телефоны идут на новый адрес сами (Р-02).

## Модель (черновик)

Все записи — с `id` (ULID), автором (`memberId`), временем сервера (`at`, UTC, мс). Суммы — целыми в минимальных единицах валюты комнаты. Итоги, коэффициенты, долги — считаются, не хранятся.

**Журнал комнаты только дописывается** (Р-11): ничего не стирается и не переписывается; отмена, уточнение, исправление — новая запись со ссылкой на прежнюю. Из журнала считаются текущее состояние и экран «История».

- `Room` — название, валюта, ведущий, ссылка-приглашение (меняется), создана, закрыта. В коде (`RoomState`): `id`, `name`, `currency`, `hostId`, `createdAt`, `members`; приглашение — не в журнале, отдельной записью хранилища.
- `Member` — номер (не привязан к способу входа), имя, ключи телефонов, впущен кем и когда, выбыл. В коде: `id`, `name`, `addedBy`, `addedAt`; ключи — только хешами в хранилище сервера, не в журнале. Жизнь комнаты (Р-40, Р-41): `leftAt` — вышел (вернулся — поля нет), `droppedAt` — помечен «выбыл» (сняли — поля нет), `absent: [{ why: 'left' | 'dropped', from, to }]` — промежутки «вне игры» для жребия суда на любой миг; у старых комнат полей нет — все в комнате. Записи и правила — «Правила жизни комнаты в коде».
- **Записи журнала** (`LogEntry`, этап 1): `room.created` (`roomId`, `name`, `currency`; автор — ведущий), `member.added` (`member`, `name`; автор — кто впустил, ведущего при создании — он сам; впущен по заявке — `member` равен номеру заявки), `join.requested` (`request`, `name`; автор — сама заявка), `join.rejected` (`request`; автор — ведущий), `invite.changed` (автор — ведущий; токена нет), `device.issued` (`member`, `unlink`, `expiresAt`; автор — он сам или ведущий; токена нет), `device.linked` (`member`, `unlink`; автор — участник). Состояние — `foldLog` по порядку записей; заявки — `joinRequests` (ждёт, впущена, отклонена; решение — первое).
- **Записи журнала событий** (этап 2): `event.created` (`condition`, `check`, `outcomes: [{ id, title }]` — полным списком, со «Другое», если исходы свои, `closesAt`, `expectedAt`, `subject` — номер участника или `null`, `subjectRule: 1` — признак правила предмета, только у событий с предметом, заведённых после выкатки Р-26 (у старых поля нет), `requestId`; автор — кто завёл; номер события — `id` записи), `bet.placed` (`event`, `outcome`, `amount`, `requestId`; автор — кто поставил; у события с признаком ставка предмета не по правилу Р-26 не действует), `event.clarified` (`event`, `text`; автор — автор события), `event.cancelled` (`event`, `reason` или `null`; автор — кто отменил). `requestId` — номер запроса телефона, не секрет: по нему узнаётся повтор (Р-13). События — `roomEvents` (`src/rules/event.ts`) по порядку записей; записи о неизвестном событии не действуют; отмена — первая; статус — из журнала и времени сервера, не хранится.
- **Записи журнала исхода** (этап 2, Р-17): `outcome.proposed` (`event`, `outcome`, `requestId`; автор — кто предложил), `outcome.objected` (`event`, `reason`, `requestId`; автор — кто возразил), `outcome.agreed` (`event`, `requestId`; автор — кто согласился; Р-21), `outcome.decided` (`event`, `outcome`, `requestId`; автор — ведущий), `outcome.voted` (`event`, `outcome`, `requestId`; автор — голосующий). В `roomEvents`: предложение и решение — первые; предложение снято «ещё не известно» (`withdrawnAt` на время новой записи, Р-27) — следующее `outcome.proposed` начинает новый ход исхода, снятые — в `EventState.withdrawn`; первое предложение до `closesAt` — `closedAt`, ставка после любого предложения не действует; решение и голос `"not-yet"` — только у досрочного предложения; возражение, согласие и голос — первые от участника; возражение без предложения или от согласившегося, согласие без предложения или после первого возражения, решение и голос без возражения не действуют; согласие не ставившего, предложившего или после суток не считается (`eventOutcome`). «Утверждён», «ждёт суда», «окончательный» не записываются — считаются (`eventOutcome`).
- **Записи журнала пари** (этап 3, Р-22): `offer.created` (`condition`, `check`, `side`, `odds: { a, b }`, `amount` — сумма автора, `to` — адресат или `null`, `closesAt`, `expectedAt`, `guarantor` — уже определённый гарант, `counterTo` — встречное к какому пари или `null`, `subject` — о ком спор, только если задан (Р-26; у пари до выкатки и «ни о ком» поля нет — само поле и есть признак правила), `requestId`; автор — кто предложил; номер пари — `id` записи), `offer.accepted` (`offer`, `requestId`; автор — принявший), `offer.revoked` (`offer`, `requestId`; автор — автор пари); исход (Р-23): `offer.marked` (`offer`, `winner` — `author` / `taker`, `requestId`; автор — сторона), `offer.decided` (`offer`, `winner`, `requestId`; автор — гарант), `offer.declined` (`offer`, `requestId`; автор — гарант), `offer.nominated` (`offer`, `guarantor`, `requestId`; автор — сторона). Сумма соперника, статус, фаза исхода и нынешний гарант не записываются — считаются. Пари — `logOffers` (`src/rules/offer.ts`): записи журнала → записи правил (`offer.revoked` журнала — `offer.withdrawn` правил) → `roomOffers` с ведущим и участниками из журнала.
- **Записи журнала апелляции и суда** (этап 4, Р-25): `appeal.filed` (`target` — событие или пари, `reason`, `seed`, `candidates`, `requestId`; автор — подавший), `appeal.joined` (`target`, `requestId`; автор — присоединившийся), `court.drawn` (`target`, `seed`, `candidates`; суд по «ждёт суда», дописывает сам сервер; автор — ведущий комнаты, не проверяется; номера запроса нет), `court.voted` (`target`, `verdict` и `outcome` / `winner`, `requestId`; автор — член суда), `court.replaced` (`target`, `member`, `reason`, `requestId`; автор — ведущий). У `event.created` и `offer.created` — необязательное `times`: сроки, закреплённые при создании (темп комнаты на этот миг); нет поля — обычный набор (все записи до темпа). Темп — `logPace` (`src/rules/pace.ts`): `room.created`, затем последняя `room.pace`, которую разрешает `checkPaceChange`; сроки события и пари — `EventState.times`, `OfferState.times` (`recordTimes` из записи; битое поле — как нет), в ответе их пока нет (протокол — задача сервера).
- **Записи журнала торга** (этап 7, Р-37): у `offer.created` — необязательное `auction: { start, step }` (старт — наименьшая сумма соперника, шаг); только у открытого и не встречного; `closesAt` тогда — исходный конец торга, `odds` — стартовый кэф `{ a: amount, b: start }`; нет поля — обычное пари (все записи до торга). `offer.bid` (`offer`, `amount` — сколько ставит против суммы автора, `requestId`; автор — кто торгуется), `offer.bid-accepted` («принять сейчас»: `offer`, `requestId`; автор — автор пари). Конца торга, продления, принятия лучшего в срок и «не состоялось» в журнале нет — считаются (`offerAt`, `offerStatus`).
- **Записи журнала лота** (этап 7, Р-38): `lot.created` (`title`, `description`, `start`, `step`, `closesAt` — исходный конец торга, `times` — сроки темпа на миг создания (молчание и суд; нет поля — обычный набор), `requestId`; автор — продавец; номер лота — `id` записи), `lot.bid` (`lot`, `amount`, `requestId`; автор — кто ставит), `lot.withdrawn` («Снять лот»: `lot`, `requestId`; автор — продавец), `lot.handed` («Передал»), `lot.declined` («Не смогу передать») — автор продавец, `lot.received` («Получил»), `lot.disputed` («Не получил») — автор победитель; у всех четырёх — `lot`, `requestId`. Лоты — `logLots` (`src/rules/lot.ts`): записи журнала → записи правил `LotRecord` (`lotRecord`, без `requestId`; `court.drawn` о лоте — `{ type: 'court.drawn', lot }`) → `roomLots` с участниками из журнала.
- **Записи журнала выбора** (этап 7, Р-39): `choice.created` (`question`, `options` — названия вариантов автора по порядку, можно пустой список (номера — `'1'`, `'2'`, …), `recipient` — получатель, участник (не задан в форме — ведущий), `cashbox` — подпись «касса», `optionsUntil` — «варианты до», `closesAt` — «вклады до», `requestId`; автор — кто завёл; номер выбора — `id` записи), `choice.option` (`choice`, `title`, `requestId`; автор — кто предложил; номер варианта — `id` записи), `choice.stake` (`choice`, `option`, `amount`, `requestId`; автор — кто вкладывает), `choice.drawn` (`choice`, `seed` — зерно, hex, `options` — равные варианты; жребий при ничьей, дописывает сервер; автор — ведущий, не проверяется; номера запроса нет). Конца с продлениями, победителя, итога и долгов в журнале нет — считаются. Выборы — `logChoices` (`src/rules/choice.ts`): записи журнала → записи правил `ChoiceRecord` (`choiceRecord`, без `requestId`) → `roomChoices` с ведущим и участниками из журнала.
- `Event` (пул) — условие, «как проверяем», исходы (2+; свои — с «Другое» последним, Р-16), приём ставок до, исход ожидается к, автор, предмет (участник, если спор о нём), действует ли правило предмета (Р-26); уточнения автора, отмена. В коде: записи `event.*` журнала, `EventState` / `EventView` (`src/rules/event.ts`, `protocol.ts`; `subjectId`, `subjectRule`).

В коде: записи `choice.*` журнала, `ChoiceState` (`src/rules/choice.ts`), в ответе — `ChoiceView` (`protocol.ts`); правила — раздел «Правила выбора в коде».

## Правила

- **Пул.** Банк события — все ставки; победители делят его пропорционально своим ставкам на исход; остаток единиц — по порядку ставок. Коэффициент исхода = банк ÷ ставки на исход; «вероятность по ставкам» = ставки на исход ÷ банк.
- **Пари.** Автор рискует `a·k`, соперник `b·k`; победитель забирает оба. «3 к 1, сумма автора 300» → соперник ставит 100.
- **Темп комнаты** (Р-35, уточняет Р-05 и Р-31). Сроки исхода, апелляции и суда — из темпа комнаты, четыре: **возражение** (`objection`: возражение на исход пула и окно пометки поздних ставок), **апелляция** (`appeal`: до окончательности у пула и пари), **молчание** (`silence`: автор события после «исход ожидается к», вторая сторона пари, часы гаранта, «нужен другой гарант» до суда), **суд** (`court`: голосование не ставивших и место в суде). Обычный — 24 ч / 7 дней / 3 дня / 72 ч (как было); быстрый — 2 ч / 24 ч / 12 ч / 12 ч; свой — каждый срок из списка: возражение 2, 6, 12, 24, 48 ч; апелляция 1, 2, 3, 7, 14 дней; молчание и суд 12 ч, 1, 2, 3, 5, 7 дней. Темп выбирают при создании комнаты, ведущий меняет в любой момент; сроки закрепляются в каждом событии и пари при создании — смена темпа задним числом ничего не сокращает; своих сроков у отдельного события или пари нет. Ниже сроки названы для обычного темпа.
- **Исход пула.** Сроки — события (Р-35: возражение, молчание, суд; здесь — обычного темпа). Автор предлагает (молчит 3 дня после срока — ведущий) → сутки на возражение → утверждён; до возражения согласились все ставившие (предложивший — согласен; Р-21) — утверждён и окончательный сразу, кроме предложившего никто не ставил — в миг предложения; возражение → ведущий; ведущий ставил → голосуют не ставившие (большинство; ничья — суд сразу). Голосование — в этапе 2 (Р-17): не ставившие и не предмет спора, 72 часа или пока не проголосуют все, большинство поданных; ничья или некому голосовать — «ждёт суда» до этапа 4. «Исход уже известен» (Р-27): тот, кто может предложить исход, предлагает и раньше «приём до» — приём ставок закрывается в миг предложения навсегда, дальше — тот же путь. По возражению на досрочное предложение ведущий (или голосующие, большинством) может выбрать «ещё не известно» — предложение снимается, приём остаётся закрытым, исход предлагают снова, когда ясно, по обычным правилам; предложение после «приём до» так не снимается. Ставки за сутки до досрочного предложения (Р-30) не запрещены — экран исхода показывает их всем пометкой: кто, сколько, на что и за сколько до предложения (`lateBets`: ставки с `at` в [`closedAt` − срок возражения события (24 ч у обычного темпа), `closedAt`]), основание возразить.
- **Исход пари** (Р-05, Р-06, Р-27, Р-31). Все «3 дня» ниже — срок молчания пари, «7 дней» — срок апелляции (Р-35; здесь — обычного темпа). Каждая сторона отмечает исход с подтверждением — в любой миг после принятия, и раньше «исход к». Совпало — утверждён без гаранта и окончательный сразу, в любой момент. До «исход к» исход утверждают только совпавшие отметки (Р-31): разошлось — решает гарант с «исход к» (разошлись позже — сразу); одна молчит — гарант через 3 дня с первой отметки или с «исход к», что позже (не отметил никто — 3 дня после «исход к»); пока он не решил, сторона может поменять отметку. Гарант молчит 3 дня или отказался → стороны выбирают другого (ведущий — по умолчанию, если не сторона). 3 дня без общего гаранта — дело уходит в суд само, как «ждёт суда» у пула (Р-31): суд выбирает «прав автор» / «прав соперник» / «отменить», решение окончательное; судить некому — суда нет, стороны по-прежнему договариваются о гаранте. Пари, предложенные до Р-31 (без пометки в записи), — по прежним часам (Р-27: молчание — 3 дня с первой отметки, расхождение — сразу) и без суда.
- **Пари без гаранта** (Р-36, уточняет Р-05 и Р-31). При создании гарант — выбранный участник, не выбран (ведущий) или «без гаранта». Без гаранта — только если судить есть кому: у адресного — хотя бы один участник, кроме автора, адресата и предмета спора; у открытого — хотя бы двое, кроме автора и предмета (один примет, один судит); иначе «Без гаранта судить некому — выберите гаранта». Отметки совпали — окончательно сразу (Р-06); разошлись или вторая сторона молчит срок молчания — с мига, когда решал бы гарант (те же часы, что у правила Р-31), сразу суд: без часов гаранта и без «нужен другой гарант»; суд — как по Р-31 (кандидаты — все, кроме сторон). Суд не собрать (кандидатов нет) — «нужен гарант»: стороны называют общего, дальше — обычный путь с гарантом. «Утвердить» и «Отказаться» гаранта — «У пари нет гаранта». Встречное — гарант по выбору автора встречного, по тем же правилам. У события-пула способ спора не меняется.
- **«Торг до …»** (Р-37, уточняет Р-04) — второй режим открытого пари. Автор закрепляет сторону, свою сумму, старт (наименьшую сумму соперника) и шаг (по умолчанию 10 % старта, не меньше единицы); конец торга — от 10 минут до 3 дней с создания, «исход к» — не раньше конца + 30 минут. Встречное — одно число: сколько ставишь против суммы автора; первое — не меньше старта, следующее — больше лучшего хотя бы на шаг; не ставят автор, гарант и предмет спора не на своей стороне (Р-26); встречное не отзывается, перебитое — свободно, все видны всем (Р-11). Встречное за 2 минуты до конца переносит конец на 2 минуты после себя, не дальше исходного конца + 30 минут. Автор может «принять сейчас» лучшее в любой миг торга; к концу лучшее принимается само, отклонить его нельзя; ни одного встречного — «не состоялось», никто никому не должен (заново — новым пари). Отозвать — только пока нет встречных. Гарант — как у пари (выбранный, ведущий или без гаранта); принятых и встречных пари у торга нет. Дальше — обычное пари: суммы — автора и принятого встречного, кэф — их отношение (только для показа, предел 1…100 не действует).
- **«Лот»** (Р-09, Р-38) — торг за вещь, цифровой товар или услугу внутри обычной комнаты, рядом с событиями и пари. Продавец (автор) задаёт название, описание, старт и шаг (по умолчанию 10 % старта, не меньше единицы); конец торга — от 10 минут до 3 дней с создания; сроки темпа (молчание, суд) закрепляются при создании. Ставка — не меньше старта, следующая — больше лучшей хотя бы на шаг; продавец не ставит; ставка не отзывается, перебитая — свободна, все видны всем; продление — как у торга пари (ставка за 2 минуты до конца → +2 минуты, не дальше конца + 30 минут). Снять лот — продавец, пока ставок нет; к концу ставок нет — «не продан». Победитель — лучшая ставка. После торга продавец отмечает «Передал» или «Не смогу передать» (лот «не состоялся», никто никому не должен); победитель — «Получил» (в любой момент после конца) или «Не получил» (после «Передал» или когда после конца прошёл срок молчания без «Передал»); после «Передал» победитель молчит срок молчания — считается «получил»; обе стороны молчат — «ждёт передачи», без срока. «Не получил» — суд жребием из участников, кроме продавца и победителя, голоса «передано» / «не передано», решение окончательное, апелляции нет; большинства нет — «не передано»; судить некому — «в споре», пока победитель не отметит «Получил» или продавец — «Не смогу передать». Передача — вне приложения; долг победителя продавцу (его ставка) — в «Расчёт», только когда получено (отметкой, молчанием, судом «передано»).
- **«Выбор»** (Р-09, Р-39) — голосование деньгами внутри обычной комнаты: компания выбирает один из вариантов (куда едем, какой устав). Автор задаёт вопрос, свои варианты (можно ни одного), получателя — участника комнаты (по умолчанию ведущий; подпись «касса» — по желанию, кошелька нет) и два срока: «варианты до» и «вклады до»; каждая фаза — не меньше 10 минут, весь выбор — не дольше 3 дней с создания. **Фаза вариантов:** любой участник добавляет вариант (до 10, одинаковые — отказ); вкладов нет; к концу фазы меньше двух вариантов — «не состоялось». **Фаза вкладов:** новых вариантов нет; участник вкладывает только в один вариант (первый вклад выбирает его), докладывать можно в него же; вклад не отзывается, все видны всем; вклад за 2 минуты до конца → +2 минуты, не дальше «вклады до» + 30 минут. **Итог:** побеждает вариант с большей суммой; ничья в конце — продление на 2 минуты, снова и снова, в тех же +30 минутах; ничья и после — жребий сервера среди равных; вкладов нет — «не состоялось». Каждый вложившийся в победивший должен получателю свою сумму; проигравшие — ничего; вклад самого получателя — не долг; итог окончательный сразу — спора и суда нет.
- **Апелляция.** Срок апелляции события или пари после утверждения (Р-35; 7 дней у обычного темпа), место в суде — срок суда (72 часа у обычного); подаёт ставивший (у пари — сторона) с причиной; одна на событие, другие присоединяются. Суд — ведущий + 2 присяжных жребием из незаинтересованных (не ставили, не стороны, не гарант, не автор и не предмет события, не апеллянт); 72 часа; 2 из 3; голос — «оставить» / «изменить на …» / «отменить событие — вернуть ставки»; решение окончательное.
- **Окончательность.** Событие окончательно, когда прошёл срок апелляции без апелляции (неделя у обычного темпа, Р-35), суд решил, все ставившие в пуле согласились с исходом (Р-21) или стороны пари согласились; только окончательные идут в «Расчёт».
- **Расчёт.** Итог каждого по окончательным событиям и пари → минимум переводов (жадно, от большего долга к большему выигрышу) → получатель отмечает «получил».
  Уточнено Р-32: расчёт живой, без периодов — баланс = итог по окончательным + отдал − получил; у каждого три числа с основанием: итог, ждёт окончательности, в игре. Перевод — в два шага: должник «Перевёл» → получатель «Получил» или «Не получал»; получатель может отметить «Получил» и сам; ошибка — отмена своей отметки новой записью (Р-11). «Кто кому» — в режиме комнаты: **по ставкам** (по умолчанию) — по каждому окончательному событию и пари проигравший платит выигравшему (в пуле — выигравшим пропорционально их выигрышу, остаток единиц — правилом пула), встречные долги пары сворачиваются, переводы пары вычитаются; **меньше переводов** — из балансов, жадно, от большего долга к большему выигрышу. Режим выбирают при создании комнаты; ведущий меняет, пока переводов нет (дальше — только когда все балансы ноль). В комнате на очки переводов нет — «Таблица очков».
- **История** (Р-11). Экран «История» комнаты: прошедшие события и пари — исход, кто сколько ставил, возражения, апелляции, жребий; итог каждого по времени. Закрытая комната остаётся в «Моих комнатах» только для чтения.
  В коде (#72): прошедшее — событие с окончательным исходом или отменённое (и судом); пари окончательное, отменённое судом или не состоявшееся (истекло, отозвано, закрыто встречным); остальное, в том числе голосование, «снято», «ждёт суда», неделя апелляции и фазы гаранта, — не прошедшее (`historyParts`). Прошедшее уходит из «Событий» и «Пари» комнаты; под ними — «История · N» (всё ушедшее); на экране — итоги участников из свода расчёта и список с моим результатом; ставки, возражения, апелляцию и жребий показывает экран события или пари. Подробно — «История на сайте» в `02-Сайт.md`.

## Крайние случаи и как решаются

| Случай | Как решается |
|---|---|
| На выигравший исход никто не ставил; ставки только на один исход | Событие — «без игры»: все ставки возвращаются |
| Ставка после того, как исход стал известен | Приём закрывается в срок автора (ставится до события), по времени сервера; исход ясен раньше срока — «Исход уже известен»: приём закрывается в миг предложения навсегда, ставка после — отказ «Приём закрыт: исход уже предложен» (Р-27); поздняя ставка «на известное» — основание апелляции, суд может отменить событие |
| Условие неясное, спорят о смысле | Шаблон «Условие / Как проверяем / Срок»; после первой ставки текст не меняется — только уточнения, видные всем; поменять по сути — отменить событие и завести заново |
| Спор о самом участнике («я подтянусь 50 раз») | Предмет спора ставит только на «сбудется» (Р-26): в событии «Да / Нет» — только на «Да», в событии со своими исходами — не ставит; у пари — необязательное «о ком спор», предмет только на стороне «сбудется» (автор-предмет — сторона «сбудется»; другой участник принимает, только если автор — за «не сбудется»). Его ставка видна всем пометкой «⚑ <имя> — предмет спора — ставит на себя: 300 ₽ на „Да“» (у пари — «на стороне „сбудется“»); у старых событий, где его ставка на «Нет», — «ставка против себя: 300 ₽ на „Нет“». Тексты о предмете спора и участниках по имени — без рода. Правило — только у событий и пари, заведённых после выкатки (признак в записи), старые свёртываются как раньше. Предмет не объявляет исход, не гарант и не присяжный. Событие ведущего о себе — исход предлагает любой другой участник, первый (Р-19) |
| Доказательство (видео, фото) | В первой версии — ссылка или текст; вложения на сервере — позже |
| Отменить событие | Одно правило на любой шаг (Р-29, `checkCancel` в `src/rules/event.ts`; им пользуются и сервер, и экран): исход окончательный — отмены нет ни у кого; идёт суд (апелляция подана или суд по «ждёт суда» собран, решения нет) — отмены нет, решает суд (у него есть «отменить», Р-24); чужих ставок нет (свои не в счёт) — автор или ведущий, без причины, в любой момент до окончательности; есть — только ведущий и только с причиной, а ведущий, который сам ставил или он — предмет спора, не отменяет (путь — возражение и суд). Исключение — «ждёт суда», а судить некому (суд не собран): ведущий отменяет с причиной, и ставивший — иначе событию нет выхода (Р-19). Ставки возвращаются. Отменено и после утверждения исхода — исход «отменено», выплат нет, окончательным не станет (Р-19). Записи `event.cancelled` из журнала до Р-29 действуют, как были |
| Отменить свою ставку | Нельзя (иначе крупная ставка и отмена двигают коэффициенты); можно добавить. Пари — отзыв, пока не принято |
| Нажал «Поставить» дважды | Ставка — с подтверждением суммы; повтор того же действия с тем же номером сервер не примет дважды |
| Обе стороны пари ошибочно отметили один исход | Отметка — с подтверждением; совпадение окончательно сразу (Р-06) |
| Сторона пари отметила исход задолго до «исход к» | До «исход к» исход утверждают только совпавшие отметки: расхождение и молчание часы гаранта не запускают — отсчёт с «исход к» (Р-31); гарант не решает исход, которого ещё нет |
| Гарант пари промолчал или отказался, а проигрывающий не соглашается на нового | Срок молчания пари без общего гаранта (3 дня у обычного темпа, Р-35) — суд сам, как «ждёт суда» у пула (Р-31); после сбора суда гаранта не назвать и исход не отметить. Судить некому (комната из трёх: стороны и гарант) — суда нет, стороны договариваются о гаранте; экран: «Суд собрать не из кого — договоритесь о гаранте» |
| Пари без гаранта, стороны разошлись (Р-36) | Сразу суд жребием, без часов гаранта; «без гаранта» не выбрать, если судить некому (адресное — нет никого, кроме сторон и предмета; открытое — меньше двоих, кроме автора и предмета). Суд всё же не собрать — стороны называют общего гаранта, дальше — как с гарантом. Пока участников не убирают из комнаты, проверка при создании оставляет хотя бы одного кандидата |
| Торг: встречное в последнюю секунду; автору не нравится лучшее; встречных нет (Р-37) | Встречное за 2 минуты до конца продлевает торг на 2 минуты после себя, не дальше исходного конца + 30 минут («торг закончится не позже …» видно с создания); «исход к» — не раньше этого предела, так продление не уводит торг за исход. Лучшее к концу принимается само, без будильника: автор его не отклоняет — его «нет» это старт (хочет страховку — ставит старт выше). Ни одного встречного — «не состоялось», никто никому не должен. Отозвать — только пока встречных нет |
| Лот: вещь не передана, победитель тянет, судить некому (Р-38) | После «Передал» молчание победителя срок молчания — «получил»: долг в «Расчёте». «Не получил» — суд жребием без продавца и победителя, окончательно; большинства нет — «не передано», долга нет. Комната из двоих (или все, кроме сторон, выбыли) — суда нет, лот «в споре», пока одна сторона не уступит («Получил» или «Не смогу передать»); в приложении такой спор не решить. Обе стороны молчат после конца — «ждёт передачи», долга нет. После сбора суда отметки сторон не действуют |
| Ведущий — сторона или ставил | Не решает возражение и не сидит в суде за ведущего: третий присяжный — жребием |
| Сговор ведущего и друга | Присяжных выбирает жребий сервера; кандидаты и выпавшие видны всем в истории события |
| Присяжный не голосует | Через срок суда события или пари (72 часа у обычного темпа, Р-35) — одна замена жребием; дальше решают проголосовавшие; ничья — исход остаётся |
| Незаинтересованных меньше трёх | Суд из тех, кто есть; ни одного — апелляции нет; экран предупреждает при создании события |
| Апелляция после «Расчёта» | Невозможна по устройству: в расчёт идут только окончательные события |
| Участник пропал с долгом | Долг остаётся в расчёте; выйти из комнаты — только без открытых ставок и с отмеченными переводами; ведущий может пометить «выбыл» — открытые ставки доигрываются (Р-40, Р-41; в коде — «Правила жизни комнаты в коде») |
| Ведущий пропал | 7 дней без запросов ни с одного устройства (при любом темпе) — любой участник в игре может «Взять ведение», берёт первый успевший; все видят в истории, у кого и когда взято. Ведущий может «Передать ведение» участнику сам — так он может и выйти. Прежний ведущий — обычный участник; в событиях и пари, заведённых раньше, гарант и способ спора не меняются (Р-42; в коде — «Правила ведения в коде») |
| Потерял телефон | «Ссылка для другого устройства»; без неё — ведущий привязывает к новому телефону, старый отвязывается |
| Ссылка утекла | Новичка впускает ведущий; ссылку можно сменить — старая перестаёт работать |
| Сервер лежал в момент срока | Приём закрывается по времени сервера: ставка с меткой позже срока отклоняется; будильник срабатывает, когда сервер поднялся |
| Часовые пояса | Время хранится в UTC, показывается местное |
| Разные валюты у друзей | Одна валюта на комнату; другая валюта — другая комната |
| Закрыть или удалить комнату | По умолчанию — «закрыть»: только чтение, история остаётся (Р-11). Удалить — только ведущий, только когда всё окончательно и переводы отмечены; перед удалением у всех — копия |

## Правила пари в коде

`src/rules/offer.ts` (этап 3; записи журнала и адреса сервера предложить / принять / отозвать / встречное — Р-22, исход — Р-23, выше; экраны — следующие задачи этапа). Вход — записи `OfferRecord` (из журнала их собирает `logOffers`; `offer.revoked` журнала — это `offer.withdrawn`, записи исхода — те же, что в правилах): `memberId` — автор записи, `at` — время сервера, порядок — журнала; номер пари — `id` записи `offer.created`. Статусы и итоги считаются, не хранятся.

- **Суммы** (`offerStakes`). Кэф `a к b` — целые 1…100; сумма автора — целое > 0. Соперник ставит сумма × b ÷ a вниз до целой единицы (`BigInt`; «3 к 1», 300 → 100; 100 очков → 33, `exact: false`); меньше единицы — «Сумма соперника меньше одной единицы — увеличьте сумму или кэф»; банк — обе суммы. Итоги (`offerNets`): прав автор — автор +сумма соперника, соперник −она; прав соперник — автор −своя сумма, соперник +она.
- **Форма** (`checkOfferInput`): условие и «как проверяем» — как у события (не пустые, ≤ 300 знаков); `side` — сторона автора `yes` («сбудется», по умолчанию) / `no`; `to` — адресат или `null` (открытое); `closesAt` «приём до» (не включая) — в будущем, `expectedAt` «исход к» — не раньше (`checkOfferTimes`, по времени сервера). Гарант (`offerGuarantor`): выбранный — участник, не автор и не адресат; не выбран — ведущий; ведущий — автор или адресат — «Ведущий — сторона пари: выберите гаранта». Без гаранта (Р-36): в форме `noGuarantor: true` (`OfferInput.noGuarantor`; вместе с `guarantor` — «„Без гаранта“ — тогда гаранта не выбирают», не `true`/`false` — `BAD_GUARANTOR`); `offerGuarantor` даёт `null`, если судить есть кому (`NO_GUARANTOR_JUDGES` — правило в «Правилах» выше). В записи `offer.created` гарант уже определён: участник или `null` — без гаранта (отдельного признака нет: у старых пари `guarantor` — всегда участник, `null` бывает только у новых); `OfferState.guarantorId`, `OfferInfo.guarantorId` и `OfferOutcome.guarantorId` — нынешний гарант или `null`, пока стороны его не назвали.
- **О ком спор** (Р-26; `subject` — участник или `null`, `checkOfferInput`, `checkOfferSubject`): предмет — участник комнаты; предмет — автор — сторона автора только `yes` («Вы — предмет спора: ваша сторона — только «сбудется»»); предмет — адресат — сторона автора только `no` («Предмет спора примет пари, только если ваша сторона — «не сбудется»»). Гарант (`offerGuarantor` с `subject`) — не предмет («Предмет спора не бывает гарантом…»), и новый гарант вместо отказавшегося или промолчавшего — тоже (`checkNominate`); ведущий — предмет и гарант не выбран — «Ведущий — предмет спора: выберите гаранта». Принять (`checkAccept`) и встречное (`checkCounter`, через ту же проверку) предмету — только если автор за `no` («Вы — предмет спора: принять можно, только если автор — за «не сбудется»»); встречное переносит `subject` (`counterInput`). Пометка для всех (`subjectIsSide`): предмет — сторона пари.
- **Статус** (`offerStatus` на `now`): `accepted` → `withdrawn` → `countered` (закрыто встречным) → `expired` (`now ≥ closesAt`) → `open`.
- **Принять** (`offer.accepted`, `checkAccept`): до `closesAt`; адресное — только адресат, открытое — любой участник, кроме автора и гаранта; второй раз — «Пари уже принято». **Отозвать** (`offer.withdrawn`, `checkWithdraw`) — автор, пока не принято и не закрыто встречным.
- **Встречное** — новое `offer.created` с `counterTo` (`counterInput`): свои кэф, сумма и «приём до»; условие, «как проверяем», «исход к» — исходного; сторона — обратная; адресат — автор исходного; гарант — выбор автора встречного (Р-36: `guarantor` — участник, `noGuarantor` — без гаранта, проверка та же — `offerGuarantor`), не выбрал — тот же, что у исходного (у исходного без гаранта — тоже без). Делает тот, кто мог бы принять исходное (`checkCounter`): к принятому, отозванному, закрытому, истёкшему или своему — отказ. Автор принял встречное — исходное `closedBy` («закрыто встречным»), если его ещё можно было принять; уже принятое другим остаётся принятым.
- **Исход** (Р-05, Р-06, Р-27). Отметка стороны `offer.marked` (`winner`: `author` — прав автор, `taker` — прав соперник; `checkMark`) — после принятия, в любой миг (и до `expectedAt`), только стороны (гарант — «Гарант не отмечает исход как сторона…»); действует последняя, повтор той же ничего не меняет. Отметки совпали (и после того, как расходились) до решения гаранта — `agreed`, утверждён согласием и окончательный сразу. Решает гарант (`guarantorTurn`) с мига, как отметки впервые разошлись, или через 3 дня (`SIDE_SILENCE`) после первой отметки, и раньше `expectedAt` (Р-27; никто не отметил — после `expectedAt`). Правило гаранта (Р-31; пометка `guarantorRule: 1` в записи `offer.created` новых пари, в правилах — `guarantorRule: true`, в ответе `OfferInfo.guarantorRule`; у прежних пари поля нет — как выше): расхождение — с max(миг расхождения, `expectedAt`), молчание — 3 дня с max(первая отметка, `expectedAt`), что раньше. Решение `offer.decided` (`checkDecide`) — только нынешний гарант, в свои 3 дня (`GUARANTOR_SILENCE`, с перехода решения к нему или с назначения, что позже); окончательный через 7 дней (`FINAL_TIME`; апелляция — этап 4). Гарант молчит 3 дня или отказался (`offer.declined`, `checkDecline`) — «нужен другой гарант»: каждая сторона называет участника не из сторон и не предмет спора (Р-26; у пари без `subject` — как раньше) (`offer.nominated`, `checkNominate`; действует последнее), назвали одного — он гарант (`guarantorSince`), отсчёт 3 дней — заново.
- **Суд без общего гаранта** (Р-31, только с `guarantorRule`). `courtFrom` — миг `needSince` + 3 дня (`NEED_GUARANTOR_TIME`), пока нужен другой гарант; `courtDue` — он настал. Тогда суд собирается сам — запись журнала `court.drawn` по пари (`checkCourtDraw`, кандидаты — `courtCandidates`: без сторон и нынешнего гаранта). `logOffers` переводит `court.drawn` о пари в запись правил `{ type: 'court.drawn', offer }`: первая в срок ставит `courtAt`; после неё отметки, решение и отказ гаранта, назначение не действуют (`checkMark`, `checkDecide`, `checkDecline`, `checkNominate` — «Пари решает суд — назвать гаранта и отметить исход уже нельзя», `IN_COURT`), так что ход до сбора не меняется. Суда не собрали (кандидатов нет) — фаза остаётся `need-guarantor`, назвать гаранта можно.
- **Суд по пари без гаранта** (Р-36; `guarantorId === null`). Часов гаранта нет: `guarantorUntil` — `null`; с `turnAt` (`guarantorTurn`, те же часы, что у правила гаранта) фаза — `need-guarantor` с `needSince = turnAt`, `courtFrom` = `turnAt` — суд пора сразу, без `NEED_GUARANTOR_TIME` (у этого пути `guarantorRule` не нужен). Сервер собирает суд при первом запросе (`drawDueCourts`) — в ответе сразу `court`; кандидаты — все, кроме сторон (гаранта нет). `checkDecide`, `checkDecline` — «У пари нет гаранта» (`NO_GUARANTOR`), раньше всех прочих проверок. Суд не собрать — стороны называют гаранта (`checkNominate`), назвали одного — `guarantorId`, `guarantorSince`, дальше — обычный путь: часы гаранта с назначения, молчит или отказался — «нужен другой гарант» и суд через срок молчания (Р-31).
- **Ответ** (`offerOutcome` на `now`; не принято — `null`): `phase` — `marking` / `guarantor` / `need-guarantor` / `court` («ждёт суда», Р-31: суд собран) / `approved` / `final`, `marks` (последняя отметка каждой стороны), `guarantorId` (без гаранта — `null`), `turnAt`, `guarantorUntil`, `needSince`, `nominations`, `approved` (`{ winner, at, how: 'agreement' | 'guarantor', by }`), `finalAt`. Итог для «Расчёта» (`offerResult`) — только окончательное: `[{ memberId, net }]` автора и соперника. С апелляцией (Р-24) — ещё `how: 'court'`, фаза `cancelled` и поля `appeal` / `court`: раздел «Правила апелляции в коде».
- **Сроки пари** (Р-35): `SIDE_SILENCE`, `GUARANTOR_SILENCE`, `NEED_GUARANTOR_TIME` и `FINAL_TIME` выше — значения обычного набора; правила берут сроки пари `timesOf(o)` (`OfferState.times` из поля `times` записи `offer.created`, нет — обычный набор): молчание стороны, часы гаранта и «нужен другой гарант» до суда — `silence`, окончательность решения гаранта — `appeal`. Константы остаются для экранов, пока они не знают темпа.
- **Свёртка** (`roomOffers(records, { hostId, members })`): запись действует, если её разрешает та же проверка на её время `at` — сервер и свёртка не расходятся; записи о неизвестном пари не действуют.
- **Торг** (Р-37; записи — «Записи журнала торга» в модели). Форма (`checkOfferInput` с `auction: { start, step? }` вместо `odds`): старт — целое > 0 (`BAD_START`), шаг не задан — `auctionStep` (10 % старта вниз, не меньше 1), иначе целое > 0 (`BAD_STEP`); банк — точное целое (`BANK_TOO_BIG`); адресат — «Торг — только открытое пари…» (`AUCTION_ADDRESSED`); в `OfferInput` — `auction: { start, step }` и `odds: { a: amount, b: start }`. Сроки (`checkOfferTimes` с `auction`, по времени сервера): `closesAt` — не раньше `now` + 10 минут (`AUCTION_MIN`, `AUCTION_SHORT`), не позже `now` + 3 дня (`AUCTION_MAX`, `AUCTION_LONG`); `expectedAt` — не раньше `auctionLatestEnd` = `closesAt` + 30 минут (`AUCTION_EXTEND_MAX`, `AUCTION_EXPECTED`). Сроки торга — постоянные, не темпа. Гарант и предмет — `offerGuarantor`, `checkOfferSubject`, как у открытого. Свёртка берёт запись торга, только если `to` и `counterTo` — `null`, старт и шаг — целые > 0, `odds` — `{ amount, start }`. Состояние — `OfferState.auction` (`AuctionState`: `start`, `step`, `endsAt` — конец с продлениями, `bids` — действующие встречные по порядку, последнее — лучшее (`bestBid`), `taken` — `now` / `end` / `null`); у обычного пари поля нет.
  - **Встречное** (`offer.bid`, `checkBid(o, участник, amount, room, now)`): не торг — `NOT_AUCTION`; отозван — `WITHDRAWN`; кончился (принят, «не состоялось», `now ≥ endsAt`) — `AUCTION_OVER`; автор — `OWN_BID`; гарант — `GUARANTOR_BIDS`; предмет спора при стороне автора `yes` — `SUBJECT_BIDS`; не участник — `NOT_MEMBER`; сумма — целое > 0 (`BAD_BID`), банк — точное целое; первое < старта — `BID_LOW`, следующее < лучшего + шаг — `BID_STEP`. Свою перебить можно. Продление: `endsAt` = min(`auctionLatestEnd`, max(`endsAt`, `at` + 2 минуты)) (`AUCTION_EXTEND`).
  - **«Принять сейчас»** (`offer.bid-accepted`, `checkTakeBid`): только автор (`ONLY_AUTHOR_TAKES`), пока торг идёт (`AUCTION_OVER`), встречные есть (`NO_BIDS`) — `accepted` = `{ by: лучший, at }`, `taken: 'now'`. **Конец торга** — без записи (`offerAt(o, now)`): `now ≥ endsAt`, встречное было, не отозван — `accepted` = `{ by: лучший, at: endsAt }`, `taken: 'end'`; свёртка делает то же перед каждой записью о пари с `at ≥ endsAt` (встречное в миг конца уже не действует). Правила с `now` (`offerStatus`, `checkDecide`, `checkDecline`, `checkNominate`, `courtFrom`, `offerOutcome`, `offerResult`, `offerView`) берут пари через `offerAt` сами; проверки без `now` (`checkMark`, `checkWithdraw`, `sideOf`) — на пари, которое им дали: сервер даёт `offerAt(o, now)`.
  - **Статус** (`offerStatus`): торг закрывается по `endsAt`, не по `closesAt`: принят — `accepted`; отозван — `withdrawn`; `now ≥ endsAt` без встречных — `failed` («не состоялось»); иначе — `open`. `checkAccept` и `checkCounter` к торгу — отказ раньше прочих (`AUCTION_ACCEPT`, `AUCTION_COUNTER`): иначе его приняли бы по старту. **Отозвать** (`checkWithdraw`) — ещё и `AUCTION_HAS_BIDS`, если встречное есть.
  - **Суммы** (`offerAmounts`): обычное пари — `offerStakes`; торг — сумма автора и лучшего встречного (принятого — оно и есть лучшее), без встречных — старт; `exact: true`; кэф 1…100 не применяется. Итог (`offerResult`, «Расчёт») — по ним; «не состоялось» не принято — не в счёт.
  - **Ответ.** `OfferInfo` торга: `takerAmount` — `offerAmounts`, `odds` — `{ a: amount, b: takerAmount }` (отношение сумм, для показа), `auction: { start, step, latestEnd }` («торг закончится не позже …»). `OfferView.bidding` (`biddingView` на `now`): `bids` (`{ id, at, by, amount }` по порядку), `best`, `endsAt`, `result` — `{ how: 'now' | 'end', at, bid }` (принято, каким встречным), `{ how: 'failed', at: endsAt }` или `null` (идёт или отозван). У обычного пари полей нет. Протокол: статус `failed` и поля — в `protocol.ts` и `isOfferView`; версия — 8 (сервер торга, #116; адреса — `02-Сервер.md`, «Пари»).

## Правила апелляции в коде

`src/rules/appeal.ts` — кто подаёт, кто судит, проверки и свёртка; `src/rules/court.ts` — жребий, места, решение (отдельно, чтобы `event.ts` и `offer.ts` не зависели от `appeal.ts`). Этап 4, Р-05, Р-24; записи в журнале комнаты и адреса — Р-25 («Апелляция и суд» в адресах и «Записи журнала апелляции и суда» в модели), экраны — следующая задача этапа. Вход — записи `AppealRecord` (`memberId` — автор, `at` — время сервера, `target` — событие или пари, порядок — журнала); будильника нет — всё считается на `now`. Длины текстов — как у события (≤ 300 знаков, пробелы по краям срезаются).

- **Записи.** `appeal.filed` (`target`, `reason`, `seed`, `candidates`; автор — подавший; суд собран в этот миг), `appeal.joined` (`target`; автор — присоединившийся), `court.drawn` (`target`, `seed`, `candidates`; суд по «ждёт суда» без апелляции; автор не проверяется), `court.voted` (`target`, `verdict`: `keep` / `change` с `outcome` (пул) или `winner` (пари) / `cancel`; автор — член суда), `court.replaced` (`target`, `member`, `reason`; автор — ведущий).
- **Подать** (`checkAppeal`): исход утверждён и ещё не окончательный (срок апелляции цели с утверждения — `appeal` её сроков, Р-35; у обычного темпа 7 дней, `FINAL_TIME`; отказ — «Исход уже окончательный: срок апелляции прошёл»); утверждён согласием (у пула — всех ставивших, Р-21, у пари — сторон) — «Исход утверждён согласием — он окончательный, апелляции нет»; у пула подаёт ставивший, кроме согласившихся (`outcome.agreed`), у пари — сторона; причина — не пустая; одна на событие или пари — вторая: «Апелляция уже подана — присоединитесь к ней»; событие отменено — нет; «ждёт суда» — нет (суд и так собирается); кандидатов 0 — «В комнате некому судить: все участники заинтересованы».
- **Присоединиться** (`checkJoin`): тот, кто мог бы подать, кроме подавшего; один раз; до решения суда (и после 7 дней, если суд не решил).
- **Кандидаты** (`courtCandidates(target, { hostId, members: [{ id, addedAt, absent? }] }, at)`): участники, впущенные к мигу жребия и в игре на этот миг (не вышли и не «выбыл» — `absentAt`, Р-41), кроме заинтересованных — у пула: ставившие, автор, предмет спора, ведущий, решивший возражение (`outcome.decided`); у пари: стороны и нынешний гарант (без гаранта, Р-36, — только стороны); и кроме подавшего и присоединившихся. Голосовавшие по возражению (Р-17) — кандидаты. В записи — тем же списком (порядок не важен, `checkDraw`); зерно — hex.
- **Жребий** (`drawCourt(seed, candidates, hostId)`): каждому кандидату — число `courtHash(seed + ':' + номер)`: 32-битный FNV-1a по кодам знаков строки (начало `0x811c9dc5`, для каждого знака: `h ^= код`, `h = h × 0x01000193` по модулю 2³²), затем перемешивание fmix32 из MurmurHash3 (`h ^= h >>> 16; h ×= 0x85ebca6b; h ^= h >>> 13; h ×= 0xc2b2ae35; h ^= h >>> 16`, умножения по модулю 2³²). Порядок — по возрастанию числа, равные — по номеру; ведущий, если он кандидат, — первым. Первые три — суд (ведущий + 2 или 3 присяжных), дальше — запасные по порядку; кандидатов меньше — суд из тех, кто есть.
- **Места** (`courtState` на `now`): у места — срок дела `seatTime` с жребия (Р-35: `roomAppeals` берёт `court` из сроков события или пари; у записей без `times` поля нет — 72 часа, `SEAT_TIME`; «72 часа» ниже — этот срок). Член суда (и ведущий) не проголосовал за 72 часа — место переходит к следующему запасному, у него свои 72 часа с этого мига; замена одна на место: заменивший молчит — срок места прошёл. Досрочно (`checkReplace`) — только ведущий, если он сам кандидат (не заинтересован): не проголосовавшего, не себя, с причиной, одна замена на место, до решения. Запасные кончились — место пустое. Замены по сроку идут по времени, равные — по номеру места; запись — после замен по срокам на её время.
- **Голос** (`checkCourtVote`): только член суда на своём месте в свои 72 часа, один раз, не меняется; `keep` — только у апелляции (исход утверждён); `change` — у пула другой исход события, у пари — другая сторона; `cancel` — всегда. Голоса — в ответе сразу (Р-11).
- **Решение** (`courtVerdict`): суд кончился, когда все места проголосовали или их сроки прошли (пустое место — сразу); миг решения — последний из них. Побеждает вариант строгого большинства поданных голосов (3 голоса — 2; один — он); большинства нет (`majority: false`) — у апелляции «оставить», у «ждёт суда» — «отменить». Решение окончательное, второй апелляции нет.
- **Окончательность** (`eventOutcome(e, now, court)`, `offerOutcome(o, now, court)`; `court` — дело суда или `null`, без него — как раньше). Апелляция подана до конца 7 дней — исход «утверждён», `finalAt: null`, пока суд не решил; «оставить» — окончательный в миг решения с прежним исходом; «изменить» — `approved` с `how: 'court'`, `by: null`, окончательный сразу, выплаты пула и итог пари — по новому исходу; «отменить» — у пула статус `cancelled`, `payouts` пусты, возврат — `refunds` события (`eventRefunds(e, outcome)`), у пари — фаза `cancelled`, без выплат. «Ждёт суда» с судом: до решения — `court`; «изменить» — утверждён судом, окончательный; иначе — `cancelled` с возвратом. У пари «ждёт суда» — 3 дня без общего гаранта (Р-31; `checkCourtDraw` пускает пари по `courtDue`, раздел «Правила пари в коде»): фаза `court`, голоса — «прав автор» / «прав соперник» / «отменить», «оставить» нет (`NO_KEEP`); «изменить» — утверждён судом, окончательный сразу; «отменить» или большинства нет — `cancelled`, без выплат; второй апелляции нет (`COURT_DECIDED`). `offerResult` и выплаты пула — только по окончательному.
- **Ответ** (`appeal` и `court` у `OutcomeView` и `OfferOutcomeView`): `appeal` — `{ id, at, by, reason, joined: [{ id, at, by }] }` или `null` (суд по «ждёт суда»); `court` — `{ seed, drawnAt, candidates` (порядок жребия)`, seats: [{ member, since, until, replaced: { member, at, by, reason } | null, vote }], decision: { at, majority, verdict, … } | null }`. Суда нет — полей нет (ответ как до этапа 4; всегда — с подъёмом версии протокола, задача сервера).
- **Свёртка** (`roomAppeals(records, { events, offers }, room)` → дела `CourtCase`; `caseOf` — дело по цели): запись действует, если её разрешает та же проверка на её время `at` (`checkAppeal` + `checkDraw`, `checkCourtDraw` + `checkDraw`, `checkJoin`, `checkCourtVote`, `checkReplace`); исход цели — по уже собранному событию или пари; пари — на миг записи (`offerAt`, как в свёртке пари): торг, кончившийся по времени со встречным, принят в миг конца без записи (Р-37) — соперник уже сторона; записи о неизвестной цели не действуют.
- **Лот** (Р-38). Цель суда — ещё и лот: `CourtTarget` = `AppealTarget` (событие или пари — как было, его перебирает сервер) или `{ kind: 'lot', lot }`; проверки суда (`courtCandidates`, `checkCourtDraw`, `checkCourtVote`, `courtVote`, `checkAppeal`, `checkJoin`) принимают `CourtTarget`; `roomAppeals` и `logAppeals` — ещё и `lots` (нет — лотов нет). Заинтересованы продавец и победитель (лучшая ставка); суд — как по «ждёт суда» (`court.drawn`, `appeal: null`), пускает его `lotCourtDue` («Не получил» есть, к этому мигу ни «Получил», ни «Не смогу передать»); место — срок суда лота. Голоса — только `delivered` («передано») / `undelivered` («не передано»), иначе «Голос — «передано» или «не передано»» (`BAD_LOT_VERDICT`); у события и пари этих голосов нет. Апелляции и присоединения нет — «Решение суда по лоту окончательное — апелляции нет» (`LOT_NO_APPEAL`). Решение: большинство `delivered` — получен судом; `undelivered` или большинства нет (`courtVerdict` даёт `cancel`) — не передан (`lotOutcome`).

## Правила расчёта в коде

`src/rules/settle.ts` — этап 5, Р-07, Р-11, Р-32; записи о переводах и режим комнаты в журнале, адреса и свод в ответе комнаты — сервер (Р-33, `docs/02-Сервер.md`, «Расчёт»), экран «Расчёт» — `docs/02-Сайт.md`, «Расчёт на сайте»; «История» — следующая задача этапа. Вход свода — события и пари комнаты (`roomEvents`, `logOffers`), дела суда (`logAppeals`) и записи `TransferRecord` (`memberId` — автор, `at` — время сервера, порядок — журнала); будильника нет — всё считается на `now`. Суммы — целые в минимальных единицах; итоги, балансы и подсказка не хранятся.

- **Три числа** (`roomSettlement` → `members`: `total`, `pending`, `inPlay` — каждое `{ amount, events, offers }`: сумма и из скольких событий и пари сложена). Событие — по `eventOutcome(e, now, дело суда)`: отменено (и судом, `cancelled`) или «без игры» (`void`) — не в счёт ни одного числа; утверждено и `final` — `net` из `payouts` в **итог**; утверждено, ещё не окончательное (неделя апелляции, суд по апелляции, `finalAt: null`) — в **ждёт окончательности**; без утверждённого исхода — не предложен, `proposed`, `disputed`, `voting`, `withdrawn` (Р-27), `court` — свои ставки **в игре**. Пари — только принятые, по `offerOutcome`: `cancelled` — не в счёт; `final` — итог по `offerNets`; утверждено, не окончательное — ждёт; `marking`, `guarantor`, `need-guarantor`, `court` — своя сумма (`offerStakes`) в игре. Торг (Р-37) — на `now` (`offerAt`), суммы — `offerAmounts`: до конца торга лучшее встречное не в игре, «не состоялось» — ни в одном числе. Лот (Р-38; `SettleInput.lots` — лоты комнаты `logLots`; дали — у каждого числа ещё `lots`, сколько лотов, не дали — поля нет, как до лотов) — по `lotOutcome(l, now, дело суда)`: торг идёт — лучшая ставка **в игре** у её автора (перебитые — свободны, у продавца ничего); после конца со ставками победитель должен продавцу свою ставку: получено (`received`: отметкой, молчанием, судом «передано») — в **итог** сразу (апелляции нет), в долги пар — как окончательный спор (продавец +ставка, победитель −она: «по ставкам» — прямой долг пары, «меньше переводов» — общим счётом); «ждёт передачи», «передан», «в споре», «ждёт суда» — в **ждёт** (продавец +, победитель −); снят, не продан, не состоялся, не передан — ни в одном числе. Выбор (Р-39; `SettleInput.choices` — выборы комнаты `logChoices`; дали — у каждого числа ещё `choices`, не дали — поля нет) — по `choiceOutcome(c, now)`: вклады идут или «ждёт жребия» — свои вклады **в игре** (`choiceInPlay`; у получателя — нет: свой вклад он не платит); решён — каждый вложившийся в победивший должен получателю свою сумму (`choiceResult`), в **итог** сразу (спора нет), в долги пар — как окончательный спор; фаза вариантов и «не состоялся» — ни в одном числе. В комнате на очки — так же, итог — в таблице очков.
- **Переводы** (`TransferRecord`, свёртка `roomTransfers(records, { currency, members })`; запись действует, если её разрешает та же проверка на её место в журнале; повтор номера записи — не второй перевод). «Перевёл» `transfer.sent` (`checkSend`) — должник участнику; прямое «Получил» `transfer.received` с `from` (`checkReceive`) — получатель от участника, сразу `received`: оба — участники комнаты (`NOT_MEMBER`), не сам себе (`SELF_TRANSFER`), сумма — целое > 0 (`BAD_AMOUNT`), долгом не ограничена. «Получил» с `transfer` и «Не получал» `transfer.rejected` (`checkAnswer`) — только получатель (`ONLY_RECEIVER`) и только у `pending`. Отмена `transfer.revoked` (`checkRevoke`): должник — своё «Перевёл», пока `pending` (подтверждён — `RECEIVED_NO_REVOKE`) → `cancelled`; получатель — своё «Получил»: подтверждённое «Перевёл» снова `pending`, прямое — `cancelled`; чужая отметка — `ONLY_OWN`. Из неподходящего состояния — отказ по нему (`ALREADY_RECEIVED`, `ALREADY_REJECTED`, `TRANSFER_CANCELLED`, `NOTHING_TO_REVOKE`); нет перевода — `NO_TRANSFER`. В комнате на очки (`PTS`) — «В комнате на очки переводов нет» (`NO_TRANSFERS`) на любое действие, свёртка пуста.
- **Баланс** = итог + `sent` − `received`; считаются переводы `pending` и `received` (`countedTransfer`), отклонённые и отменённые — нет. Плюс — участнику должны, минус — он должен; сумма балансов комнаты — ноль.
- **«Кто кому»** (`suggestions: [{ from, to, amount }]`; режим — параметр `mode`, по умолчанию `stakes`; один журнал, `now` и режим — одна подсказка; все балансы ноль — пусто; в комнате на очки — пусто). **По ставкам** (`stakes`): по каждому окончательному спору — долги пар `resultDebts`: в пари проигравший → выигравшему его `net`; в пуле каждый проигравший → выигравшим пропорционально их `net`, вниз до целой единицы (`BigInt`), неделимый остаток проигравшего — по единице выигравшим с недобором по порядку первой ставки (как `settlePool`): каждый выигравший получает ровно свой `net`, каждый проигравший отдаёт ровно свой. Долги пары по всем спорам сворачиваются в один, переводы пары вычитаются (переплата — долг меняет сторону); долги, сложившиеся по кругу (A → B → C → A), сокращаются (`cancelCycles`): на каждом шаге — первый круг обхода по номерам участников, из каждой его пары вычитается наименьший долг круга, пока кругов нет — так все балансы ноль дают пустую подсказку и в этом режиме; порядок — по номерам пары. Сумма подсказок участника — его баланс. **Меньше переводов** (`fewest`, `fewestTransfers`): из балансов, жадно — наибольший долг платит наибольшему выигрышу, сколько закрывает меньший; при равенстве — по номеру участника.
- **Смена режима** (`checkSettleMode(свод, { hostId, currency }, участник, режим)`): на очки — `NO_TRANSFERS`; только ведущий (`ONLY_HOST_MODE`); режим — `stakes` / `fewest` (`BAD_MODE`); тот же — «Этот режим уже выбран» (`SAME_MODE`); нет переводов `pending` / `received` — можно; есть — только когда все балансы ноль и ни один не `pending` (`MODE_LOCKED`).

## Правила лота в коде

`src/rules/lot.ts` — этап 7, Р-09, Р-38; правила для людей — «Лот» в «Правилах», записи — «Записи журнала лота» в модели; адреса сервера и экраны — следующие задачи этапа (сервер поднимет версию протокола). Вход — записи `LotRecord` (`memberId` — автор, `at` — время сервера, порядок — журнала; номер лота — `id` записи `lot.created`); будильника нет — всё считается на `now`. Торг — общий с «Торгом до …» пари (`src/rules/auction.ts`): сроки решения, не темпа.

- **Форма** (`checkLotInput`): название — не пустое, ≤ 100 знаков (`MAX_LOT_TITLE`; `NEED_LOT_TITLE`, `LONG_LOT_TITLE`); описание — ≤ 300 знаков, может быть пустым (`LONG_LOT_DESCRIPTION`); пробелы по краям срезаются; старт — целое > 0 (`BAD_LOT_START`); шаг не задан — `auctionStep` (10 % старта вниз, не меньше 1), иначе целое > 0 (`BAD_LOT_STEP`); конец — число (`NEED_LOT_END`). Срок (`checkLotTimes`, по времени сервера): `closesAt` — не раньше `now` + 10 минут (`LOT_SHORT`), не позже `now` + 3 дня (`LOT_LONG`). Свёртка берёт `lot.created`, только если её пропускают те же проверки на её `at` и продавец — участник; повтор номера — тот же лот. Сроки — `LotState.times` (`recordTimes`; нет поля — обычный набор, `timesOf`): молчание — `silence`, место в суде — `court`.
- **Ставка** (`lot.bid`, `checkLotBid(l, участник, amount, { members }, now)`): снят — `LOT_WITHDRAWN`; `now ≥ endsAt` — `LOT_OVER`; продавец — `OWN_LOT`; не участник — `NOT_MEMBER`; сумма — целое > 0 (`BAD_LOT_BID`); первая < старта — `LOT_BID_LOW`, следующая < лучшей + шаг — `LOT_BID_STEP` (`nextBid`); свою перебить можно. Ставки не отзываются; действующие — `LotState.bids` по порядку, последняя — лучшая (`bestLotBid`). Продление: `endsAt` = min(`closesAt` + 30 минут, max(`endsAt`, `at` + 2 минуты)) (`extendEnd`); ставка в миг конца уже не действует.
- **Снять** (`lot.withdrawn`, `checkLotWithdraw`): только продавец (`ONLY_SELLER`), пока ставок нет (`LOT_HAS_BIDS`) и торг идёт (`LOT_OVER`); снят — `LOT_WITHDRAWN`.
- **Победитель** (`lotWinner(l, now)`): `now ≥ endsAt`, не снят, ставка есть — лучшая; иначе `null`. Ставок к концу нет — «не продан».
- **После торга.** Общее у всех отметок: снят — `LOT_WITHDRAWN`, торг идёт — `LOT_NOT_OVER`, ставок не было — `LOT_UNSOLD`; итог уже есть или суд собран — «не состоялся» (`LOT_FAILED`), получено (`LOT_RECEIVED`), суд (`LOT_IN_COURT`). «Передал» (`lot.handed`, `checkHanded`) — продавец, один раз (`LOT_HANDED`), не после «Не получил» (`LOT_DISPUTED`). «Не смогу передать» (`lot.declined`, `checkDeclined`) — продавец, и после «Передал», и в споре без суда. «Получил» (`lot.received`, `checkReceived`) — победитель (`ONLY_WINNER`), в любой момент после конца, и в споре без суда. «Не получил» (`lot.disputed`, `checkDisputed`) — победитель, один раз (`LOT_DISPUTED`); без «Передал» — не раньше `disputeFrom` = `endsAt` + срок молчания (`LOT_TOO_EARLY`). Получено молчанием — `handedAt` + срок молчания, если до него не было «Не получил» и «Не смогу передать».
- **Суд** (`lotCourtDue(l, now)`; дальше — `appeal.ts`, «Лот» в «Правилах апелляции в коде»). `logLots` переводит `court.drawn` о лоте в запись правил `{ type: 'court.drawn', lot }`: первая в срок ставит `courtAt`; после неё отметки сторон не действуют. Сервер пишет `court.drawn`, только когда кандидаты есть; нет — лот «в споре».
- **Итог** (`lotOutcome(l, now, дело суда)` → `{ status, winner, received, closedAt }`): `withdrawn` (снят) → `open` (`now < endsAt`) → `unsold` (ставок нет; `closedAt` — `endsAt`) → `failed` («Не смогу передать») → `received` (отметкой `mark`, молчанием `silence`) → после «Не получил»: суда нет — `dispute`, суд собран, решения нет (или дела не дали) — `court`, решение `delivered` — `received` (`court`, миг решения), иначе — `undelivered` → `handed` («Передал») → `awaiting` (ждёт передачи). `lotResult` — для «Расчёта»: только `received` — продавец +ставка победителя, победитель −она.
- **Ответ** (`lotView` → `LotView` в `protocol.ts`, проверка `isLotView`): условия (`closesAt`, `latestEnd`, `endsAt`, `times`), `status`, `bids`, `best`, `winner` и `amount` (после конца со ставками), `withdrawnAt`, `handedAt`, `declinedAt`, `disputedAt`, `disputeFrom`, `silenceUntil` (после «Передал» — с какого мига «получил» молчанием), `received` (`{ at, how }`), `closedAt` (миг итога — для «Истории»: снят, не продан, получен, не состоялся, не передан), `court` (суд по «Не получил»; нет дела — поля нет). Протокол: виды и проверки — в `protocol.ts`; в ответ комнаты и адреса их добавит задача сервера с подъёмом версии.
- **Свёртка** (`roomLots(records, { members })`): запись действует, если её разрешает та же проверка на её время `at`; записи о неизвестном лоте не действуют.

## Правила выбора в коде

`src/rules/choice.ts` — этап 7, Р-09, Р-39; правила для людей — «Выбор» в «Правилах», записи — «Записи журнала выбора» в модели; адреса сервера и ответ комнаты — «Выбор» в `02-Сервер.md` (версия протокола 10); «Расчёт» и «История» на сайте — следующая задача этапа. Вход — записи `ChoiceRecord` (`memberId` — автор, `at` — время сервера, порядок — журнала; номер выбора — `id` записи `choice.created`); будильника нет — всё считается на `now`. Сроки (10 минут, 3 дня, +2 минуты, +30 минут) — постоянные решения, общие с торгом (`src/rules/auction.ts`), не темпа; сроков темпа у выбора нет.

- **Форма** (`checkChoiceInput(x, { hostId, members })`): вопрос — не пустой, ≤ 300 знаков (`NEED_QUESTION`, `LONG_QUESTION`); варианты — не заданы (пусто) или список (`BAD_OPTIONS`), не больше 10 (`MAX_CHOICE_OPTIONS`, `TOO_MANY_OPTIONS`), каждый — не пустой, ≤ 40 знаков (`checkOptionTitle`: `NEED_OPTION`, `LONG_OPTION`), без повторов без учёта регистра и пробелов по краям (`SAME_OPTION`); пробелы по краям срезаются; получатель не задан — ведущий, иначе участник комнаты (`BAD_RECIPIENT`); `cashbox` — только `true` даёт подпись «касса»; сроки — числа (`NEED_CHOICE_TIMES`). Сроки (`checkChoiceTimes`, по времени сервера): `optionsUntil` ≥ `now` + 10 минут (`OPTIONS_SHORT`), `closesAt` ≥ `optionsUntil` + 10 минут (`STAKES_SHORT`), `closesAt` ≤ `now` + 3 дня (`CHOICE_LONG`). Свёртка берёт `choice.created`, только если её пропускают те же проверки на её `at` и автор — участник; повтор номера — тот же выбор. Варианты автора — номера `'1'`, `'2'`, …, добавленные — `id` записи `choice.option`.
- **Вариант** (`choice.option`, `checkChoiceOption(c, участник, title, { members }, now)`): не участник — `NOT_MEMBER`; `now ≥ optionsUntil` — `OPTIONS_CLOSED`; название — `checkOptionTitle`; уже 10 — `TOO_MANY_OPTIONS`; повтор — `SAME_OPTION`.
- **Вклад** (`choice.stake`, `checkChoiceStake(c, участник, option, amount, { members }, now)`): не участник — `NOT_MEMBER`; `now < optionsUntil` — `STAKES_NOT_YET`; вариантов меньше двух — `CHOICE_NO_OPTIONS`; `now ≥ choiceEnd` — `CHOICE_OVER`; нет варианта — `NO_OPTION`; участник уже вкладывал в другой — `ONE_OPTION`; сумма — целое > 0 (`BAD_STAKE`). Автор и получатель тоже вкладывают. Вклады не отзываются; действующие — `ChoiceState.stakes` по порядку. Продление: `endsAt` = min(`closesAt` + 30 минут, max(конец на миг вклада, `at` + 2 минуты)) (`extendEnd`).
- **Конец с ничьей** (`choiceEnd(c, now)`): от `endsAt`; в прошедший миг конца ничья (`choiceTie` — два и больше варианта с наибольшей суммой > 0 по вкладам до этого мига) — ещё 2 минуты, снова и снова, не дальше `latestEnd` = `closesAt` + 30 минут; будущий конец не продлевается заранее — до него ещё могут вложить. Продление может выйти за «весь выбор ≤ 3 дня» — так задумано, как у торга.
- **Жребий при ничьей** (`choice.drawn`): нужен (`choiceDrawDue`), когда конец с продлениями прошёл и в нём ничья — значит, дошли до `latestEnd`; равные — `choiceDrawOptions` (жребий уже брошен — пусто): по ним сервер пишет запись с зерном `randomSeed` (как `court.drawn`, Р-25). Запись действует (`checkChoiceDraw`), если жребий нужен на её `at` (`NO_DRAW`), ещё не брошен (`DRAW_DONE`), зерно — hex (`BAD_DRAW_SEED`), варианты — ровно равные, порядок не важен (`BAD_DRAW_OPTIONS`). Победитель — `drawChoice(seed, options)`: наименьший `courtHash(зерно + ':' + номер варианта)` (хеш жребия суда), равные — по номеру.
- **Итог** (`choiceOutcome(c, now)` → `{ status, failed, endsAt, winner, how, closedAt }`): `options` (`now < optionsUntil`) → меньше двух вариантов — `failed`, `failed: 'options'` (`closedAt` — `optionsUntil`) → `open` (`now < choiceEnd`) → вкладов нет — `failed`, `'stakes'` (`closedAt` — конец) → ничья: жребия нет — `draw`, есть — `decided`, `how: 'draw'` (`closedAt` — миг жребия) → иначе `decided`, `how: 'sum'` (`closedAt` — конец). Долги (`choiceDebts`): только у `decided` — каждый вложившийся в победивший → получателю свою сумму, по порядку первого вклада; вклад получателя — не долг. `choiceResult` — для «Расчёта»: получатель +сумма долгов, должники −свои; `choiceInPlay` — вклады «в игре» у `open` и `draw`, кроме получателя.
- **Ответ** (`choiceView` → `ChoiceView` в `protocol.ts`, проверка `isChoiceView`): вопрос, `recipientId`, `cashbox`, сроки (`optionsUntil`, `closesAt`, `latestEnd`, `endsAt` — конец с продлениями на `now`), `status`, `failed`, `options` (`{ id, at, by, title, total }` — сумма вкладов), `stakes` (видны всем, Р-11), `winner`, `how`, `draw` (`{ at, seed, options }` или `null`), `debts` (`{ from, to, amount }` — кто кому), `closedAt` (миг итога — для «Истории»). В ответе комнаты — `choices`, в «Расчёте» — счётчик `choices` в `SettleSumView` (сервер, версия 10); «Расчёт» и «История» на сайте — задача сайта.
- **Свёртка** (`roomChoices(records, { hostId, members })`): запись действует, если её разрешает та же проверка на её время `at`; записи о неизвестном выборе не действуют.

## Правила жизни комнаты в коде

`src/rules/member.ts` — Р-40 (выйти), Р-41 («выбыл»); правила для людей — «Участник пропал с долгом» в «Крайних случаях»; адреса сервера — «Жизнь комнаты» в `02-Сервер.md` (версия протокола 11); экраны — следующая задача. Состав «вышел / выбыл» считает свёртка комнаты (`applyEntry` в `src/rules/room.ts`), проверки действий — `member.ts` на время сервера.

- **Записи.** `member.left` (`requestId`; автор — вышедший; ведущего свёртка не выводит), `member.returned` (`member` — вышедший, `request` — заявка, которой он вернулся; автор — ведущий), `member.dropped` и `member.reinstated` (`member`, `requestId`; автор — ведущий; ведущего и вышедшего не помечают). Старые комнаты без этих записей — все в комнате и в игре.
- **Выйти** (`checkLeave(комната, участник, now)` — отказ первым по порядку): ведущий — `HOST_LEAVES` «Сначала передайте ведение» (передача ведения — Р-42, «Правила ведения в коде»); ставка в событии без окончательного исхода (`openBet`); принятое пари стороной, пока исход не окончательный и не отменён (`openOffer`); своё встречное в идущем торге (`ownBid`); свой торг со встречными (`ownAuction`; торг без встречных отзывается сам); лот продавцом или лучшей ставкой, после торга — победителем, пока лот не завершён (`openLot`); вклад в «Выбор» до итога (`openChoice`); гарант пари, которое не завершено (в том числе не принятое) (`guarantorIn`); место в суде без своего голоса, пока решения нет (`jurorIn`); баланс не ноль или перевод с ним ждёт подтверждения (`UNSETTLED`; в комнате на очки не проверяется). Свои непринятые пари и торги без встречных (`leaveRevocations`) сервер отзывает записями `offer.revoked` той же меткой времени перед `member.left`.
- **Вышедший**: ключи его устройств помечены отвязанными, ссылки для устройства погашены; ключ вышедшего — отказ `LEFT`; ссылку для устройства ему не выдать. Имя вышедшего не занято (`nameTaken`): заявка с тем же именем без учёта регистра — возврат (`returningMember`), ведущий впускает её записью `member.returned` — тот же участник (номер, имя, история, итоги); ключ заявки открывает его (`keyMember`).
- **«Выбыл»** (`checkDrop`): ставит и снимает только ведущий (`ONLY_HOST_DROP`), не себе (`HOST_NOT_DROPPED`), не вышедшему (`MEMBER_LEFT`); уже помечен / не помечен — `ALREADY_DROPPED` / `NOT_DROPPED`. Выбывшему (`checkActive` → `DROPPED`) нельзя новое: событие, ставка, пари, встречное, принять пари, встречное в торге, лот и ставка на лот, «Выбор», вариант и вклад, апелляция и присоединение к ней; можно — отметки исхода своих пари и лота, «Принять сейчас» своего торга, отметки переводов, чтение комнаты.
- **Кого можно назвать**: гарант, адресат, новый гарант и судьи «без гаранта» (Р-36) — только участники в игре (`playingMembers`); о ком спор, получатель «Выбора», участник лота — не вышедшие (`roomMembers`). Свёртки пари, лота и выбора проверяют записи по всем участникам — записи, сделанные до пометки, действуют.
- **Жребий суда** (`courtCandidates`): кандидат — в игре на миг жребия; промежуток «вне игры» — `from < at ≤ to` (`absentAt`), так суд, дописанный сервером тем же запросом до пометки, и свёртка не расходятся.
- **Гарант «выбыл»** — молчание гаранта (`OfferState.guarantorAway`): его срок кончается, как только решение у него, но не раньше пометки — дальше «нужен другой гарант» и суд (Р-31). Пометку сняли, пока решение не ушло, — гарант снова решает; ушло — так и остаётся, как отказ в тот миг.

## Правила ведения в коде

Р-42; правила для людей — «Ведущий пропал» в «Крайних случаях»; проверки — `src/rules/member.ts`, смену держит свёртка комнаты (`applyEntry` в `src/rules/room.ts`); адреса сервера и запись `seen:` — «Ведение» в `02-Сервер.md` (версия протокола 12); экраны — следующая задача.

- **Записи.** `host.passed` (`member` — новый ведущий, `requestId`; автор — ведущий), `host.taken` (`from` — у кого взято, `seenAt` — когда тот заходил, основание для всех; `requestId`; автор — взявший). Свёртка берёт запись, только если передаёт нынешний ведущий или берут у нынешнего, а новый — участник в игре и не сам ведущий; семь дней свёртка не проверяет (время запросов — вне журнала). Старые комнаты без этих записей — ведущий автор `room.created`, как был.
- **Кто ведущий.** `RoomState.hostId` — нынешний; `RoomState.hosts` — сроки ведения `{ member, from, how: 'created' | 'passed' | 'taken', by, id }` по порядку журнала. Ведущий на миг записи — `hostAt(комната, at)`: смена действует с её мига. Правила, проходящие журнал по порядку (`roomEvents`, `logPace`, `logSettleMode` сервера), берут ведущего из свёртки на месте записи; правила со временем (`roomOffers`, `roomAppeals`) — `hostAt` по `hosts` из `roomRoles` и `courtRoom`.
- **Передать** (`checkPassHost`): только ведущий (`ONLY_HOST_PASS`); кому — участник (`NO_MEMBER`), не сам (`PASS_SELF`), не вышедший (`PASS_LEFT`), не «выбыл» (`PASS_DROPPED`).
- **Взять** (`checkTakeHost(комната, участник, seenAt, now)`): участник в комнате (`NO_MEMBER`), не сам ведущий (`ALREADY_HOST`), не «выбыл» (`TAKE_DROPPED`); можно с `takeHostFrom(seenAt)` = `seenAt` + 7 дней (`HOST_AWAY`, при любом темпе). Раньше: ведущий сменился за последние 7 дней — «Ведение уже взял <имя>» (`hostTakenBy`) или «Ведение уже передано: ведущий — <имя>» (`hostPassedTo`) — так второй из двоих подряд узнаёт, кто успел; иначе — «Ведущий заходил <сколько> назад: взять ведение можно через <сколько>» (`hostSeen`; срок — словами, без даты: часового пояса телефона сервер не знает, даты в ответе комнаты — числами).
- **Когда заходил** (`hostSeenAt(журнал, комната, seen)`): наибольшее из — время последнего запроса ведущего, которое помнит сервер (`seen`, точность — час), миг, когда он стал ведущим, и его последняя запись в журнале, кроме жребия суда и выбора (их дописывает сервер от имени ведущего). Без `seen` (старые комнаты, загрузка из копии) — по журналу.
- **Событие.** `EventState.hostId` — ведущий на миг `event.created`: по нему способ спора (`hostDecides`: решает ведущий, если тот не ставил и не предмет; иначе голосование) — со сменой ведения не меняется. Решает нынешний ведущий, если сам не ставил и не предмет (`hostMayDecide`; ведение перешло к ставившему — отказ, передать тому, кто не ставил). За автора-предмет или молчащего автора исход предлагает нынешний ведущий (`mayPropose(e, участник, now, host)`); «ведущий о себе» — ведущий на миг создания. Отмена события ведущим (`cancelError`) — нынешний.
- **Пари.** Гарант по умолчанию закреплён в записи `offer.created` (`guarantor` — уже определённый участник) — со сменой ведения не меняется; свёртка проверяет запись с ведущим на миг её создания.
- **Суд.** `CourtCase.hostId` — ведущий на миг жребия (`appeal.filed`, `court.drawn`): он, если кандидат, первым в порядке (`drawCourt`) — порядок уже собранного суда не меняется. `court.drawn` и `choice.drawn` сервер пишет от имени нынешнего ведущего. Досрочная замена (`checkReplace(…, host)`) — нынешний ведущий на миг записи, если он сам кандидат.
- **Прочее ведущего** — нынешний: впустить и отклонить заявку, вернуть вышедшего, ссылка-приглашение, ссылка для устройства за другого, «выбыл», режим «кто кому», темп, гарант и получатель «Выбора» по умолчанию для новых. Ведущий не выходит (`HOST_LEAVES`) — сначала передать ведение; прежний выходит как обычный участник.
- **Копия** (`src/rules/backup.ts`): записи `host.passed` и `host.taken` — в списке видов журнала; `seen:` в копию не идёт.

## Резерв сервера (Р-02)

1. **Код переносим:** правила — чистые функции над `RoomStorage`; Cloudflare — обёртка; запасная — Node + SQLite в `server/node/`, CI гоняет одни тесты на обеих (`roomsSuite`; `npm test` показывает каждый набор дважды). Запуск — `npm run server:node` (Vite собирает `server/node/main.ts` в `server/node/dist/main.js`, встроенные `node:sqlite` и `node:http`, Node 24): адрес `http://localhost:8787`, те же ответы, что у Worker'а. Переменные: `ROOM_PASSWORD` — пароль компании, `PORT` (8787), `HOST` (все адреса), `ROOMS_DB` — файл комнат (`server/node/data.sqlite`, в `.gitignore`); `DATA_TOKEN` и `DATA_REPO` — суточная копия (п. 2). Будильник комнаты (`setAlarm`) хранится в файле; обработчик (`onAlarm`, как `alarm()` объекта `Room`) — пока пустой: сроков у комнат ещё нет. Типы — `server/node/tsconfig.json` с `@types/node` (Р-14), проверка — в `npm run server:check`.
2. **Данные в трёх местах:** сервер; журнал комнат на каждом телефоне участника («Файл-копия»); суточная выгрузка всех комнат (этап 6).
   - **Суточная копия** (`server/src/backup.ts`, `dailyBackup`): раз в сутки ночью по Екатеринбургу — 21:17 UTC (Worker — Cloudflare cron, `server/wrangler.toml`, `[triggers]`; Node — таймер на тот же миг, `nextBackupAt`) сервер берёт полные копии всех комнат (`collectBackups`, та же, что у `GET /export`) и кладёт их одним файлом `rooms.json` — массив копий, как `backups` у `GET /export`, — в корень приватного репо данных (ветка по умолчанию). Два запроса к GitHub REST: `GET /repos/<репо>/contents/rooms.json` (`sha` и содержимое; 404 — файла нет) и `PUT` того же адреса с сообщением коммита «Копия ДД.ММ.ГГГГ, комнат: N» (дата — по Екатеринбургу, UTC+5) и `sha`, если файл был. Копии отличаются от лежащих только мигом выгрузки (`exportedAt`) — коммита нет; содержимого в ответе нет (файл больше 1 МБ — GitHub его не отдаёт) — пишем заново. История дней — история коммитов репо.
   - **Ключи:** токен — `DATA_TOKEN` (fine-grained, только к репо данных, Contents — запись), репо — `DATA_REPO` («владелец/репо»): у Worker'а оба — секреты в панели Cloudflare (не `[vars]`: переменные панели выкатка стирает), у Node — переменные окружения. Не задан хоть один (или репо записан не как «владелец/репо») — копия пропускается строкой в лог, сервер работает как раньше. Токен — только в заголовке `Authorization` к GitHub: не в ответах, журнале и логе.
   - **Сбой** — реестр не отдал комнаты, GitHub не ответил или отказал (401, 403, 409 — файл сменился между чтением и записью, 429 — лимит): строка в лог сервера с кодом ответа, без повтора — следующая попытка по расписанию; комнаты только читаются. Node лежал в срок — копия на следующую ночь.
   - **Пределы бесплатного плана Cloudflare** (оценка): к GitHub — 2 запроса из 50 внешних на вызов; копии — вызов реестра и по вызову объекта на комнату, до 1000 вызовов служб Cloudflare на вызов — около 1000 комнат. Раньше упрёмся в процессор — 10 мс на вызов: сборка, сверка с прошлым файлом и base64 — порядка 0,5–1 МБ копий, то есть десятки комнат с сотнями записей. Признак — в логе Worker'а «Exceeded CPU Limit» и нет коммита при живых комнатах; тогда — платный план Workers (30 с процессора на вызов) или копия частями (файл на комнату), отдельной задачей.
   - **«Файл-копия»** (#100) — любой участник скачивает в комнате «Скачать копию комнаты»: копия участника (`GET /rooms/<номер>/export` ключом телефона, `fetchBackup`) файлом `ТоргСин — <название> — ДД.ММ.ГГГГ.json` — журнал целиком, без служебных записей и ключей (экран — `02-Сайт.md`, «Копия комнаты»).
3. **Переезд:** сервер отдаёт и принимает комнату целиком (`export` / `import`, с паролем компании; адреса — `02-Сервер.md`, «Копия комнаты»); адрес сервера — в «Настройках» и в ссылке комнаты.
   - **Копия** (`src/rules/backup.ts`, Р-34) — один формат для выгрузки, переезда и копии участника: `{ format: 1, roomId, exportedAt, log, store? }`. `log` — журнал целиком, по порядку; `store` — служебные записи хранилища, без которых после переезда не войти, ключи и значения как хранятся: `key:<хеш>`, `device:<хеш>`, `invite`, `secret` (ключей и токенов ссылок в открытом виде нет; новых секретов копия не создаёт). Копия участника — без `store`. Пометка реестра `registry` в копию не идёт.
   - **`checkBackup`** — отказ по-русски, комната не трогается: формат незнаком; журнал пуст, первая запись — не `room.created`, запись неизвестного вида или без `id` / `at` / `memberId`, `foldLog` не собирает комнату; номер комнаты не сходится с `room.created`; записи не по порядку — время записи убывает или номер (`id`) повторяется (у записей одного мига случайная часть ULID не упорядочена, порядок держит время); у полной — служебная запись чужого ключа или вида, нет приглашения; загрузке нужна полная копия.
   - **Реестр комнат** — только Cloudflare: объект `Registry`, одна запись на комнату (номер, миг создания). Комната отмечается в нём один раз (`registerOnce`, пометка `registry` в хранилище комнаты): новая — сразу после создания и загрузки, старая — при первом запросе после выкатки; реестр недоступен — комната работает, отметка — при следующем запросе. Пока комната зовёт реестр, её другие вызовы ждут (`blockConcurrencyWhile`). Node берёт список комнат из своей базы (`SqliteRooms.roomIds`).
4. **`docs/Резерв сервера.md`** — для человека: где лежит суточная копия, признаки беды, шаги переезда на запасной сервер (загрузка каждой комнаты из `rooms.json`, новый адрес в «Настройках»), что сказать друзьям, ежемесячная проба (этап 6).

## Выкатка

- **Сайт** — `deploy.yml`: пуш в `main` → сборка → GitHub Pages.
- **Сервер** — `server.yml`: пуш в `main` с правкой `server/`, `src/rules/` или зависимостей → тесты → `wrangler deploy` → проба `/health`. Ключи — секреты репо `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`; нет их — выкатка пропускается. Откат — Cloudflare → Workers → `torg-sin` → Deployments → Rollback.
- **Проверки PR** — `ci.yml`: `npm test`, `npm run build`, `npm run server:check`, `npm run server:build`.
