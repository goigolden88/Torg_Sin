# Архитектура

Источник истины для кода: имена, модель, правила. Отступление — вслух и до кода (`CLAUDE.md`). Модель и правила — из ТЗ (Штаб, `docs/замыслы/Тотализатор.md`, Ш-182…Ш-191); имена полей — черновик, уточняет этап 1 и каждый следующий в этом файле.

## Устройство

```
Телефон или компьютер (сайт-PWA на GitHub Pages)     Сервер (Cloudflare Worker)
  React + TypeScript, IndexedDB: журнал        ⇄    объект Room на комнату (SQLite)
  своих комнат, «Мои комнаты», копия                  над правилами src/rules/
  адрес сервера — «Настройки» и ссылка                реестр комнат, будильник к срокам и суду
                                                      запасная обёртка: Node + SQLite (те же тесты)
```

- **Один репо:** сайт (`src/`), сервер (`server/`), общие правила (`src/rules/` — чистые функции, ими пользуются и экран, и сервер; ни DOM, ни Cloudflare). Публичный — данных в нём нет.
- **Сервер — источник истины** (Р-01). Ставка, исход, жребий — только на сервере, по времени сервера; объект комнаты обрабатывает действия по одному — гонок «две ставки в последнюю секунду» нет. Телефон без сети показывает последнее известное; ставить без сети нельзя.
- **Связь:** WebSocket в открытой комнате, запрос-ответ для остального. Версия протокола `PROTOCOL_VERSION` (`src/rules/protocol.ts`) — в каждом ответе и сообщении; не та версия — экран просит обновить страницу.
- **Хранилище за интерфейсом** `RoomStorage` (get, put, list, setAlarm) — две реализации: Cloudflare (`server/src/index.ts`) и Node (`server/node/`, этап 1). Правила о Cloudflare не знают (Р-02).
- **Создание комнаты** — по паролю компании (секрет Worker'а `ROOM_PASSWORD`); вход — по ссылке, без пароля, впускает ведущий (Р-03).
- **Адрес сервера** — `DEFAULT_SERVER` (`src/rules/address.ts`, `https://torg-sin.goigolden88.workers.dev`); свой — в «Настройках» (localStorage `torgsin.server`) и в ссылке комнаты: при переезде телефоны идут на новый адрес сами (Р-02).

**Адреса сервера.** Ответ — JSON с `v` (версия протокола); отказ — `{ v, error }` с текстом для человека.

- `POST /rooms` — `{ password, name, currency, hostName, requestId? }` → `{ roomId, invite, memberId, key }`. Пароль на сервере не задан — 503 «Создание комнат выключено»; пароль неверный или пустой — 403 «Неверный пароль компании»; форма с ошибкой — 400. `requestId` — номер запроса (ULID) от телефона: повтор с тем же номером — та же комната и тот же ответ; с другой формой — 409.
- `GET /rooms/<номер>` с заголовком `Authorization: Bearer <ключ>` → `{ room: { id, name, currency, hostId, createdAt }, members: [{ id, name }], me, events, now }`; `events` — события-пул по порядку создания (ниже), `now` — время сервера в ответе (UTC, мс): по нему сайт считает отсчёт до закрытия приёма, а не по часам телефона. Нет ключа или ключ не участника — 403; нет комнаты — 404. Ключ заявки, которую ещё не впустили, — 403 «Ждём, пока ведущий впустит» с `join: "waiting"`; отклонённой — 403 «Ведущий отклонил заявку» с `join: "rejected"` (экран ожидания спрашивает раз в несколько секунд).

**Вход по ссылке** (Р-03). Ссылка-приглашение несёт номер комнаты и токен `invite`; токены — в теле запроса, не в адресе. Связь — запрос-ответ; WebSocket — с этапа 2.

- `POST /rooms/<номер>/preview` — `{ invite }` → `{ name, hostName }`, больше ничего. Токен неверный, сменённый, нет комнаты — 403 «Ссылка недействительна — попросите новую у ведущего».
- `POST /rooms/<номер>/join` — `{ invite, name, requestId? }` → `{ memberId, key, join: "waiting" }`: ключ телефона, который откроет комнату, когда ведущий впустит; `memberId` — номер заявки, он же номер участника. Имя уже у участника или ждущей заявки (без учёта регистра) — 409 «Такое имя уже есть — добавьте букву»; имя пустое или длиннее 30 — 400. Повтор с тем же `requestId` — та же заявка и тот же ключ (`join` — её нынешнее состояние); тот же номер с другим именем — 409.
- `GET /rooms/<номер>/requests` — ведущему: ждущие заявки `{ requests: [{ id, name, at }] }`.
- `POST /rooms/<номер>/admit` и `/reject` — `{ request }`, ведущему → `{ member: { id, name } }` и `{ request }`. Повтор того же решения — тот же ответ без записи; обратное — 409 («Участник уже впущен», «Заявка уже отклонена»); нет заявки — 404.
- `POST /rooms/<номер>/invite` — ведущему: новая ссылка `{ invite }`; старая перестаёт работать, впущенные и поданные заявки не страдают.
- `POST /rooms/<номер>/device` — `{ member?, unlink? }` → `{ token, member, expiresAt }`: «ссылка для другого устройства», одноразовая, на 24 часа. Себе — любой участник; за другого — только ведущий. `unlink: true` — когда ссылкой воспользуются, прежние ключи участника и его неиспользованные ссылки гаснут (потерял телефон).
- `POST /rooms/<номер>/device/claim` — `{ token }` → `{ memberId, key }`: новый ключ того же участника. Второй раз, через сутки или чужой токен — 403 «Ссылка для другого устройства недействительна — попросите новую».
- Действия по ключу: нет ключа или ключ не участника — 403; не ведущий там, где нужен ведущий, — 403 «Это может только ведущий».

**События-пул** (этап 2; экраны — следующей задачей). Все адреса — по ключу участника (нет ключа или ключ не участника — 403); номер события — `id` его записи `event.created`; нет события — 404 «Нет такого события».

- `POST /rooms/<номер>/events` — `{ condition, check, outcomes?, closesAt, expectedAt, subject?, requestId? }` → `{ event: EventInfo }` (`id`, `at`, `authorId`, `condition`, `check`, `outcomes: [{ id, title }]`, `closesAt`, `expectedAt`, `subjectId`). Заводит любой участник. `outcomes` не задан или пуст — «Да» и «Нет»; свои — 2–6, каждый ≤ 40 знаков, и сервер добавляет последним «Другое (ничего из перечисленного)» (Р-16); номер исхода — «1», «2», … по порядку. Одинаковые варианты (без учёта регистра и пробелов по краям, «Другое» тоже) — 400. Условие и «как проверяем» — не пустые, ≤ 300 знаков. `closesAt` — «приём ставок до» (не включая), уже прошёл по времени сервера — 400; `expectedAt` — «исход ожидается к», раньше `closesAt` — 400. `subject` — предмет спора, участник комнаты (не участник — 400). Повтор с тем же `requestId` — то же событие и тот же ответ, даже после срока; тот же номер с другой формой или от другого — 409.
- `POST /rooms/<номер>/events/<событие>/bets` — `{ outcome, amount, requestId? }` → `{ bet: { id, event, memberId, outcome, amount, at } }`. Любой участник, и автор, и предмет спора; несколько раз и на разные исходы; отменить нельзя. `amount` — целое > 0 в минимальных единицах (иначе 400), банк события не выходит за безопасное целое (400). Ставка в момент или после `closesAt` по времени сервера в момент запроса — 409 «Приём ставок закрыт» (будильника нет: срок проверяется при каждом запросе, сервер лежал — всё равно закрыто); отменённое событие — 409 «Событие отменено»; нет исхода — 400. Повтор с тем же `requestId` — та же ставка и тот же ответ (и после срока); тот же номер с другой суммой, исходом или от другого — 409.
- `POST /rooms/<номер>/events/<событие>/clarify` — `{ text }` (≤ 300 знаков) → `{ clarification: { id, at, text } }`. Только автор события (403 «Это может только автор события»); условие, «как проверяем» и исходы не меняются никогда.
- `POST /rooms/<номер>/events/<событие>/cancel` — `{ reason? }` → `{ cancelled: { at, by, reason } }`. Пока приём идёт — только автор, причина по желанию; после закрытия — только ведущий (403 «Это может только ведущий») и только с причиной ≤ 300 знаков (400 «Нужна причина отмены»). Уже отменено — та же отмена без новой записи. Отменённое ставок не принимает; ставки возвращаются.
- Событие в `GET /rooms/<номер>` (`EventView`): поля `EventInfo` и `status` (`open` — приём идёт, `closed` — закрыт, `cancelled` — отменено; на `now`), `clarifications: [{ id, at, text }]`, `bets: [{ id, memberId, outcome, amount, at }]` по порядку журнала, `cancelled` (`{ at, by, reason }` или `null`), `refunds: [{ memberId, amount }]` — у отменённого каждому его сумма (`settlePool` «без игры»), иначе пусто. Номера запросов (`requestId`) — только в журнале сервера, сайту не отдаются.

**Хранилище комнаты** (`RoomStorage`): `log:00000001…` — журнал, запись по ключу не меняется; `key:<SHA-256 ключа>` → номер участника или заявки (ключа в открытом виде нет; отвязанный помечен `unlinkedAt`); `invite` — токен приглашения; `secret` — секрет комнаты, заводится при первой заявке; `device:<SHA-256 токена>` → чья ссылка, `unlink`, `expiresAt`, `usedAt` / `revokedAt`. Номер комнаты и ключ ведущего выводятся из `requestId` и пароля компании (HMAC-SHA-256): повтор создания отдаёт тот же ключ, не храня его; `requestId` на сервере не хранится (Р-13). Так же ключ по заявке — HMAC секретом комнаты из `requestId` заявки: повтор заявки отдаёт тот же ключ.

**Ссылка-приглашение** (`src/rules/link.ts`): `https://goigolden88.github.io/Torg_Sin/#/join/<номер комнаты>/<токен invite>`; сервер не по умолчанию — `?server=<адрес>` в конце (адрес закодирован). Ссылку собирает ведущий из `invite`, который хранится у комнаты на его устройстве (`GET /rooms/<номер>` токен не отдаёт); «Пригласить» сервер не спрашивает — `POST /rooms/<номер>/invite` сменил бы ссылку. Комната создана на другом устройстве — `invite` нет, экран предлагает сменить ссылку. «Сменить ссылку» (ведущему, с подтверждением) — `POST /rooms/<номер>/invite`; новый `invite` записывается у комнаты вместо старого.

**Ссылка для другого устройства** (`src/rules/link.ts`): `…/Torg_Sin/#/device/<номер комнаты>/<токен>`, сервер — как у приглашения. Выдаёт «Ссылка для другого устройства» в комнате (`POST /device`): себе — любой участник; ведущий выбирает участника и, только за другого, флажок «Отвязать старый телефон» (`unlink`). Открыли ссылку — экран `ClaimDevice`: комната уже есть на устройстве — «Открыть», ссылка не тратится; нет — кнопка «Открыть комнату здесь» (не сама при открытии: просмотр ссылки в мессенджере её не истратит) → `POST /device/claim` → `GET /rooms/<номер>` → комната записывается с `invite: null`.

**Вход по ссылке на сайте** (`JoinRoom`): комната уже есть — открыть её; заявка уже подана (`joins`) — ожидание; иначе `POST /preview` → «Вход в комнату „<название>“, ведущий — <имя>», поле имени и «Попроситься» → `POST /join` с номером запроса (`requestFor`: та же форма — тот же номер, Р-13) → заявка записывается на устройство → «Ждём, пока ведущий впустит»: опрос `GET /rooms/<номер>` ключом заявки раз в 5 секунд, пока экран открыт и вкладка видна. 200 — комната записывается (`admitJoin`: комната и удаление заявки одной транзакцией) и открывается; `join: "rejected"` — «Ведущий отклонил заявку» (отметка — у заявки на устройстве) с «Попроситься снова»: `POST /preview` заново по ссылке, открытой сейчас (не по сохранённой в заявке: ведущий мог её сменить), → та же форма с прежним именем в поле, но с новым номером запроса (форма новая; прежний номер вернул бы ту же отклонённую заявку) → новая заявка записывается поверх отказа (`saveJoin`, та же запись `joins`). Ошибка — текст сервера («Такое имя уже есть — добавьте букву», «Ссылка недействительна…»), нет сети — «Нет связи с сервером»; введённое имя остаётся. Ведущему в открытой комнате — опрос `GET /requests` раз в 5 секунд; есть заявки — «Заявки (N)» с «Впустить» и «Отклонить»; впустил — состояние комнаты спрашивается заново. Сервер комнаты — из ссылки; «Настройки» не меняются.

**На устройстве.** IndexedDB `torgsin` (`src/store/db.ts`), версия 2 (шаг 1 → 2 только добавляет хранилище `joins`, комнаты не трогает). Хранилище `joins` по `roomId` — поданная, но не впущенная заявка (`SavedJoin`): `roomId`, `server` (из ссылки), `invite`, `name`, `memberId` (номер заявки), `key` (ключ заявки), `roomName`, `hostName` (что показала ссылка), `status` (`waiting` / `rejected`), `savedAt`; впустили — заявка становится комнатой и убирается. Хранилище `rooms` по `id` — своя комната (`SavedRoom`): `id`, `server` (адрес сервера комнаты: запоминается у комнаты, «Настройки» его не меняют), `memberId`, `key` (ключ телефона), `invite` (или `null`), последнее известное с сервера — `name`, `currency`, `hostId`, `createdAt`, `members` (`{ id, name }`), и `savedAt` (порядок в «Моих комнатах», новые сверху), `syncedAt` (последний ответ сервера; `null` — не было). Открыл комнату — состояние с сервера, записывается поверх; нет связи — показано последнее известное. Пароль компании — настройка устройства: localStorage `torgsin.password`, запоминается после удачного создания, стирается в «Настройках». Создание: форма → номер запроса (`requestFor`: та же форма — тот же номер) → `POST /rooms` → `GET /rooms/<номер>` → запись на устройство; кнопка «Создать» на время запроса закрыта (Р-13).

Сайт: `base` сборки `/Torg_Sin/`, адрес `https://goigolden88.github.io/Torg_Sin/`. Сервер: Worker `torg-sin`, адрес `https://torg-sin.goigolden88.workers.dev/`.

## Модель (черновик)

Все записи — с `id` (ULID), автором (`memberId`), временем сервера (`at`, UTC, мс). Суммы — целыми в минимальных единицах валюты комнаты. Итоги, коэффициенты, долги — считаются, не хранятся.

**Журнал комнаты только дописывается** (Р-11): ничего не стирается и не переписывается; отмена, уточнение, исправление — новая запись со ссылкой на прежнюю. Из журнала считаются текущее состояние и экран «История».

- `Room` — название, валюта, ведущий, ссылка-приглашение (меняется), создана, закрыта. В коде (`RoomState`): `id`, `name`, `currency`, `hostId`, `createdAt`, `members`; приглашение — не в журнале, отдельной записью хранилища.
- `Member` — номер (не привязан к способу входа), имя, ключи телефонов, впущен кем и когда, выбыл. В коде: `id`, `name`, `addedBy`, `addedAt`; ключи — только хешами в хранилище сервера, не в журнале.
- **Записи журнала** (`LogEntry`, этап 1): `room.created` (`roomId`, `name`, `currency`; автор — ведущий), `member.added` (`member`, `name`; автор — кто впустил, ведущего при создании — он сам; впущен по заявке — `member` равен номеру заявки), `join.requested` (`request`, `name`; автор — сама заявка), `join.rejected` (`request`; автор — ведущий), `invite.changed` (автор — ведущий; токена нет), `device.issued` (`member`, `unlink`, `expiresAt`; автор — он сам или ведущий; токена нет), `device.linked` (`member`, `unlink`; автор — участник). Состояние — `foldLog` по порядку записей; заявки — `joinRequests` (ждёт, впущена, отклонена; решение — первое).
- **Записи журнала событий** (этап 2): `event.created` (`condition`, `check`, `outcomes: [{ id, title }]` — полным списком, со «Другое», если исходы свои, `closesAt`, `expectedAt`, `subject` — номер участника или `null`, `requestId`; автор — кто завёл; номер события — `id` записи), `bet.placed` (`event`, `outcome`, `amount`, `requestId`; автор — кто поставил), `event.clarified` (`event`, `text`; автор — автор события), `event.cancelled` (`event`, `reason` или `null`; автор — кто отменил). `requestId` — номер запроса телефона, не секрет: по нему узнаётся повтор (Р-13). События — `roomEvents` (`src/rules/event.ts`) по порядку записей; записи о неизвестном событии не действуют; отмена — первая; статус — из журнала и времени сервера, не хранится.
- `Event` (пул) — условие, «как проверяем», исходы (2+; свои — с «Другое» последним, Р-16), приём ставок до, исход ожидается к, автор, предмет (участник, если спор о нём); уточнения автора, отмена. В коде: записи `event.*` журнала, `EventState` / `EventView` (`src/rules/event.ts`, `protocol.ts`).
- `Bet` — событие, участник, исход, сумма. Отменить нельзя, добавить можно.
- `Offer` (пари) — условие, «как проверяем», сторона автора, кэф `a:b`, сумма автора, адресат или открытое, приём до, исход к, гарант; принято кем, отозвано, встречное к какому.
- `Outcome` — предложено кем и что, отметки сторон пари, возражения, утверждено кем (автор, ведущий, голосование, гарант, согласие сторон), когда; окончательно с.
- `Appeal` — кто, причина, присоединившиеся; суд (состав, жребий — зерно и список кандидатов), голоса, решение.
- `Transfer` — расчёт: кто кому, сколько; отметка «получил».
- **Валюты** — таблица в коде: код, знаков после запятой, знак, название для выбора (`RUB 2 ₽ рубли`, `USD 2 $ доллары`, `EUR 2 € евро`, `USDT 2`, `BTC 8 ₿ биткоины`, `PTS 0 очки`); новая валюта — строка таблицы (Р-07).

## Правила

- **Пул.** Банк события — все ставки; победители делят его пропорционально своим ставкам на исход; остаток единиц — по порядку ставок. Коэффициент исхода = банк ÷ ставки на исход; «вероятность по ставкам» = ставки на исход ÷ банк.
- **Пари.** Автор рискует `a·k`, соперник `b·k`; победитель забирает оба. «3 к 1, сумма автора 300» → соперник ставит 100.
- **Исход пула.** Автор предлагает (молчит 3 дня после срока — ведущий) → сутки на возражение → утверждён; возражение → ведущий; ведущий ставил → голосуют не ставившие (большинство; ничья — суд сразу).
- **Исход пари** (Р-05, Р-06). Каждая сторона отмечает исход с подтверждением. Совпало — утверждён без гаранта и окончательный сразу. Разошлось или одна молчит 3 дня — решает гарант; пока он не решил, сторона может поменять отметку. Гарант молчит 3 дня или отказался → стороны выбирают другого (ведущий — по умолчанию, если не сторона).
- **Апелляция.** 7 дней после утверждения; подаёт ставивший (у пари — сторона) с причиной; одна на событие, другие присоединяются. Суд — ведущий + 2 присяжных жребием из незаинтересованных (не ставили, не стороны, не гарант, не автор и не предмет события, не апеллянт); 72 часа; 2 из 3; голос — «оставить» / «изменить на …» / «отменить событие — вернуть ставки»; решение окончательное.
- **Окончательность.** Событие окончательно, когда прошла неделя без апелляции, суд решил или стороны пари согласились; только окончательные идут в «Расчёт».
- **Расчёт.** Итог каждого по окончательным событиям и пари → минимум переводов (жадно, от большего долга к большему выигрышу) → получатель отмечает «получил».
- **История** (Р-11). Экран «История» комнаты: прошедшие события и пари — исход, кто сколько ставил, возражения, апелляции, жребий; итог каждого по времени. Закрытая комната остаётся в «Моих комнатах» только для чтения.

## Крайние случаи и как решаются

| Случай | Как решается |
|---|---|
| На выигравший исход никто не ставил; ставки только на один исход | Событие — «без игры»: все ставки возвращаются |
| Ставка после того, как исход стал известен | Приём закрывается в срок автора (ставится до события), по времени сервера; поздняя ставка «на известное» — основание апелляции, суд может отменить событие |
| Условие неясное, спорят о смысле | Шаблон «Условие / Как проверяем / Срок»; после первой ставки текст не меняется — только уточнения, видные всем; поменять по сути — отменить событие и завести заново |
| Спор о самом участнике («я подтянусь 50 раз») | Предмет спора может ставить, но не объявляет исход, не гарант и не присяжный |
| Доказательство (видео, фото) | В первой версии — ссылка или текст; вложения на сервере — позже |
| Отменить событие | До закрытия приёма — автор, ставки возвращаются; после — только ведущий или гарант с причиной, и это обжалуется |
| Отменить свою ставку | Нельзя (иначе крупная ставка и отмена двигают коэффициенты); можно добавить. Пари — отзыв, пока не принято |
| Нажал «Поставить» дважды | Ставка — с подтверждением суммы; повтор того же действия с тем же номером сервер не примет дважды |
| Обе стороны пари ошибочно отметили один исход | Отметка — с подтверждением; совпадение окончательно сразу (Р-06) |
| Ведущий — сторона или ставил | Не решает возражение и не сидит в суде за ведущего: третий присяжный — жребием |
| Сговор ведущего и друга | Присяжных выбирает жребий сервера; кандидаты и выпавшие видны всем в истории события |
| Присяжный не голосует | Через 72 часа — одна замена жребием; дальше решают проголосовавшие; ничья — исход остаётся |
| Незаинтересованных меньше трёх | Суд из тех, кто есть; ни одного — апелляции нет; экран предупреждает при создании события |
| Апелляция после «Расчёта» | Невозможна по устройству: в расчёт идут только окончательные события |
| Участник пропал с долгом | Долг остаётся в расчёте; выйти из комнаты — только без открытых ставок и с отмеченными переводами; ведущий может пометить «выбыл» — открытые ставки доигрываются |
| Ведущий пропал | 7 дней без входа — любой участник может взять ведение, все видят |
| Потерял телефон | «Ссылка для другого устройства»; без неё — ведущий привязывает к новому телефону, старый отвязывается |
| Ссылка утекла | Новичка впускает ведущий; ссылку можно сменить — старая перестаёт работать |
| Сервер лежал в момент срока | Приём закрывается по времени сервера: ставка с меткой позже срока отклоняется; будильник срабатывает, когда сервер поднялся |
| Часовые пояса | Время хранится в UTC, показывается местное |
| Разные валюты у друзей | Одна валюта на комнату; другая валюта — другая комната |
| Закрыть или удалить комнату | По умолчанию — «закрыть»: только чтение, история остаётся (Р-11). Удалить — только ведущий, только когда всё окончательно и переводы отмечены; перед удалением у всех — копия |

## Вёрстка (Р-10)

Одна страница на все экраны, «сначала телефон»: базовые правила CSS — для узкого экрана, шире — через `min-width`.

- **до 600 px** — телефон: одна колонка, вкладки снизу (`.nav` внизу), открытое — отдельным экраном;
- **600–1023 px** — планшет: то же, поля шире;
- **от 1024 px** — компьютер: меню слева (`.nav` колонкой); «список + открытое» (`.split`) — рядом: список ≈ 340 px (`--list-w`), открытое ≤ 720 px (`--detail-w`), вместе — по центру свободного места (на широком мониторе по краям пусто поровну).

Меню слева на компьютере сворачивается до значков: кнопка ««»/«»» вверху меню (`.nav-toggle`, `aria-label` «Свернуть меню» / «Развернуть меню»), у `.app` — класс `.nav-collapsed`; подписи (`.nav-label`) скрыты, у значка — всплывающая подпись (`title`) и `aria-label`. Положение — настройка устройства (localStorage `torgsin.navCollapsed`, `getNavCollapsed` / `setNavCollapsed` в `src/settings.ts`), по умолчанию развёрнуто. Ниже 1024 px кнопки нет, класс ни на что не влияет.

Комната на компьютере (`.room`): заголовок, «Валюта · создана», заявки, кнопки и участники — колонкой с одним отступом; участники (`.members`) — список в рамке со строками-разделителями. На телефоне и планшете — как было.

«Мои комнаты» (`.rooms`): список (`.list`) и открытое (`.detail` — комната или форма создания). На телефоне и планшете открыто что-то — класс `.open`, виден только `.detail` с «Назад» (`.back`); ничего — только список. От 1024 px видны оба, «Назад» скрыт.

Правила: действия — видимыми кнопками (на телефоне наведения мыши нет; `:hover` — только украшение); широкие таблицы на телефоне — карточками; кнопки и поля не ниже 44 px (`--tap`); на компьютере Enter отправляет форму, Esc закрывает окно; длинные строки переносятся (`overflow-wrap`). Каждый экран проверяется на 390 и 1280 px — снимки в PR; раскладка компьютера (меню развёрнуто и свёрнуто) — ещё и на 1920 px (`npm run shots`).

## Резерв сервера (Р-02)

1. **Код переносим:** правила — чистые функции над `RoomStorage`; Cloudflare — обёртка; запасная — Node + SQLite в `server/node/`, CI гоняет одни тесты на обеих (`roomsSuite`; `npm test` показывает каждый набор дважды). Запуск — `npm run server:node` (Vite собирает `server/node/main.ts` в `server/node/dist/main.js`, встроенные `node:sqlite` и `node:http`, Node 24): адрес `http://localhost:8787`, те же ответы, что у Worker'а. Переменные: `ROOM_PASSWORD` — пароль компании, `PORT` (8787), `HOST` (все адреса), `ROOMS_DB` — файл комнат (`server/node/data.sqlite`, в `.gitignore`). Будильник комнаты (`setAlarm`) хранится в файле; обработчик (`onAlarm`, как `alarm()` объекта `Room`) — пока пустой: сроков у комнат ещё нет. Типы — `server/node/tsconfig.json` с `@types/node` (Р-14), проверка — в `npm run server:check`.
2. **Данные в трёх местах:** сервер; журнал комнат на каждом телефоне участника («Файл-копия»); суточная выгрузка всех комнат (этап 6).
3. **Переезд:** сервер отдаёт и принимает комнату целиком (`export` / `import`, с паролем компании); адрес сервера — в «Настройках» и в ссылке комнаты.
4. **`docs/Резерв сервера.md`** — для человека: признаки беды и шаги переезда (этап 6).
