# Архитектура

Источник истины для кода: имена, модель, правила. Отступление — вслух и до кода (`CLAUDE.md`). Модель и правила — из ТЗ (Штаб, `docs/замыслы/Тотализатор.md`, Ш-182…Ш-191); имена полей — черновик, уточняет этап 1 и каждый следующий в этом файле.

## Устройство

```
Телефон или компьютер (сайт-PWA на GitHub Pages)     Сервер (Cloudflare Worker)
  React + TypeScript, IndexedDB: журнал        ⇄    объект Room на комнату (SQLite)
  своих комнат, «Мои комнаты», копия                  над правилами src/rules/
  адрес сервера — «Настройки» и ссылка                реестр комнат, будильник к срокам и суду
                                                      запасная обёртка: Node + SQLite (те же тесты)
```

- **Один репо:** сайт (`src/`), сервер (`server/`), общие правила (`src/rules/` — чистые функции, ими пользуются и экран, и сервер; ни DOM, ни Cloudflare). Публичный — данных в нём нет.
- **Сервер — источник истины** (Р-01). Ставка, исход, жребий — только на сервере, по времени сервера; объект комнаты обрабатывает действия по одному — гонок «две ставки в последнюю секунду» нет. Телефон без сети показывает последнее известное; ставить без сети нельзя.
- **Связь:** запрос-ответ; открытая комната и событие спрашивают сервер раз в 5 секунд, пока экран открыт и вкладка видна (`usePoll`); WebSocket в этапе 2 не делаем (Р-18). Версия протокола `PROTOCOL_VERSION` (`src/rules/protocol.ts`) — в каждом ответе и сообщении; не та версия — экран просит обновить страницу.
- **Хранилище за интерфейсом** `RoomStorage` (get, put, list, setAlarm) — две реализации: Cloudflare (`server/src/index.ts`) и Node (`server/node/`, этап 1). Правила о Cloudflare не знают (Р-02).
- **Создание комнаты** — по паролю компании (секрет Worker'а `ROOM_PASSWORD`); вход — по ссылке, без пароля, впускает ведущий (Р-03).
- **Адрес сервера** — `DEFAULT_SERVER` (`src/rules/address.ts`, `https://torg-sin.goigolden88.workers.dev`); свой — в «Настройках» (localStorage `torgsin.server`) и в ссылке комнаты: при переезде телефоны идут на новый адрес сами (Р-02).

**Адреса сервера.** Ответ — JSON с `v` (версия протокола); отказ — `{ v, error }` с текстом для человека.

- `POST /rooms` — `{ password, name, currency, hostName, requestId? }` → `{ roomId, invite, memberId, key }`. Пароль на сервере не задан — 503 «Создание комнат выключено»; пароль неверный или пустой — 403 «Неверный пароль компании»; форма с ошибкой — 400. `requestId` — номер запроса (ULID) от телефона: повтор с тем же номером — та же комната и тот же ответ; с другой формой — 409.
- `GET /rooms/<номер>` с заголовком `Authorization: Bearer <ключ>` → `{ room: { id, name, currency, hostId, createdAt }, members: [{ id, name }], me, events, offers, now }`; `events` — события-пул по порядку создания (ниже), `offers` — пари по порядку создания (ниже, Р-22), `now` — время сервера в ответе (UTC, мс): по нему сайт считает отсчёт до закрытия приёма, а не по часам телефона. Нет ключа или ключ не участника — 403; нет комнаты — 404. Ключ заявки, которую ещё не впустили, — 403 «Ждём, пока ведущий впустит» с `join: "waiting"`; отклонённой — 403 «Ведущий отклонил заявку» с `join: "rejected"` (экран ожидания спрашивает раз в несколько секунд).

**Вход по ссылке** (Р-03). Ссылка-приглашение несёт номер комнаты и токен `invite`; токены — в теле запроса, не в адресе. Связь — запрос-ответ, ожидание — опросом раз в 5 секунд; WebSocket в этапе 2 не делаем (Р-18).

- `POST /rooms/<номер>/preview` — `{ invite }` → `{ name, hostName }`, больше ничего. Токен неверный, сменённый, нет комнаты — 403 «Ссылка недействительна — попросите новую у ведущего».
- `POST /rooms/<номер>/join` — `{ invite, name, requestId? }` → `{ memberId, key, join: "waiting" }`: ключ телефона, который откроет комнату, когда ведущий впустит; `memberId` — номер заявки, он же номер участника. Имя уже у участника или ждущей заявки (без учёта регистра) — 409 «Такое имя уже есть — добавьте букву»; имя пустое или длиннее 30 — 400. Повтор с тем же `requestId` — та же заявка и тот же ключ (`join` — её нынешнее состояние); тот же номер с другим именем — 409.
- `GET /rooms/<номер>/requests` — ведущему: ждущие заявки `{ requests: [{ id, name, at }] }`.
- `POST /rooms/<номер>/admit` и `/reject` — `{ request }`, ведущему → `{ member: { id, name } }` и `{ request }`. Повтор того же решения — тот же ответ без записи; обратное — 409 («Участник уже впущен», «Заявка уже отклонена»); нет заявки — 404.
- `POST /rooms/<номер>/invite` — ведущему: новая ссылка `{ invite }`; старая перестаёт работать, впущенные и поданные заявки не страдают.
- `POST /rooms/<номер>/device` — `{ member?, unlink? }` → `{ token, member, expiresAt }`: «ссылка для другого устройства», одноразовая, на 24 часа. Себе — любой участник; за другого — только ведущий. `unlink: true` — когда ссылкой воспользуются, прежние ключи участника и его неиспользованные ссылки гаснут (потерял телефон).
- `POST /rooms/<номер>/device/claim` — `{ token }` → `{ memberId, key }`: новый ключ того же участника. Второй раз, через сутки или чужой токен — 403 «Ссылка для другого устройства недействительна — попросите новую».
- Действия по ключу: нет ключа или ключ не участника — 403; не ведущий там, где нужен ведущий, — 403 «Это может только ведущий».

**События-пул** (этап 2; экраны — «События на сайте» ниже). Все адреса — по ключу участника (нет ключа или ключ не участника — 403); номер события — `id` его записи `event.created`; нет события — 404 «Нет такого события».

- `POST /rooms/<номер>/events` — `{ condition, check, outcomes?, closesAt, expectedAt, subject?, requestId? }` → `{ event: EventInfo }` (`id`, `at`, `authorId`, `condition`, `check`, `outcomes: [{ id, title }]`, `closesAt`, `expectedAt`, `subjectId`, `subjectRule` — действует ли правило предмета, Р-26: у нового события с предметом — `true`). Заводит любой участник. `outcomes` не задан или пуст — «Да» и «Нет»; свои — 2–6, каждый ≤ 40 знаков, и сервер добавляет последним «Другое (ничего из перечисленного)» (Р-16); номер исхода — «1», «2», … по порядку. Одинаковые варианты (без учёта регистра и пробелов по краям, «Другое» тоже) — 400. Условие и «как проверяем» — не пустые, ≤ 300 знаков. `closesAt` — «приём ставок до» (не включая), уже прошёл по времени сервера — 400; `expectedAt` — «исход ожидается к», раньше `closesAt` — 400. `subject` — предмет спора, участник комнаты (не участник — 400). Повтор с тем же `requestId` — то же событие и тот же ответ, даже после срока; тот же номер с другой формой или от другого — 409.
- `POST /rooms/<номер>/events/<событие>/bets` — `{ outcome, amount, requestId? }` → `{ bet: { id, event, memberId, outcome, amount, at } }`. Любой участник, и автор, и предмет спора; несколько раз и на разные исходы; отменить нельзя. Предмет спора у события с `subjectRule` (Р-26) — только на «Да» (403 «Вы — предмет спора: ставить можно только на „Да“»), в событии со своими исходами — никак (403 «Вы — предмет спора: в событии со своими исходами вы не ставите»); у старых событий без признака — как прежде. `amount` — целое > 0 в минимальных единицах (иначе 400), банк события не выходит за безопасное целое (400). Ставка в момент или после `closesAt` по времени сервера в момент запроса — 409 «Приём ставок закрыт» (будильника нет: срок проверяется при каждом запросе, сервер лежал — всё равно закрыто); отменённое событие — 409 «Событие отменено»; нет исхода — 400. Повтор с тем же `requestId` — та же ставка и тот же ответ (и после срока); тот же номер с другой суммой, исходом или от другого — 409.
- `POST /rooms/<номер>/events/<событие>/clarify` — `{ text }` (≤ 300 знаков) → `{ clarification: { id, at, text } }`. Только автор события (403 «Это может только автор события»); условие, «как проверяем» и исходы не меняются никогда.
- `POST /rooms/<номер>/events/<событие>/cancel` — `{ reason? }` → `{ cancelled: { at, by, reason } }`. Пока приём идёт — только автор, причина по желанию; после закрытия — только ведущий (403 «Это может только ведущий») и только с причиной ≤ 300 знаков (400 «Нужна причина отмены»). Уже отменено — та же отмена без новой записи. Отменённое ставок не принимает; ставки возвращаются.
- Событие в `GET /rooms/<номер>` (`EventView`): поля `EventInfo` и `status` (`open` — приём идёт, `closed` — закрыт, `cancelled` — отменено; на `now`), `clarifications: [{ id, at, text }]`, `bets: [{ id, memberId, outcome, amount, at }]` по порядку журнала, `cancelled` (`{ at, by, reason }` или `null`), `refunds: [{ memberId, amount }]` — у отменённого каждому его сумма (`settlePool` «без игры»), иначе пусто, `outcome` — исход (ниже; не предложен — `null`). Номера запросов (`requestId`) — только в журнале сервера, сайту не отдаются.

**Исход события** (этап 2, Р-05, Р-17, Р-21; на сайте — «Исход» в «Событиях на сайте» ниже). Адреса — `POST /rooms/<номер>/events/<событие>/propose | object | agree | decide | vote`, по ключу участника, с `requestId?`: повтор с тем же номером — тот же ответ без второй записи (и после сроков); тот же номер с другим содержимым, от другого или к другому событию — 409 «Этот номер запроса уже занят другим действием». Нет события — 404; отменённое — 409 «Событие отменено». Сроки считаются в момент запроса по времени сервера — будильника нет.

- `propose` — `{ outcome }` → `{ proposal: { id, at, by, outcome } }`. Пока приём идёт — 409 «Приём ставок ещё идёт…». Предлагает автор события; предмет спора — никогда (403 «Предмет спора не объявляет исход»): если автор — предмет, предлагает ведущий; автор молчит 3 дня после `expectedAt` — может и ведущий; ведущий завёл событие о себе (он и автор, и предмет) — любой участник, кроме него, первый предложивший (Р-19); остальным — 403. Исход — один из исходов события (иначе 400). Второе предложение — 409 «Исход уже предложен».
- `object` — `{ reason }` (не пустая, ≤ 300 знаков, иначе 400) → `{ objection: { id, at, by, reason } }`. Только ставивший на событие (403), не предложивший (403 «Свой исход не оспаривают»), до `proposal.at` + 24 часа (не включая; позже — 409 «Сутки на возражение прошли»); от участника — одно (второе — 409 «Вы уже возразили»); согласившийся — 409 «Вы уже согласились»; исход уже утверждён (ведущим или согласием всех) — 409. Нет предложения — 409.
- `agree` — `{}` → `{ agreement: { id, at, by } }` (Р-21). Только ставивший на событие (403 «Согласиться может только тот, кто ставил»), не предложивший (403 «Своё предложение не подтверждают»), до `proposal.at` + 24 часа (позже — 409 «Сутки на возражение прошли»); от участника — одно (второе — 409 «Вы уже согласились»), не отзывается; возразивший — 409 «Вы уже возразили»; есть хоть одно возражение — 409 «Есть возражение — согласия больше не принимаются»; исход уже утверждён — 409. Нет предложения — 409.
- `decide` — `{ outcome }` → `{ decision: { id, at, by, outcome } }`. Только ведущий (403), только после возражения (409 «Возражений нет…»), только если ведущий не ставил и не предмет спора (иначе 403 — решает голосование); любой исход события; одно решение (второе — 409).
- `vote` — `{ outcome }` → `{ vote: { id, at, by, outcome } }`. Когда ведущий ставил или он предмет спора и есть возражение (иначе 409). Голосуют участники на миг первого возражения, кто не ставил и не предмет спора (остальным 403); один голос (второй — 409); голосование кончилось — 409 «Голосование закончено».
- В `EventView.outcome` (`OutcomeView`): `status` — `proposed` (сутки на возражение), `disputed` (ждёт решения ведущего), `voting`, `court` (ждёт суда, этап 4; исход не утверждён), `approved`, `final`, `cancelled` (событие отменено на любом шаге, и после утверждения: выплат нет, `finalAt` — `null`, окончательным не станет и в «Расчёт» не идёт; `approved` остаётся тем, что было утверждено до отмены, или `null`; возврат — `refunds`, Р-19); `proposal`, `objectionUntil`, `objections`, `agreements` (`[{ id, at, by }]` — согласия ставивших, кроме предложившего, поданные до конца суток), `awaiting` (чьего согласия ещё ждём, пока статус `proposed`; иначе пусто), `decision`, `voters`, `votingUntil` (первое возражение + 72 часа; голосования нет — `null`), `votes`; `approved` — `{ outcome, at, how, by }`: `unopposed` — сам через сутки без возражения (`at` — конец суток, `by` — `null`), `host` — ведущим (`by` — ведущий), `vote` — голосованием (`at` — последний голос, если проголосовали все, или конец 72 часов), `agreed` — согласием всех ставивших до возражения (`at` — последнее согласие; кроме предложившего, никто не ставил — миг предложения; `by` — `null`; Р-21); `finalAt` — `approved.at` + 7 дней (апелляции — этап 4), у `agreed` — сам `approved.at`: окончательный сразу; с него статус `final` (событие отменено — `null`); `void` и `payouts: [{ memberId, staked, payout, net }]` — `settlePool` по утверждённому исходу (не утверждён или событие отменено — пусто). Голосование: побеждает исход с большинством поданных голосов; ничья, ни одного голоса за 72 часа или некому голосовать — `court`.

**Пари** (этап 3, Р-04, Р-22; правила — «Правила пари в коде» ниже; исход пари — ниже, Р-23; экраны — «Пари на сайте» ниже). Все адреса — `POST`, по ключу участника (нет ключа или ключ не участника — 403), с `requestId?`: повтор с тем же номером — тот же ответ без второй записи (и после сроков); тот же номер с другим содержимым, от другого или у другого действия — 409 «Этот номер запроса уже занят другим действием». Номер пари — `id` его записи `offer.created`; нет пари (или кривой номер) — 404 «Нет такого пари». Сроки — по времени сервера в момент запроса, будильника нет: «истекло» считается, не записывается. Отказы правил: «не вам» (своё, гарант, не адресат, не автор) — 403, «уже не то состояние» (принято, отозвано, закрыто встречным) — 409, срок «приём до» прошёл — 409 «Приём закрыт — срок «приём до» прошёл».

- `POST /rooms/<номер>/offers` — `{ condition, check, side?, odds: { a, b }, amount, to?, closesAt, expectedAt, guarantor?, subject?, requestId? }` → `{ offer: OfferInfo }` (`id`, `at`, `authorId`, `condition`, `check`, `side`, `odds`, `amount` — сумма автора, `takerAmount` — сумма соперника по кэфу, `to`, `closesAt`, `expectedAt`, `guarantorId`, `counterTo: null`, `subjectId` — о ком спор или `null`, Р-26). `subject` — о ком спор (`checkOfferSubject`, 400): участник; автор-предмет — только `side: yes`; адресат-предмет — только `side: no`; не гарант. Предлагает любой участник; форма — `checkOfferInput` (400 с текстом правил: кэф, сумма соперника меньше единицы, условие, сроки, сторона); адресат и гарант — `offerGuarantor` (400); `side` не задана — `yes`, `to` не задан — открытое, `guarantor` не задан — ведущий (ведущий — автор или адресат — 400 «Ведущий — сторона пари: выберите гаранта»). «Приём до» уже прошёл — 409; «исход к» раньше него — 400.
- `POST …/offers/<пари>/accept` — `{}` → `{ accepted: { id, at, by, offer }, offer: OfferInfo }` (суммы обеих сторон — в `offer`). `checkAccept`: адресное — только адресат (иначе 403 «Пари предложено другому участнику»), открытое — любой, кроме автора (403 «Своё пари не принимают») и гаранта (403); предмет спора — только если автор за «не сбудется» (403, Р-26; встречное — так же); второй принявший — 409 «Пари уже принято»; отозванное, закрытое встречным — 409; после «приём до» — 409 «Приём закрыт…».
- `POST …/offers/<пари>/revoke` — `{}` → `{ revoked: { id, at, by, offer } }`. Только автор (403 «Отозвать может только автор пари»), пока не принято (409 «Принятое пари не отзывают») и не закрыто встречным; уже отозвано — 409 «Пари отозвано».
- `POST …/offers/<пари>/counter` — `{ odds?, amount?, closesAt, requestId? }` → `{ offer: OfferInfo }` — новое пари с `counterTo` (`counterInput`): свои кэф и/или сумма (не заданы — исходного) и «приём до» (нет — 400 «Нужен срок «приём до»»); условие, «как проверяем», «исход к» — исходного; сторона — обратная; адресат — автор исходного; гарант — тот же. Делает тот, кто мог бы принять исходное (`checkCounter`: своё, гарант, не адресат — 403; принятое, отозванное, закрытое — 409; после «приём до» — 409 «Приём закрыт…»); форма встречного — `checkOfferInput` (400); его «приём до» прошёл — 409, позже «исход к» исходного — 400. Автор исходного принял встречное — исходное закрыто встречным (`roomOffers`).
- Пари в `GET /rooms/<номер>` (`offers`, `OfferView`): поля `OfferInfo` и `status` на `now` — `open` (открыто), `accepted` (принято), `withdrawn` (отозвано), `expired` (истекло), `countered` (закрыто встречным); `accepted` (`{ by, at }` — кто принял, или `null`), `withdrawnAt` (или `null`), `closedBy` (`{ offer, at }` — каким встречным закрыто, или `null`), `outcome` — исход (ниже; не принято — `null`). Видят все участники, адресные тоже — тайных пари нет. Номера запросов сайту не отдаются.

**Исход пари** (этап 3, Р-05, Р-06, Р-23; правила — «Исход» в «Правилах пари в коде» ниже; экран — «Исход пари» в «Пари на сайте»). Адреса — `POST /rooms/<номер>/offers/<пари>/mark | decide | decline | nominate`, по ключу участника, с `requestId?` — повтор и отказы как у пари выше: «не вам» — 403, «уже не то состояние» — 409, кривое тело — 400, нет пари — 404. Фазы считаются в момент запроса по времени сервера — будильника нет.

- `mark` — `{ winner: "author" | "taker" }` (иначе 400 «Отметка — «прав автор» или «прав соперник»») → `{ marked: { id, at, by, offer, winner } }`. `checkMark`: только сторона принятого пари (гарант — 403 «Гарант не отмечает исход как сторона…», не сторона — 403 «Это могут только стороны пари»); не принято — 409; утверждён согласием или гарант решил — 409. Поменять можно до решения гаранта; та же отметка, что действует, — ответ прежней записью, новой нет. Отметки совпали — исход утверждён согласием и окончательный сразу.
- `decide` — `{ winner }` → `{ decided: { id, at, by, offer, winner } }`. `checkDecide`: только нынешний гарант (403 «Это может только гарант пари»); стороны ещё отмечают (не разошлись и 3 дня после «исход к» / первой отметки не прошли) — 409; 3 дня гаранта прошли или он отказался — 409 «Гарант не решил за 3 дня или отказался…». Окончательный через 7 дней.
- `decline` — `{}` → `{ declined: { id, at, by, offer } }`. `checkDecline`: только нынешний гарант (403), пока исход не утверждён (409) и другой гарант ещё не нужен (409). Дальше — «нужен другой гарант».
- `nominate` — `{ guarantor }` → `{ nominated: { id, at, by, offer, guarantor } }`. `checkNominate`: только сторона (403), только когда нужен другой гарант (иначе 409 «Гарант на месте…»); кандидат — участник комнаты, не сторона (иначе 400). Обе стороны назвали одного — он гарант, его 3 дня — с назначения.
- В `OfferView.outcome` (`OfferOutcomeView`, `offerOutcome` на `now`): `phase` — `marking` (отмечают), `guarantor` (решает гарант), `need-guarantor` (нужен другой гарант), `approved` (утверждён гарантом), `final` (окончательный); `marks` — `{ author, taker }`, последняя отметка каждой стороны или `null`; `guarantorId` — нынешний гарант; `turnAt` — с какого мига решает гарант; `guarantorUntil` — до какого мига он решает (утверждено — `null`); `needSince` — с какого мига нужен другой гарант (или `null`); `nominations` — кого называют стороны (`{ author?, taker? }`); `approved` — `{ winner, at, how: "agreement" | "guarantor", by }` (согласием — `by: null`) или `null`; `finalAt` — с какого мига окончательный (или `null`).

**Апелляция и суд** (этап 4, Р-05, Р-24, Р-25; правила — «Правила апелляции в коде» ниже; экраны — «Апелляция и суд на сайте» ниже). Адреса — `POST /rooms/<номер>/events/<событие>/…` и `POST /rooms/<номер>/offers/<пари>/…` + `appeal | appeal/join | judge | replace`, по ключу участника, с `requestId?`: повтор с тем же номером — тот же ответ без второй записи (и после сроков и решения суда); тот же номер у другого действия, спора, содержимого или от другого — 409 «Этот номер запроса уже занят другим действием». Нет события — 404 «Нет такого события», нет пари (и номер события по адресу пари) — 404 «Нет такого пари». Отказы — тексты правил: «не вам» (не ставивший, согласившийся, не сторона, своя апелляция, не член суда, не ведущий, ведущий заинтересован, себя) — 403; кривое тело (причина, голос, кого заменить) — 400; «уже не то состояние» — 409. Сроки — по времени сервера в момент запроса, будильника нет.

- `appeal` — `{ reason }` (не пустая, ≤ 300 знаков, иначе 400) → `{ appeal: { id, at, by, target, reason, seed, candidates } }`. `checkAppeal`: у пула — ставивший, кроме согласившихся (403), у пари — сторона (403); исход утверждён (иначе 409 «Исход ещё не утверждён…»), не согласием (409) и не окончательный (7 дней прошли — 409); событие отменено — 409; одна на спор (вторая — 409 «Апелляция уже подана — присоединитесь к ней»); судить некому — 409. Суд собран в этот миг: зерно — 16 случайных байт сервера (`crypto.getRandomValues`, hex), `candidates` — `courtCandidates` на этот миг (без подавшего), оба — в той же записи журнала.
- `appeal/join` — `{}` → `{ joined: { id, at, by, target } }`. `checkJoin`: апелляции нет — 409; тот, кто мог бы подать (403), не подавший (403); второй раз и после решения суда — 409.
- `judge` — `{ verdict: "keep" | "change" | "cancel", outcome? | winner? }` → `{ voted: { id, at, by, target, verdict, outcome? | winner? } }`. У пула «изменить» — с `outcome` (исход события), у пари — с `winner` (`author` / `taker`); иначе 400. `checkCourtVote`: только член суда на своём месте (403), в его 72 часа (позже — 409), один раз (409 «Вы уже проголосовали…»); «оставить» без апелляции и «изменить» на тот же исход — 400; суд решил — 409. Суда нет — 409 «Суда по этому спору нет».
- `replace` — `{ member, reason }` (кого — не строка — 400 «Такого члена суда нет»; причина — не пустая, ≤ 300 знаков) → `{ replaced: { id, at, by, target, member, reason } }`. `checkReplace`: только ведущий (403), если сам не заинтересован (403); не себя (403); только член суда на месте (400), не проголосовавший (409), одна замена на место (409), до решения (409). Суда нет — 409.
- **Суд по «ждёт суда»** собирается сам: при первом запросе к комнате (`GET /rooms/<номер>` и любое действие, ещё до самого действия) после того, как исход пула перешёл в «ждёт суда», сервер один раз дописывает `court.drawn` — зерно, кандидаты на этот миг; второй запрос второй записи не даёт. Кандидатов нет — записи нет, исход остаётся «ждёт суда» (выход — отмена ведущим с причиной, Р-19).
- В `GET /rooms/<номер>` у исхода пула (`OutcomeView`) и пари (`OfferOutcomeView`) — `appeal` и `court` по правилам на время сервера (`eventView` / `offerView` с делом суда из `logAppeals`): места, сроки, замены, голоса, решение; окончательность, выплаты пула и итог пари — с учётом суда. Суда нет — полей нет. Версия протокола — 3: старый сайт видит «обновите страницу», а не падает. С предметом спора (Р-26: `subjectRule` у события, `subjectId` у пари, `subject` в форме пари) — 4.

**События на сайте** (Р-04, Р-18). Комната (`RoomView`), новое событие (`NewEvent`) и событие (`EventScreen`) спрашивают `GET /rooms/<номер>` раз в 5 секунд (`useRoom` поверх `usePoll`), ответ — на устройство (`withState`, поле `events`). Часы сервера: `now` из последнего ответа плюс прошедшее на телефоне по монотонным часам (`performance.now()`), на комнату — общие для её экранов; по ним отсчёт до закрытия приёма и статус между опросами (`eventStatus`).

- **«События» в комнате** (`EventList`) — под участниками: «Новое событие»; сначала «Приём идёт» (ближний срок сверху, «Приём ставок до … — осталось …»), ниже «Закрытые и отменённые» (новые сверху); у каждого — банк и число ставок; предмет спора сам поставил — пометка (Р-26, `SubjectFlag` по `subjectStake`): «⚑ Аня — предмет спора — сам ставит: 300 ₽ на „Да“» (у старого события со ставкой на «Нет» — «⚑ Аня — предмет спора — поставил против себя»), жирным в рамке; пусто — «Событий пока нет».
- **«Новое событие»** (`#/room/<номер>/event/new`): «Условие», «Как проверяем», исходы — «Да / Нет» или «Свои варианты» (2–6 полей, «Добавить вариант» / «Убрать», под ними — «Последним добавится „Другое (ничего из перечисленного)“»), «Приём ставок до» и «Исход ожидается к» (`datetime-local`, местное время; подсказка — завтра к ровному часу и ещё сутки), «Предмет спора» — «Никто» или участник. Форма проверяется `checkEventInput`, сроки — сервером; номер запроса — `requestFor` (та же форма — тот же номер, Р-13) и синхронный замок; удалось — состояние комнаты заново и экран события; ошибка — текст сервера, введённое остаётся.
- **Событие** (`#/room/<номер>/event/<номер события>`): условие, «Как проверяем», уточнения со временем, автор, предмет спора, «исход ожидается к», строка статуса («Приём ставок до … — осталось …» / «Приём ставок закрыт <дата, время>» / «отменено — ставки возвращены» с кем, когда и причиной). Полоса банка на каждый исход — доля по `poolOdds` и основание: «банк 750 ₽, на „Да“ 300 ₽ — коэффициент 2,5, вероятность по ставкам 40 %»; проценты полос — `chancePercents` (в сумме 100), то же число на полосе и в строке под ней; без ставок — «ставок нет». Под строкой статуса — та же пометка предмета спора, что в списке (Р-26). Пока приём идёт — «Поставить»: исход и сумма (`parseAmount`); предмету спора — только доступные исходы (`betOutcomes`): в событии «Да / Нет» — только «Да» с подсказкой, в событии со своими исходами — вместо формы «Вы — предмет спора: в событии со своими исходами вы не ставите» → окно подтверждения «Поставить 300 ₽ на „Да“? Если „Да“ выиграет, при нынешних ставках получите ≈ … (`payoutIfWins`) — до закрытия приёма это число ещё сдвинется» → «Поставить» / «Отмена» (Esc). Номер запроса ставки — по событию, исходу и сумме, хранится до принятой ставки (двойное нажатие и повтор после «нет связи» — одна ставка); принята — номер забыт, поле суммы очищено, следующая — снова с подтверждением. Нет связи или сервер отказал в состоянии — «Поставить» закрыта. «Ваша позиция» — мои ставки по исходам и выплата при каждом исходе по `settlePool` (строка с моим номером); отменено — возврат из `refunds`. Исход утверждён (`outcome.approved`, событие не отменено) — вместо прикидки одна строка итога из моей строки `outcome.payouts`: «Утверждён „Да“: вы поставили 300 ₽, получите 900 ₽ — итог +600 ₽» (`staked`, `payout`, `net`; итог — тем же видом и цветом, что «Итог» в «Выплатах»); ставил на несколько исходов — ниже мелко «ваши ставки: „Да“ …, „Нет“ …»; «без игры» (`outcome.void`) — «Без игры — вам вернётся N» (`payout`); окончательно (`status: 'final'`) — «получили» / «вернулось»; не ставил — «Вы не ставили.». Над лентой — «Вероятность по ставкам» (`ChanceChart`): с двух ставок — график, точки — `chanceHistory(номера исходов, ставки)`, на экране не пересчитываются; по горизонтали — от заведения события до сейчас по часам сервера, закрытия приёма или отмены (что раньше), по вертикали 0–100 %; ломаная на каждый исход своим цветом (`--series-1…7` в `styles.css`, по порядку исходов) с точкой на каждую ставку и нынешней вероятностью до конца оси; легенда — исход и нынешняя вероятность, переносится; проценты легенды и подписи ставки — `chancePercents` по точке (в сумме 100), высота линий — по сырым долям. Нажатие (на компьютере — наведение, с клавиатуры — стрелки) выбирает ближайшую по времени ставку: под графиком — время, кто, сколько на что и вероятности после неё. Рисунок — свой SVG (Р-12), новые ставки — опросом, без перезагрузки; ставок меньше двух — «График появится после второй ставки». «Лента ставок» — кто, сколько на что, когда, новые сверху. Автору — «Уточнить» (пока не отменено); «Отменить событие» — автору, пока приём идёт (причина по желанию), «Отменить» — ведущему после закрытия (причина обязательна); обе — с подтверждением. Исход — блок «Исход» под строкой статуса (ниже).
- **Исход** (`EventOutcome`, на экране события после закрытия приёма). Статус и выплаты — из `EventView.outcome` с сервера, сайт их не пересчитывает; кто какие кнопки видит — теми же правилами, что сервер (`mayPropose`, `hostDecides`, `betOn` с ведущим комнаты; голосующие — `outcome.voters`). Не предложен — «Исход ещё не предложен» и кто предлагает (ведущему — с какого мига сможет он, если автор молчит); кому `mayPropose` — выбор исхода и «Предложить исход» → окно «Предложить „Да“? Ставившие смогут согласиться или возразить в течение суток». Предложен — «Предложен исход „Да“ (кто, когда), возразить до <дата, время>» и «Согласны N из M ставивших: <кто>» (предложивший — согласен, если ставил; `agreements`, `awaiting`); ставившему, кроме предложившего, до `objectionUntil`, пока не утверждён и он не возражал и не соглашался, — «Возразить»: причина обязательна (`checkObjection`) → окно подтверждения; пока возражений нет — рядом «Согласен с исходом» → окно «Соглашаясь, вы отказываетесь возразить и подать апелляцию. Согласие не отозвать. Когда согласятся все ставившие, исход утвердится сразу и станет окончательным.» (Р-21); согласился — кнопок нет, «Вы согласны с исходом». Ниже — ход исхода: предложение, «Согласие: <кто>», «Все ставившие согласны — утверждён <дата, время>», «Возражение: <кто>, <причина>», решение ведущего, голосующие («проголосовали N из M», кто — да, кто — ещё нет; за что — не показывается). `disputed` — «Есть возражение — решает ведущий»; ведущему (`hostDecides`) — выбор и «Решить» → «Утвердить „Нет“ решением ведущего?». `voting` — «голосуют не ставившие, до <дата>»; голосующему, пока не голосовал и до `votingUntil`, — выбор и «Голосовать» → «Голосовать за „Да“?». `court` — «Ждёт суда» и почему (ничья, никто не голосовал, некому голосовать); суд — «Апелляция и суд на сайте» ниже. `approved` / `final` — сверху «Утверждён „Да“ — без возражений / ведущим (имя) / голосованием / все ставившие согласны», когда и «Окончательно <дата>, если до неё нет апелляции» или «Окончательно»; «Выплаты» — основание (банк, ставки на исход, коэффициент) и таблица «кто — поставил — получил — итог» по `payouts` (на телефоне — карточки, от 600 px — таблица); `void` — «Без игры: ставки возвращены» и почему. `cancelled` — «Событие отменено — исход не действует, выплат нет», был `approved` — «Был утверждён „Да“ до отмены»; таблицы нет (возврат — `refunds`, как в отмене). Каждое действие — с окном подтверждения, синхронным замком и номером запроса по событию, действию и выбору (`requestFor`; двойное нажатие и повтор после «нет связи» — одно действие, Р-13); отказ сервера и «Нет связи с сервером» — в окне, ничего не записано; нет связи при опросе — кнопки закрыты. Esc закрывает окно и форму возражения, не уводя с экрана. У других участников — опросом раз в 5 секунд.

**Пари на сайте** (этап 3, Р-04, Р-22; исход — Р-23). Те же опрос и часы сервера, что у событий (`useRoom`); пари — из ответа комнаты на устройство (`withState`, поле `offers`). Кто какие кнопки видит — правилами `offer.ts` (`checkAccept`, `checkWithdraw`, `checkCounter`), на пари из ответа (`offerState` в `offerParts`: условия, адресат, гарант, кто принял, отзыв, «закрыто встречным»); суммы — `offerStakes`, статус между опросами — `offerStatus` на часах сервера. Кнопок, которых правила не позволяют, нет; нет связи — кнопки закрыты.

- **«Пари» в комнате** (`OfferList`) — под «Событиями»: «Предложить пари»; «Открытые и принятые» (открытые — ближний «приём до» сверху, принятые — ближний «исход к»), ниже «Отозванные, истёкшие и закрытые встречным» (новые сверху). У каждого — условие, «встречное ·» у встречного, автор и кому (`открытое — любой`), суммы с основанием — «Аня ставит 300 ₽ на „сбудется“, соперник — 100 ₽ (кэф 3 к 1), банк 400 ₽» (себе — «вы ставите»; принято — имя принявшего вместо «соперник»), статус: «открыто — приём до …, осталось …» / «принято — ждём исхода к …» / «отозвано» / «истекло — приём закрыт …» / «закрыто встречным»; у принятого после «исход к» (или после первой отметки) — фаза исхода (`offerOutcome` на часах сервера): «принято — ждём отметок сторон» / «решает гарант — <имя>» / «нужен новый гарант» / «утверждено гарантом: +500 ₽ Вера, окончательно <дата>» / «окончательно: +100 ₽ Аня» (плюс выигравшего — `offerNets`); ждёт встречное — «встречное ждёт ответа автора»; предмет спора — сторона пари (автор или принявший) — пометка «⚑ Аня — предмет спора — сам на стороне „сбудется“» (Р-26, `OfferSubjectFlag`). Пусто — «Пари пока нет».
- **«Предложить пари»** (`#/room/<номер>/offer/new`, `NewOffer`): «Условие», «Как проверяем», «Ваша сторона» («Сбудется» / «Не сбудется»), кэф «a к b» — два поля «Вы рискуете» и «Соперник» (целые 1–100, по умолчанию 1 к 1), «Ваша сумма» (`parseAmount`), «Кому» («Открытое — любой» или участник), «Приём до» и «Исход к» (как у события: завтра к ровному часу и ещё сутки), «Гарант» — «Ведущий — <имя>» по умолчанию или участник не из сторон; ведущий — автор или адресат — выбора «Ведущий» нет, подсказка «Ведущий — сторона пари: выберите гаранта». «О ком спор» (Р-26) — «Ни о ком» по умолчанию или участник (и сам автор): предмет — вы — в «Вашей стороне» только «Сбудется»; предмет — адресат — только «Не сбудется», с подсказкой почему; предмет не бывает гарантом (его нет в выборе гаранта; ведущий — предмет — выбора «Ведущий» нет, «Ведущий — предмет спора: выберите гаранта»). Проверка — ещё `checkOfferSubject`; в окне подтверждения — «о ком спор — <имя>». Под формой по ходу ввода — «Вы ставите 300 ₽ на „сбудется“, соперник — 100 ₽ на „не сбудется“, банк 400 ₽ (кэф 3 к 1)» (`offerStakes`; не делится нацело — «сумма соперника — вниз до целой единицы»). Проверка до отправки — `checkOfferInput`, `offerGuarantor`, `checkOfferTimes` (часы сервера); «Предложить» → окно «Предложить пари?» с суммами, кому, гарантом и сроками → `POST /offers` с номером запроса (`requestFor`: та же форма — тот же номер) и синхронным замком; удалось — состояние комнаты заново и экран пари; отказ сервера — текстом под формой, введённое остаётся.
- **Пари** (`#/room/<номер>/offer/<номер пари>`, `OfferScreen`): условие, «Как проверяем», встречное — к какому пари (ссылкой); условия строками — автор и его сторона, кому (принято — соперник, его сторона и когда принято), кэф, суммы с основанием, гарант, «о ком спор — <имя> — только на стороне „сбудется“» (если задан, Р-26), «приём до», «исход к»; строка статуса; предмет — сторона — пометка, как в списке; предмету «Принять» и «Встречного» нет, пока автор за «сбудется», — вместо них «Вы — предмет спора: принять можно, только если автор — за «не сбудется»»; отозвано — когда; закрыто встречным — каким и когда. Встречное, пока открыто, — «Встречное ждёт ответа автора — <имя>» (автору — «ждёт вашего ответа»); ниже — «Встречные» к этому пари со своими суммами и статусом. Действия: «Принять» → окно «Вы ставите 100 ₽ против 300 ₽ — кэф 3 к 1, банк 400 ₽», сторона, гарант, «исход к», «Принятое пари не отзывается»; «Отозвать» → окно «Отозвать пари?»; «Встречное» — панель: кэф («Вы рискуете» и имя автора), своя сумма, «приём до» (сначала — те же условия со своей стороны: кэф наоборот, сумма — сумма соперника исходного, срок исходного), сумма по ходу ввода, проверка — `counterInput` + `checkOfferInput` + `checkOfferTimes` → окно «Предложить встречное?» → `POST …/counter` → экран нового пари. Номер запроса — по пари, действию и содержимому (повтор — то же действие, Р-13); отказ сервера и «Нет связи с сервером» — в окне. У принятого до «исход к» — «принято — ждём исхода к …», дальше — блок «Исход» (ниже). Рядом (от 1280 px) или ниже — «Пари» комнаты (`OfferList`), открытое отмечено рамкой.
- **Исход пари** (`OfferOutcome`, на экране принятого пари с «исход к» или с первой отметки). Ход исхода — из `OfferView.outcome`; `offerState` переносит его в состояние для правил (момент перехода к гаранту — `turnAt`, срок гаранта — `guarantorUntil`, отказ или пропуск — `needSince`, утверждено — `approved`), так что фаза между опросами — `offerOutcome` на часах сервера, а кнопки — `sideOf`, `checkMark`, `checkDecide`, `checkDecline`, `checkNominate`, как у сервера; итог сторон — `offerNets`. Сверху — фаза: «Ждём отметок сторон» (совпадут — окончательно сразу; разойдутся или одна промолчит до `turnAt` — решает гарант); «Решает гарант <имя> до <дата>» и почему (разошлись / одна сторона не отметила за 3 дня); «Нужен новый гарант» (гарант отказался <дата> / не решил до <дата>), кого называет каждая сторона; «Утверждено согласием сторон, окончательно»; «Утверждено гарантом <имя>, окончательно <дата>» (через 7 дней; после — «Окончательно»). Ниже — отметка каждой стороны («прав автор» / «прав соперник» / «ещё не отметил(а)»); утверждено — «Итог»: «Прав автор — Аня получает банк 400 ₽» и плюс / минус каждой стороны. Стороне — «Прав автор» / «Прав соперник» (своя отметка — подсказкой и нажатой кнопкой; поменять — до решения гаранта) → окно «Вы отмечаете: прав автор — Аня получает банк 400 ₽: Аня +100 ₽, Боря −100 ₽» и что дальше (другая сторона отметила так же — окончательно сразу и не обжалуется; не отметила — «если отметит так же…»; иначе — решает гарант). Гаранту — с перехода решения к нему «Прав автор» / «Прав соперник» → окно «Утвердить: …; окончательным станет через 7 дней», и «Отказаться» (пока правила позволяют) → «Отказаться быть гарантом?». Нужен новый гарант — стороне выбор участника не из сторон (сначала — кого назвала другая сторона) и «Назвать гарантом» → окно (назвала того же — сразу гарант). Не стороне и не гаранту — всё то же без кнопок. Окна — те же, что у «Принять»: номер запроса по пари, действию и выбору (Р-13), отказ сервера — текстом в окне у кнопки.

**Апелляция и суд на сайте** (этап 4, Р-05, Р-24, Р-25; #63). Блок `CourtBlock` — внутри «Исхода» события (`EventOutcome`) и пари (`OfferOutcome`). Кто что может — правила `appeal.ts` на часах сервера, без своих проверок: спор — событие из ответа (`eventState` в `courtParts`: предложение, возражения, согласия, решение ведущего, голоса; участники на миг возражения — голосующие из ответа) или пари (`offerState`; суд изменил решение гаранта — правилам отдаётся прежнее решение: прав был другой), дело суда — `courtCaseOf` (зерно, кандидаты в порядке жребия, миг жребия, ведущий; принятые записи — голоса мест и досрочные замены ведущим, замены по сроку `courtState` считает сам), кандидаты — нынешние участники комнаты (`courtRoomOf`). Места, сроки и решение — `courtState` / `courtVerdict` на часах сервера, между опросами тоже; исход пари со статусом в списке — `offerOutcome` с делом суда (`offerOutcomeOf`).

- **Окончательность.** Утверждён и не окончательный — «Окончательно <дата>, если до неё нет апелляции» (у пари — «Утверждено гарантом <имя>, окончательно <дата>»); подана апелляция — «Подана апелляция — окончательно, когда решит суд» (у пари в заголовке — «обжалуется в суде», в списке — «апелляция — решает суд»).
- **Апелляция.** Кому `checkAppeal` разрешает — «Подать апелляцию» → причина (`appealReason`, ≤ 300 знаков; Enter — отправить, Esc — закрыть) → окно «Апелляция одна на событие (пари). Суд: ведущий и 2 присяжных по жребию, 72 часа, решение окончательное» (состав — по `courtCandidates` на сейчас: ведущий заинтересован — «3 присяжных», кандидатов меньше трёх — «больше судить некому»), причина, «Апелляцию не отозвать». Некому судить (`NO_JUDGES`) — вместо кнопки «Апелляции нет: все участники заинтересованы». Подана — «Апелляция: <кто>, <когда>, причина: …», «Присоединились: …»; кому `checkJoin` разрешает — «Присоединиться» → окно. Окно «Согласен с исходом» у пула — «Соглашаясь, вы отказываетесь возразить и подать апелляцию».
- **Суд** (по апелляции или по «ждёт суда»; заголовок «Ждёт суда» и почему; суда нет — «Судить некому…»). Как собран и правила (72 часа на место, замена следующим по жребию, большинство поданных голосов); места карточками: имя (ведущий — «, ведущий»), голос и когда, или «ещё не голосовал(а) · до <дата>, осталось …», срок прошёл — «не голосовал(а)»; замена — «вместо <имя>: заменён(а) ведущим — <причина>» или «молчал(а) 72 ч», когда; пустое место — «запасные кончились». Мелко — кандидаты по порядку жребия, сколько в суде, зерно — «проверить может любой». До решения — «Голосов: N из M»; решил — «Решение суда: <вариант>, <когда>, голоса: 2 — изменить на „Нет“, 1 — оставить „Да“. Решение окончательное» (большинства нет — «исход остаётся» / отмена). Голоса видны сразу (Р-11).
- **Голос.** Члену суда на месте (`checkCourtVote`) — «Вы в суде: голос до <дата>, осталось …» и кнопки вариантов, которые правила разрешают: «Оставить „Да“» (у пари — «Оставить: прав автор»; только у апелляции), «Изменить на „Нет“» (исходы события; у пари — другая сторона), «Отменить — вернуть ставки» → окно с последствием и «Голос не изменить». «Оставить» — исход, утверждённый до суда.
- **Замена.** Ведущему, если он не заинтересован (`checkReplace`), — у не проголосовавшего «Заменить» → причина → окно «Место перейдёт следующему по жребию; одна замена на место», кто следующий (или «Запасных нет — место останется пустым»).
- **Решение в исходе.** «Изменить» — «Утверждён „Нет“ — судом» (у пари — «Утверждено судом: …, окончательно»), выплаты пула и итог пари — по новому исходу, как раньше; «оставить» — прежний исход, «Окончательно»; «отменить» — «Событие отменено судом — ставки возвращены» (в «Вашей позиции» — «Событие отменено судом — вам вернётся N» из `refunds`), у пари — «Пари отменено судом — ставки возвращены», без «Итога», в списке — «отменено судом — ставки возвращены».
- **«Вы в суде».** Член суда, который ещё не голосовал, а суд не решил (`awaitsMyVote`), — значок «вы в суде» у комнаты в «Моих комнатах» (по последней копии комнаты, `roomAwaitsMyVote`) и у события или пари в списках комнаты (ещё и срок места не прошёл по часам сервера). «Мои комнаты» при открытии один раз спрашивают `GET /rooms/<номер>` о каждой комнате без ответа сервера или с копией старше 5 минут (`syncedAt`), ответ — на устройство поверх записи (`withState`); не вышло — остаётся копия. Пушей нет.
- **Маленькая комната.** В «Новом событии» и «Предложить пари» при комнате меньше 4 участников — «В маленькой комнате суда может не хватить: судят только не ставившие».
- Действия — окнами экрана (номер запроса по спору, действию и выбору, Р-13; отказ сервера — в окне); нет связи — кнопки закрыты. Старый сайт с другой версией протокола — «Версия сайта и сервера разная — обновите страницу» (`VERSION_MISMATCH`), а не белый экран.

**Хранилище комнаты** (`RoomStorage`): `log:00000001…` — журнал, запись по ключу не меняется; `key:<SHA-256 ключа>` → номер участника или заявки (ключа в открытом виде нет; отвязанный помечен `unlinkedAt`); `invite` — токен приглашения; `secret` — секрет комнаты, заводится при первой заявке; `device:<SHA-256 токена>` → чья ссылка, `unlink`, `expiresAt`, `usedAt` / `revokedAt`. Номер комнаты и ключ ведущего выводятся из `requestId` и пароля компании (HMAC-SHA-256): повтор создания отдаёт тот же ключ, не храня его; `requestId` на сервере не хранится (Р-13). Так же ключ по заявке — HMAC секретом комнаты из `requestId` заявки: повтор заявки отдаёт тот же ключ.

**Ссылка-приглашение** (`src/rules/link.ts`): `https://goigolden88.github.io/Torg_Sin/#/join/<номер комнаты>/<токен invite>`; сервер не по умолчанию — `?server=<адрес>` в конце (адрес закодирован). Ссылку собирает ведущий из `invite`, который хранится у комнаты на его устройстве (`GET /rooms/<номер>` токен не отдаёт); «Пригласить» сервер не спрашивает — `POST /rooms/<номер>/invite` сменил бы ссылку. Комната создана на другом устройстве — `invite` нет, экран предлагает сменить ссылку. «Сменить ссылку» (ведущему, с подтверждением) — `POST /rooms/<номер>/invite`; новый `invite` записывается у комнаты вместо старого.

**Ссылка для другого устройства** (`src/rules/link.ts`): `…/Torg_Sin/#/device/<номер комнаты>/<токен>`, сервер — как у приглашения. Выдаёт «Ссылка для другого устройства» в комнате (`POST /device`): себе — любой участник; ведущий выбирает участника и, только за другого, флажок «Отвязать старый телефон» (`unlink`). Открыли ссылку — экран `ClaimDevice`: комната уже есть на устройстве — «Открыть», ссылка не тратится; нет — кнопка «Открыть комнату здесь» (не сама при открытии: просмотр ссылки в мессенджере её не истратит) → `POST /device/claim` → `GET /rooms/<номер>` → комната записывается с `invite: null`.

**Вход по ссылке на сайте** (`JoinRoom`): комната уже есть — открыть её; заявка уже подана (`joins`) — ожидание; иначе `POST /preview` → «Вход в комнату „<название>“, ведущий — <имя>», поле имени и «Попроситься» → `POST /join` с номером запроса (`requestFor`: та же форма — тот же номер, Р-13) → заявка записывается на устройство → «Ждём, пока ведущий впустит»: опрос `GET /rooms/<номер>` ключом заявки раз в 5 секунд, пока экран открыт и вкладка видна. 200 — комната записывается (`admitJoin`: комната и удаление заявки одной транзакцией) и открывается; `join: "rejected"` — «Ведущий отклонил заявку» (отметка — у заявки на устройстве) с «Попроситься снова»: `POST /preview` заново по ссылке, открытой сейчас (не по сохранённой в заявке: ведущий мог её сменить), → та же форма с прежним именем в поле, но с новым номером запроса (форма новая; прежний номер вернул бы ту же отклонённую заявку) → новая заявка записывается поверх отказа (`saveJoin`, та же запись `joins`). Ошибка — текст сервера («Такое имя уже есть — добавьте букву», «Ссылка недействительна…»), нет сети — «Нет связи с сервером»; введённое имя остаётся. Ведущему в открытой комнате — опрос `GET /requests` раз в 5 секунд; есть заявки — «Заявки (N)» с «Впустить» и «Отклонить»; впустил — состояние комнаты спрашивается заново. Сервер комнаты — из ссылки; «Настройки» не меняются.

**Вставить ссылку и экран «Домой»** (#56). На iPhone приложение с экрана «Домой» хранит данные отдельно от Safari, а адресной строки у него нет — комнату туда переносят ссылкой.

- **«Вставить ссылку»** (`PasteLink`) — в «Моих комнатах» под списком, пустым и непустым: поле и «Открыть» (Enter — тоже). Текст разбирает `parsePastedLink`: годится и сообщение целиком — берётся первое слово, разобравшееся как ссылка (кавычки и точка вокруг не мешают). Приглашение — переход на `#/join/…`, ссылка для другого устройства — на `#/device/…`, с `?server=` из ссылки (сервер не по умолчанию); дальше — те же экраны, что при открытии ссылки. Не ссылка — «Это не ссылка ТоргСина: нужна ссылка-приглашение или ссылка для другого устройства». Вставлено приглашение в комнату, которой на устройстве нет, — под полем, до «Открыть»: «Уже вошли в эту комнату в браузере? Тогда нужна не эта ссылка, а „Ссылка для другого устройства“ — иначе появится второй участник с тем же именем» (вошёл ли человек где-то ещё, устройство не знает — подсказка всем). Пустые «Мои комнаты» говорят и про «Вставить ссылку».
- **Заметка про экран «Домой»** (`HomeScreenNote`) — в комнате, под строкой «Валюта…», только на iPhone (`iPhone` / `iPod` в `navigator.userAgent`) и не с экрана «Домой» (`navigator.standalone` и `display-mode: standalone` — нет): «Поставите ТоргСин на экран „Домой“ — там комнаты не будет…». Кнопка «Скопировать ссылку для приложения» — `POST /device` себе (как «Ссылка для другого устройства»: одноразовая, на сутки) и копирование: запись в буфер начинается сразу по нажатию и ждёт ссылку (`ClipboardItem` с обещанием — иначе Safari не пускает в буфер после запроса к серверу), где так нельзя — `writeText`; ниже — ссылка (`LinkBox`) и до какого времени сработает; не скопировалось — «скопируйте её кнопкой ниже». «Закрыть» — заметки больше нет на этом устройстве ни в одной комнате (localStorage `torgsin.homeNoteClosed`).

**На устройстве.** IndexedDB `torgsin` (`src/store/db.ts`), версия 2 (шаг 1 → 2 только добавляет хранилище `joins`, комнаты не трогает). Хранилище `joins` по `roomId` — поданная, но не впущенная заявка (`SavedJoin`): `roomId`, `server` (из ссылки), `invite`, `name`, `memberId` (номер заявки), `key` (ключ заявки), `roomName`, `hostName` (что показала ссылка), `status` (`waiting` / `rejected`), `savedAt`; впустили — заявка становится комнатой и убирается. Хранилище `rooms` по `id` — своя комната (`SavedRoom`): `id`, `server` (адрес сервера комнаты: запоминается у комнаты, «Настройки» его не меняют), `memberId`, `key` (ключ телефона), `invite` (или `null`), последнее известное с сервера — `name`, `currency`, `hostId`, `createdAt`, `members` (`{ id, name }`), `events` (`EventView[]` из ответа; поле добавлено без смены версии базы — у старых записей его нет, это «событий нет» до первого ответа сервера, Р-18; копия читается через проверку протокола `isEventView` — событие, записанное до нового поля протокола, экраны не получают: событие — «Загружаю…» до ответа сервера, в списке его нет; хранимое при этом не переписывается, ответ сервера ложится поверх), `offers` (`OfferView[]` из ответа — тем же путём: поле добавлено без смены версии базы, у старых записей его нет — «пари нет» до первого ответа сервера; сервер без `offers` — пусто; копия читается через `isOfferView` (`savedOffers`) — пари, записанное до нового поля протокола, экраны не получают: пари — «Загружаю…» до ответа сервера, в списке его нет), и `savedAt` (порядок в «Моих комнатах», новые сверху), `syncedAt` (последний ответ сервера; `null` — не было). Открытая комната и событие — состояние с сервера раз в 5 секунд, записывается поверх; нет связи — показано последнее известное. Пароль компании — настройка устройства: localStorage `torgsin.password`, запоминается после удачного создания, стирается в «Настройках». Создание: форма → номер запроса (`requestFor`: та же форма — тот же номер) → `POST /rooms` → `GET /rooms/<номер>` → запись на устройство; кнопка «Создать» на время запроса закрыта (Р-13).

Сайт: `base` сборки `/Torg_Sin/`, адрес `https://goigolden88.github.io/Torg_Sin/`. Сервер: Worker `torg-sin`, адрес `https://torg-sin.goigolden88.workers.dev/`.

## Модель (черновик)

Все записи — с `id` (ULID), автором (`memberId`), временем сервера (`at`, UTC, мс). Суммы — целыми в минимальных единицах валюты комнаты. Итоги, коэффициенты, долги — считаются, не хранятся.

**Журнал комнаты только дописывается** (Р-11): ничего не стирается и не переписывается; отмена, уточнение, исправление — новая запись со ссылкой на прежнюю. Из журнала считаются текущее состояние и экран «История».

- `Room` — название, валюта, ведущий, ссылка-приглашение (меняется), создана, закрыта. В коде (`RoomState`): `id`, `name`, `currency`, `hostId`, `createdAt`, `members`; приглашение — не в журнале, отдельной записью хранилища.
- `Member` — номер (не привязан к способу входа), имя, ключи телефонов, впущен кем и когда, выбыл. В коде: `id`, `name`, `addedBy`, `addedAt`; ключи — только хешами в хранилище сервера, не в журнале.
- **Записи журнала** (`LogEntry`, этап 1): `room.created` (`roomId`, `name`, `currency`; автор — ведущий), `member.added` (`member`, `name`; автор — кто впустил, ведущего при создании — он сам; впущен по заявке — `member` равен номеру заявки), `join.requested` (`request`, `name`; автор — сама заявка), `join.rejected` (`request`; автор — ведущий), `invite.changed` (автор — ведущий; токена нет), `device.issued` (`member`, `unlink`, `expiresAt`; автор — он сам или ведущий; токена нет), `device.linked` (`member`, `unlink`; автор — участник). Состояние — `foldLog` по порядку записей; заявки — `joinRequests` (ждёт, впущена, отклонена; решение — первое).
- **Записи журнала событий** (этап 2): `event.created` (`condition`, `check`, `outcomes: [{ id, title }]` — полным списком, со «Другое», если исходы свои, `closesAt`, `expectedAt`, `subject` — номер участника или `null`, `subjectRule: 1` — признак правила предмета, только у событий с предметом, заведённых после выкатки Р-26 (у старых поля нет), `requestId`; автор — кто завёл; номер события — `id` записи), `bet.placed` (`event`, `outcome`, `amount`, `requestId`; автор — кто поставил; у события с признаком ставка предмета не по правилу Р-26 не действует), `event.clarified` (`event`, `text`; автор — автор события), `event.cancelled` (`event`, `reason` или `null`; автор — кто отменил). `requestId` — номер запроса телефона, не секрет: по нему узнаётся повтор (Р-13). События — `roomEvents` (`src/rules/event.ts`) по порядку записей; записи о неизвестном событии не действуют; отмена — первая; статус — из журнала и времени сервера, не хранится.
- **Записи журнала исхода** (этап 2, Р-17): `outcome.proposed` (`event`, `outcome`, `requestId`; автор — кто предложил), `outcome.objected` (`event`, `reason`, `requestId`; автор — кто возразил), `outcome.agreed` (`event`, `requestId`; автор — кто согласился; Р-21), `outcome.decided` (`event`, `outcome`, `requestId`; автор — ведущий), `outcome.voted` (`event`, `outcome`, `requestId`; автор — голосующий). В `roomEvents`: предложение и решение — первые; возражение, согласие и голос — первые от участника; возражение без предложения или от согласившегося, согласие без предложения или после первого возражения, решение и голос без возражения не действуют; согласие не ставившего, предложившего или после суток не считается (`eventOutcome`). «Утверждён», «ждёт суда», «окончательный» не записываются — считаются (`eventOutcome`).
- **Записи журнала пари** (этап 3, Р-22): `offer.created` (`condition`, `check`, `side`, `odds: { a, b }`, `amount` — сумма автора, `to` — адресат или `null`, `closesAt`, `expectedAt`, `guarantor` — уже определённый гарант, `counterTo` — встречное к какому пари или `null`, `subject` — о ком спор, только если задан (Р-26; у пари до выкатки и «ни о ком» поля нет — само поле и есть признак правила), `requestId`; автор — кто предложил; номер пари — `id` записи), `offer.accepted` (`offer`, `requestId`; автор — принявший), `offer.revoked` (`offer`, `requestId`; автор — автор пари); исход (Р-23): `offer.marked` (`offer`, `winner` — `author` / `taker`, `requestId`; автор — сторона), `offer.decided` (`offer`, `winner`, `requestId`; автор — гарант), `offer.declined` (`offer`, `requestId`; автор — гарант), `offer.nominated` (`offer`, `guarantor`, `requestId`; автор — сторона). Сумма соперника, статус, фаза исхода и нынешний гарант не записываются — считаются. Пари — `logOffers` (`src/rules/offer.ts`): записи журнала → записи правил (`offer.revoked` журнала — `offer.withdrawn` правил) → `roomOffers` с ведущим и участниками из журнала.
- **Записи журнала апелляции и суда** (этап 4, Р-25): `appeal.filed` (`target` — событие или пари, `reason`, `seed`, `candidates`, `requestId`; автор — подавший), `appeal.joined` (`target`, `requestId`; автор — присоединившийся), `court.drawn` (`target`, `seed`, `candidates`; суд по «ждёт суда», дописывает сам сервер; автор — ведущий комнаты, не проверяется; номера запроса нет), `court.voted` (`target`, `verdict` и `outcome` / `winner`, `requestId`; автор — член суда), `court.replaced` (`target`, `member`, `reason`, `requestId`; автор — ведущий). Порядок жребия, места, решение и окончательность не записываются — считаются. Дела суда — `logAppeals` (`src/rules/appeal.ts`): записи журнала → записи правил (`appealRecord`, без `requestId`) → `roomAppeals` с событиями, пари, ведущим и участниками (с мигом входа) из журнала.
- `Event` (пул) — условие, «как проверяем», исходы (2+; свои — с «Другое» последним, Р-16), приём ставок до, исход ожидается к, автор, предмет (участник, если спор о нём), действует ли правило предмета (Р-26); уточнения автора, отмена. В коде: записи `event.*` журнала, `EventState` / `EventView` (`src/rules/event.ts`, `protocol.ts`; `subjectId`, `subjectRule`).
- `Bet` — событие, участник, исход, сумма. Отменить нельзя, добавить можно.
- `Offer` (пари) — условие, «как проверяем», сторона автора, кэф `a:b`, сумма автора, адресат или открытое, приём до, исход к, гарант, о ком спор (необязательно, Р-26); принято кем, отозвано, встречное к какому. В коде: `OfferState.subject`, в ответе — `OfferInfo.subjectId` (`null` — ни о ком).
- `Outcome` — предложено кем и что, отметки сторон пари, возражения, утверждено кем (автор, ведущий, голосование, гарант, согласие сторон), когда; окончательно с. У пула в коде: записи `outcome.*` журнала, `OutcomeView` (`protocol.ts`, `eventOutcome` в `event.ts`).
- `Appeal` — кто, причина, присоединившиеся; суд (состав, жребий — зерно и список кандидатов), голоса, решение. В коде (этап 4, Р-24): записи правил `AppealRecord` (`appeal.filed`, `appeal.joined`, `court.drawn`, `court.voted`, `court.replaced`; в журнал комнаты — задача сервера), дело суда `CourtCase` (`src/rules/court.ts`), в ответе — `appeal` / `court` у исхода пула и пари (`AppealView`, `CourtView` в `protocol.ts`); правила — раздел «Правила апелляции в коде».
- `Transfer` — расчёт: кто кому, сколько; отметка «получил».
- **Валюты** — таблица в коде: код, знаков после запятой, знак, название для выбора (`RUB 2 ₽ рубли`, `USD 2 $ доллары`, `EUR 2 € евро`, `USDT 2`, `BTC 8 ₿ биткоины`, `PTS 0 очки`, при числе — «очко / очка / очков»); новая валюта — строка таблицы (Р-07).

## Правила

- **Пул.** Банк события — все ставки; победители делят его пропорционально своим ставкам на исход; остаток единиц — по порядку ставок. Коэффициент исхода = банк ÷ ставки на исход; «вероятность по ставкам» = ставки на исход ÷ банк.
- **Пари.** Автор рискует `a·k`, соперник `b·k`; победитель забирает оба. «3 к 1, сумма автора 300» → соперник ставит 100.
- **Исход пула.** Автор предлагает (молчит 3 дня после срока — ведущий) → сутки на возражение → утверждён; до возражения согласились все ставившие (предложивший — согласен; Р-21) — утверждён и окончательный сразу, кроме предложившего никто не ставил — в миг предложения; возражение → ведущий; ведущий ставил → голосуют не ставившие (большинство; ничья — суд сразу). Голосование — в этапе 2 (Р-17): не ставившие и не предмет спора, 72 часа или пока не проголосуют все, большинство поданных; ничья или некому голосовать — «ждёт суда» до этапа 4.
- **Исход пари** (Р-05, Р-06). Каждая сторона отмечает исход с подтверждением. Совпало — утверждён без гаранта и окончательный сразу. Разошлось или одна молчит 3 дня — решает гарант; пока он не решил, сторона может поменять отметку. Гарант молчит 3 дня или отказался → стороны выбирают другого (ведущий — по умолчанию, если не сторона).
- **Апелляция.** 7 дней после утверждения; подаёт ставивший (у пари — сторона) с причиной; одна на событие, другие присоединяются. Суд — ведущий + 2 присяжных жребием из незаинтересованных (не ставили, не стороны, не гарант, не автор и не предмет события, не апеллянт); 72 часа; 2 из 3; голос — «оставить» / «изменить на …» / «отменить событие — вернуть ставки»; решение окончательное.
- **Окончательность.** Событие окончательно, когда прошла неделя без апелляции, суд решил, все ставившие в пуле согласились с исходом (Р-21) или стороны пари согласились; только окончательные идут в «Расчёт».
- **Расчёт.** Итог каждого по окончательным событиям и пари → минимум переводов (жадно, от большего долга к большему выигрышу) → получатель отмечает «получил».
- **История** (Р-11). Экран «История» комнаты: прошедшие события и пари — исход, кто сколько ставил, возражения, апелляции, жребий; итог каждого по времени. Закрытая комната остаётся в «Моих комнатах» только для чтения.

## Крайние случаи и как решаются

| Случай | Как решается |
|---|---|
| На выигравший исход никто не ставил; ставки только на один исход | Событие — «без игры»: все ставки возвращаются |
| Ставка после того, как исход стал известен | Приём закрывается в срок автора (ставится до события), по времени сервера; поздняя ставка «на известное» — основание апелляции, суд может отменить событие |
| Условие неясное, спорят о смысле | Шаблон «Условие / Как проверяем / Срок»; после первой ставки текст не меняется — только уточнения, видные всем; поменять по сути — отменить событие и завести заново |
| Спор о самом участнике («я подтянусь 50 раз») | Предмет спора ставит только на «сбудется» (Р-26): в событии «Да / Нет» — только на «Да», в событии со своими исходами — не ставит; у пари — необязательное «о ком спор», предмет только на стороне «сбудется» (автор-предмет — сторона «сбудется»; другой участник принимает, только если автор — за «не сбудется»). Его ставка видна всем пометкой «⚑ <имя> — предмет спора — сам ставит: 300 ₽ на „Да“» (у пари — «сам на стороне „сбудется“»); у старых событий, где он поставил на «Нет», — «поставил против себя». Правило — только у событий и пари, заведённых после выкатки (признак в записи), старые свёртываются как раньше. Предмет не объявляет исход, не гарант и не присяжный. Событие ведущего о себе — исход предлагает любой другой участник, первый (Р-19) |
| Доказательство (видео, фото) | В первой версии — ссылка или текст; вложения на сервере — позже |
| Отменить событие | До закрытия приёма — автор, ставки возвращаются; после — только ведущий или гарант с причиной, и это обжалуется. Отменено и после утверждения исхода — исход «отменено», выплат нет, окончательным не станет (Р-19) |
| Отменить свою ставку | Нельзя (иначе крупная ставка и отмена двигают коэффициенты); можно добавить. Пари — отзыв, пока не принято |
| Нажал «Поставить» дважды | Ставка — с подтверждением суммы; повтор того же действия с тем же номером сервер не примет дважды |
| Обе стороны пари ошибочно отметили один исход | Отметка — с подтверждением; совпадение окончательно сразу (Р-06) |
| Ведущий — сторона или ставил | Не решает возражение и не сидит в суде за ведущего: третий присяжный — жребием |
| Сговор ведущего и друга | Присяжных выбирает жребий сервера; кандидаты и выпавшие видны всем в истории события |
| Присяжный не голосует | Через 72 часа — одна замена жребием; дальше решают проголосовавшие; ничья — исход остаётся |
| Незаинтересованных меньше трёх | Суд из тех, кто есть; ни одного — апелляции нет; экран предупреждает при создании события |
| Апелляция после «Расчёта» | Невозможна по устройству: в расчёт идут только окончательные события |
| Участник пропал с долгом | Долг остаётся в расчёте; выйти из комнаты — только без открытых ставок и с отмеченными переводами; ведущий может пометить «выбыл» — открытые ставки доигрываются |
| Ведущий пропал | 7 дней без входа — любой участник может взять ведение, все видят |
| Потерял телефон | «Ссылка для другого устройства»; без неё — ведущий привязывает к новому телефону, старый отвязывается |
| Ссылка утекла | Новичка впускает ведущий; ссылку можно сменить — старая перестаёт работать |
| Сервер лежал в момент срока | Приём закрывается по времени сервера: ставка с меткой позже срока отклоняется; будильник срабатывает, когда сервер поднялся |
| Часовые пояса | Время хранится в UTC, показывается местное |
| Разные валюты у друзей | Одна валюта на комнату; другая валюта — другая комната |
| Закрыть или удалить комнату | По умолчанию — «закрыть»: только чтение, история остаётся (Р-11). Удалить — только ведущий, только когда всё окончательно и переводы отмечены; перед удалением у всех — копия |

## Правила пари в коде

`src/rules/offer.ts` (этап 3; записи журнала и адреса сервера предложить / принять / отозвать / встречное — Р-22, исход — Р-23, выше; экраны — следующие задачи этапа). Вход — записи `OfferRecord` (из журнала их собирает `logOffers`; `offer.revoked` журнала — это `offer.withdrawn`, записи исхода — те же, что в правилах): `memberId` — автор записи, `at` — время сервера, порядок — журнала; номер пари — `id` записи `offer.created`. Статусы и итоги считаются, не хранятся.

- **Суммы** (`offerStakes`). Кэф `a к b` — целые 1…100; сумма автора — целое > 0. Соперник ставит сумма × b ÷ a вниз до целой единицы (`BigInt`; «3 к 1», 300 → 100; 100 очков → 33, `exact: false`); меньше единицы — «Сумма соперника меньше одной единицы — увеличьте сумму или кэф»; банк — обе суммы. Итоги (`offerNets`): прав автор — автор +сумма соперника, соперник −она; прав соперник — автор −своя сумма, соперник +она.
- **Форма** (`checkOfferInput`): условие и «как проверяем» — как у события (не пустые, ≤ 300 знаков); `side` — сторона автора `yes` («сбудется», по умолчанию) / `no`; `to` — адресат или `null` (открытое); `closesAt` «приём до» (не включая) — в будущем, `expectedAt` «исход к» — не раньше (`checkOfferTimes`, по времени сервера). Гарант (`offerGuarantor`): выбранный — участник, не автор и не адресат; не выбран — ведущий; ведущий — автор или адресат — «Ведущий — сторона пари: выберите гаранта». В записи `offer.created` гарант уже определён.
- **О ком спор** (Р-26; `subject` — участник или `null`, `checkOfferInput`, `checkOfferSubject`): предмет — участник комнаты; предмет — автор — сторона автора только `yes` («Вы — предмет спора: ваша сторона — только «сбудется»»); предмет — адресат — сторона автора только `no` («Предмет спора примет пари, только если ваша сторона — «не сбудется»»). Гарант (`offerGuarantor` с `subject`) — не предмет («Предмет спора не бывает гарантом…»); ведущий — предмет и гарант не выбран — «Ведущий — предмет спора: выберите гаранта». Принять (`checkAccept`) и встречное (`checkCounter`, через ту же проверку) предмету — только если автор за `no` («Вы — предмет спора: принять можно, только если автор — за «не сбудется»»); встречное переносит `subject` (`counterInput`). Пометка для всех (`subjectIsSide`): предмет — сторона пари.
- **Статус** (`offerStatus` на `now`): `accepted` → `withdrawn` → `countered` (закрыто встречным) → `expired` (`now ≥ closesAt`) → `open`.
- **Принять** (`offer.accepted`, `checkAccept`): до `closesAt`; адресное — только адресат, открытое — любой участник, кроме автора и гаранта; второй раз — «Пари уже принято». **Отозвать** (`offer.withdrawn`, `checkWithdraw`) — автор, пока не принято и не закрыто встречным.
- **Встречное** — новое `offer.created` с `counterTo` (`counterInput`): свои кэф, сумма и «приём до»; условие, «как проверяем», «исход к» — исходного; сторона — обратная; адресат — автор исходного; гарант — тот же. Делает тот, кто мог бы принять исходное (`checkCounter`): к принятому, отозванному, закрытому, истёкшему или своему — отказ. Автор принял встречное — исходное `closedBy` («закрыто встречным»), если его ещё можно было принять; уже принятое другим остаётся принятым.
- **Исход** (Р-05, Р-06). Отметка стороны `offer.marked` (`winner`: `author` — прав автор, `taker` — прав соперник; `checkMark`) — после принятия, только стороны (гарант — «Гарант не отмечает исход как сторона…»); действует последняя, повтор той же ничего не меняет. Отметки совпали (и после того, как расходились) до решения гаранта — `agreed`, утверждён согласием и окончательный сразу. Решает гарант (`guarantorTurn`) с мига, как отметки впервые разошлись, или через 3 дня (`SIDE_SILENCE`) после `expectedAt` или первой отметки, что позже (никто не отметил — после `expectedAt`). Решение `offer.decided` (`checkDecide`) — только нынешний гарант, в свои 3 дня (`GUARANTOR_SILENCE`, с перехода решения к нему или с назначения, что позже); окончательный через 7 дней (`FINAL_TIME`; апелляция — этап 4). Гарант молчит 3 дня или отказался (`offer.declined`, `checkDecline`) — «нужен другой гарант»: каждая сторона называет участника не из сторон (`offer.nominated`, `checkNominate`; действует последнее), назвали одного — он гарант (`guarantorSince`), отсчёт 3 дней — заново.
- **Ответ** (`offerOutcome` на `now`; не принято — `null`): `phase` — `marking` / `guarantor` / `need-guarantor` / `approved` / `final`, `marks` (последняя отметка каждой стороны), `guarantorId`, `turnAt`, `guarantorUntil`, `needSince`, `nominations`, `approved` (`{ winner, at, how: 'agreement' | 'guarantor', by }`), `finalAt`. Итог для «Расчёта» (`offerResult`) — только окончательное: `[{ memberId, net }]` автора и соперника. С апелляцией (Р-24) — ещё `how: 'court'`, фаза `cancelled` и поля `appeal` / `court`: раздел «Правила апелляции в коде».
- **Свёртка** (`roomOffers(records, { hostId, members })`): запись действует, если её разрешает та же проверка на её время `at` — сервер и свёртка не расходятся; записи о неизвестном пари не действуют.

## Правила апелляции в коде

`src/rules/appeal.ts` — кто подаёт, кто судит, проверки и свёртка; `src/rules/court.ts` — жребий, места, решение (отдельно, чтобы `event.ts` и `offer.ts` не зависели от `appeal.ts`). Этап 4, Р-05, Р-24; записи в журнале комнаты и адреса — Р-25 («Апелляция и суд» в адресах и «Записи журнала апелляции и суда» в модели), экраны — следующая задача этапа. Вход — записи `AppealRecord` (`memberId` — автор, `at` — время сервера, `target` — событие или пари, порядок — журнала); будильника нет — всё считается на `now`. Длины текстов — как у события (≤ 300 знаков, пробелы по краям срезаются).

- **Записи.** `appeal.filed` (`target`, `reason`, `seed`, `candidates`; автор — подавший; суд собран в этот миг), `appeal.joined` (`target`; автор — присоединившийся), `court.drawn` (`target`, `seed`, `candidates`; суд по «ждёт суда» без апелляции; автор не проверяется), `court.voted` (`target`, `verdict`: `keep` / `change` с `outcome` (пул) или `winner` (пари) / `cancel`; автор — член суда), `court.replaced` (`target`, `member`, `reason`; автор — ведущий).
- **Подать** (`checkAppeal`): исход утверждён и ещё не окончательный (7 дней с утверждения, `FINAL_TIME`); утверждён согласием (у пула — всех ставивших, Р-21, у пари — сторон) — «Исход утверждён согласием — он окончательный, апелляции нет»; у пула подаёт ставивший, кроме согласившихся (`outcome.agreed`), у пари — сторона; причина — не пустая; одна на событие или пари — вторая: «Апелляция уже подана — присоединитесь к ней»; событие отменено — нет; «ждёт суда» — нет (суд и так собирается); кандидатов 0 — «В комнате некому судить: все участники заинтересованы».
- **Присоединиться** (`checkJoin`): тот, кто мог бы подать, кроме подавшего; один раз; до решения суда (и после 7 дней, если суд не решил).
- **Кандидаты** (`courtCandidates(target, { hostId, members: [{ id, addedAt }] }, at)`): участники, впущенные к мигу жребия, кроме заинтересованных — у пула: ставившие, автор, предмет спора, ведущий, решивший возражение (`outcome.decided`); у пари: стороны и нынешний гарант; и кроме подавшего и присоединившихся. Голосовавшие по возражению (Р-17) — кандидаты. В записи — тем же списком (порядок не важен, `checkDraw`); зерно — hex.
- **Жребий** (`drawCourt(seed, candidates, hostId)`): каждому кандидату — число `courtHash(seed + ':' + номер)`: 32-битный FNV-1a по кодам знаков строки (начало `0x811c9dc5`, для каждого знака: `h ^= код`, `h = h × 0x01000193` по модулю 2³²), затем перемешивание fmix32 из MurmurHash3 (`h ^= h >>> 16; h ×= 0x85ebca6b; h ^= h >>> 13; h ×= 0xc2b2ae35; h ^= h >>> 16`, умножения по модулю 2³²). Порядок — по возрастанию числа, равные — по номеру; ведущий, если он кандидат, — первым. Первые три — суд (ведущий + 2 или 3 присяжных), дальше — запасные по порядку; кандидатов меньше — суд из тех, кто есть.
- **Места** (`courtState` на `now`): у места — 72 часа (`SEAT_TIME`) с жребия. Член суда (и ведущий) не проголосовал за 72 часа — место переходит к следующему запасному, у него свои 72 часа с этого мига; замена одна на место: заменивший молчит — срок места прошёл. Досрочно (`checkReplace`) — только ведущий, если он сам кандидат (не заинтересован): не проголосовавшего, не себя, с причиной, одна замена на место, до решения. Запасные кончились — место пустое. Замены по сроку идут по времени, равные — по номеру места; запись — после замен по срокам на её время.
- **Голос** (`checkCourtVote`): только член суда на своём месте в свои 72 часа, один раз, не меняется; `keep` — только у апелляции (исход утверждён); `change` — у пула другой исход события, у пари — другая сторона; `cancel` — всегда. Голоса — в ответе сразу (Р-11).
- **Решение** (`courtVerdict`): суд кончился, когда все места проголосовали или их сроки прошли (пустое место — сразу); миг решения — последний из них. Побеждает вариант строгого большинства поданных голосов (3 голоса — 2; один — он); большинства нет (`majority: false`) — у апелляции «оставить», у «ждёт суда» — «отменить». Решение окончательное, второй апелляции нет.
- **Окончательность** (`eventOutcome(e, now, court)`, `offerOutcome(o, now, court)`; `court` — дело суда или `null`, без него — как раньше). Апелляция подана до конца 7 дней — исход «утверждён», `finalAt: null`, пока суд не решил; «оставить» — окончательный в миг решения с прежним исходом; «изменить» — `approved` с `how: 'court'`, `by: null`, окончательный сразу, выплаты пула и итог пари — по новому исходу; «отменить» — у пула статус `cancelled`, `payouts` пусты, возврат — `refunds` события (`eventRefunds(e, outcome)`), у пари — фаза `cancelled`, без выплат. «Ждёт суда» с судом: до решения — `court`; «изменить» — утверждён судом, окончательный; иначе — `cancelled` с возвратом. `offerResult` и выплаты пула — только по окончательному.
- **Ответ** (`appeal` и `court` у `OutcomeView` и `OfferOutcomeView`): `appeal` — `{ id, at, by, reason, joined: [{ id, at, by }] }` или `null` (суд по «ждёт суда»); `court` — `{ seed, drawnAt, candidates` (порядок жребия)`, seats: [{ member, since, until, replaced: { member, at, by, reason } | null, vote }], decision: { at, majority, verdict, … } | null }`. Суда нет — полей нет (ответ как до этапа 4; всегда — с подъёмом версии протокола, задача сервера).
- **Свёртка** (`roomAppeals(records, { events, offers }, room)` → дела `CourtCase`; `caseOf` — дело по цели): запись действует, если её разрешает та же проверка на её время `at` (`checkAppeal` + `checkDraw`, `checkCourtDraw` + `checkDraw`, `checkJoin`, `checkCourtVote`, `checkReplace`); исход цели — по уже собранному событию или пари; записи о неизвестной цели не действуют.

## Вёрстка (Р-10)

Одна страница на все экраны, «сначала телефон»: базовые правила CSS — для узкого экрана, шире — через `min-width`.

- **до 600 px** — телефон: одна колонка, вкладки снизу (`.nav` внизу), открытое — отдельным экраном;
- **600–1023 px** — планшет: то же, поля шире;
- **от 1024 px** — компьютер: меню слева (`.nav` колонкой); область содержимого (`.main`) — от краёв окна: ширина окна минус меню минус поля 2 rem, не шире `--content-max` (100 rem ≈ 1600 px), на мониторе шире — по центру, по краям пусто поровну (Р-20; заменяет «≤ 720 px» Р-10). «Список + открытое» (`.split`) — рядом: список ≈ 340 px (`--list-w`), открытое — всё остальное место области;
- **от 1280 px** — событие и «Новое событие», пари и «Предложить пари» — в две колонки (ниже).

Меню слева на компьютере сворачивается до значков: кнопка ««»/«»» вверху меню (`.nav-toggle`, `aria-label` «Свернуть меню» / «Развернуть меню»), у `.app` — класс `.nav-collapsed`; подписи (`.nav-label`) скрыты, у значка — всплывающая подпись (`title`) и `aria-label`. Положение — настройка устройства (localStorage `torgsin.navCollapsed`, `getNavCollapsed` / `setNavCollapsed` в `src/settings.ts`), по умолчанию развёрнуто. Ниже 1024 px кнопки нет, класс ни на что не влияет.

Комната на компьютере (`.room`): заголовок, «Валюта · создана», заявки, кнопки и участники — колонкой с одним отступом; участники (`.members`) — список в рамке со строками-разделителями. На телефоне и планшете — как было.

«Мои комнаты» (`.rooms`): список (`.list`) и открытое (`.detail` — комната или форма создания). На телефоне и планшете открыто что-то — класс `.open`, виден только `.detail` с «Назад» (`.back`); ничего — только список. От 1024 px видны оба, «Назад» скрыт.

Событие и новое событие (`.rooms.wide`) — на любой ширине без списка комнат: открытое во всю ширину области (Р-20), «Назад» виден и ведёт в комнату. Не ячейкой сетки: `.split` становится блоком. Рядом со списком на 1024–1279 px с развёрнутым меню событию досталось бы ≈ 360–610 px, а ему нужно не меньше ≈ 640 (#18). Экран события — две обёртки-колонки: `.event-main` (заголовок, «Как проверяем», уточнения, автор и сроки, статус, отмена, исход с выплатами, банк по исходам, «Поставить», «Уточнить» / «Отменить» с панелями, «Ваша позиция») и `.event-side` (график «Вероятность по ставкам» и «Лента ставок»); окно подтверждения ставки — вне колонок. До 1280 px они одна под другой (порядок блоков прежний), от 1280 px — сеткой рядом: ≈ 55 % / 45 %, зазор 2 rem, обе от верха, высота графика своя. «Новое событие» — две обёртки `.form-col` в форме: условие и «Как проверяем»; исходы, сроки и предмет спора; от 1280 px — рядом поровну, ошибка и кнопки — под обеими; порядок в разметке (и Tab) прежний. `npm run shots` проверяет событие и новое событие на 1024, 1280, 1440, 1536, 1920 и 2560 px, меню развёрнуто и свёрнуто: карточка — во всю ширину области, область не шире 1600 px, поля слева и справа равны, списка нет, «Назад» есть, условие, колонки, график и таблица выплат — внутри карточки; от 1280 px правая колонка справа от левой и от «Вашей позиции», её верх — не ниже середины левой, у события доля левой ≈ 55 %; уже — колонки одна под другой. Комнату — на 1280, 1440 и 2560 px: список 340 px, открытое — остаток области. Окно подтверждения ставки (`.modal`) — поверх экрана по центру, не шире 28rem. Лента ставок и позиция на телефоне — карточками, от 600 px — строками. График вероятности — во всю ширину карточки (SVG в рамке 0…100 тянется по контейнеру, толщина линий и точек — в пикселях экрана), высота — `clamp(9rem, 45vw, 15rem)`; подписи осей — текстом рядом с рисунком (слева 0 / 50 / 100 %, снизу только начало и конец времени — не налезают), подпись ставки — блоком под графиком, а не всплывающей.

Пари и «Предложить пари» — как событие (Р-20): `.rooms.wide`, без списка комнат, во всю ширину области, «Назад» ведёт в комнату. Экран пари — те же обёртки-колонки `.event-main` (само пари, действия, панель встречного, блок «Исход» в рамке `.outcome` — кнопки отметки и решения гаранта строкой с переносом `.outcome-act`, итог `.offer-result` с плюсом зелёным и минусом красным, выбор нового гаранта плитками `.chips`; «Встречные») и `.event-side` («Пари» комнаты, открытое — рамкой); до 1280 px — одна под другой, от 1280 px — рядом ≈ 55 % / 45 %. «Предложить пари» — две `.form-col`: условие, «Как проверяем», сторона, кэф, сумма; кому, сроки, гарант; строка сумм, ошибка и кнопки — под обеими. Кэф — два поля в строку с «к» между ними, делят ширину поровну (`.odds-edit`); строка сумм — блоком с золотой чертой слева (`.offer-summary`); условия пари (`.offer-facts`) на телефоне — подпись над значением, от 600 px — подпись колонкой слева. `npm run shots` проверяет экран пари: на 390 px — без прокрутки вбок, колонки одна под другой; на 1280 — рядом; исход пари в каждой фазе — так же, и кнопки исхода не ниже 44 px.

Апелляция и суд (`.court` в блоке «Исход», #63) — как исход (Р-20): в левой колонке события и пари. Подблоки «Апелляция» и «Суд» (`.court-box`) — под чертой; места суда (`.seats`) — карточками в одну колонку на телефоне, от 600 px — строкой с переносом (имя, голос или срок; замена и кнопка «Заменить» — с новой строки); кнопки голоса — строкой с переносом, не ниже 44 px; зерно жребия — мелко, переносится по знакам. Значок «вы в суде» (`.court-badge`) — рядом с названием комнаты, события или пари. `npm run shots` проверяет апелляцию и суд на 390 и 1280 px: без прокрутки вбок, кнопки не ниже 44 px.

Правила: действия — видимыми кнопками (на телефоне наведения мыши нет; `:hover` — только украшение); широкие таблицы на телефоне — карточками; кнопки и поля не ниже 44 px (`--tap`); на компьютере Enter отправляет форму, Esc закрывает окно; длинные строки переносятся (`overflow-wrap`). Каждый экран проверяется на 390 и 1280 px — снимки в PR; раскладка компьютера (меню развёрнуто и свёрнуто) — ещё и на 1920 px (`npm run shots`).

## Резерв сервера (Р-02)

1. **Код переносим:** правила — чистые функции над `RoomStorage`; Cloudflare — обёртка; запасная — Node + SQLite в `server/node/`, CI гоняет одни тесты на обеих (`roomsSuite`; `npm test` показывает каждый набор дважды). Запуск — `npm run server:node` (Vite собирает `server/node/main.ts` в `server/node/dist/main.js`, встроенные `node:sqlite` и `node:http`, Node 24): адрес `http://localhost:8787`, те же ответы, что у Worker'а. Переменные: `ROOM_PASSWORD` — пароль компании, `PORT` (8787), `HOST` (все адреса), `ROOMS_DB` — файл комнат (`server/node/data.sqlite`, в `.gitignore`). Будильник комнаты (`setAlarm`) хранится в файле; обработчик (`onAlarm`, как `alarm()` объекта `Room`) — пока пустой: сроков у комнат ещё нет. Типы — `server/node/tsconfig.json` с `@types/node` (Р-14), проверка — в `npm run server:check`.
2. **Данные в трёх местах:** сервер; журнал комнат на каждом телефоне участника («Файл-копия»); суточная выгрузка всех комнат (этап 6).
3. **Переезд:** сервер отдаёт и принимает комнату целиком (`export` / `import`, с паролем компании); адрес сервера — в «Настройках» и в ссылке комнаты.
4. **`docs/Резерв сервера.md`** — для человека: признаки беды и шаги переезда (этап 6).

## Выкатка

- **Сайт** — `deploy.yml`: пуш в `main` → сборка → GitHub Pages.
- **Сервер** — `server.yml`: пуш в `main` с правкой `server/`, `src/rules/` или зависимостей → тесты → `wrangler deploy` → проба `/health`. Ключи — секреты репо `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`; нет их — выкатка пропускается. Откат — Cloudflare → Workers → `torg-sin` → Deployments → Rollback.
- **Проверки PR** — `ci.yml`: `npm test`, `npm run build`, `npm run server:check`, `npm run server:build`.
