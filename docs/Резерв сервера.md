# Резерв сервера — памятка

Для человека: что делать, если сервер комнат ТоргСина пропал. Устройство резерва — `02-Архитектура.md`, «Резерв сервера» (Р-02).

## Где лежат комнаты

1. **На сервере** — `https://torg-sin.goigolden88.workers.dev/` (Cloudflare). Это главное место.
2. **В приватном репо `Torg_Sin_Data`** на GitHub — файл `rooms.json`: полные копии всех комнат. Сервер кладёт его сам каждую ночь, около 02:17 по Екатеринбургу, коммитом «Копия 21.11.2026, комнат: 3». Если за день в комнатах ничего не случилось, нового коммита нет — так и должно быть. Копия за любой прошлый день — в истории коммитов репо.
3. **На телефонах участников** — каждый телефон помнит свои комнаты.

Копия в `Torg_Sin_Data` не зависит от Cloudflare: пропадёт аккаунт Cloudflare — копия останется.

Ключи копии: токен GitHub (доступ только к `Torg_Sin_Data`, срок — год) лежит в KeePass и секретом `DATA_TOKEN` у Worker'а в панели Cloudflare; репо — секрет `DATA_REPO`. Срок токена — в `токены.md` Штаба; кончится — копия перестанет приходить, сервер при этом работает.

## Как понять, что беда

- У всех друзей, с разных телефонов и сетей, комнаты не открываются: «Нет связи с сервером» — час и дольше.
- «Настройки» → «Проверить связь» не проходит ни у кого.
- Пришло письмо от Cloudflare о блокировке или удалении аккаунта; в панель Cloudflare не войти.
- В `Torg_Sin_Data` давно нет коммитов «Копия …», хотя в комнатах ставили, — копия перестала приходить (чаще всего — кончился токен). Это ещё не беда, но чинить сразу: попросите сессию Штаба.

Сначала проверьте, не сбой ли это у самого Cloudflare (страница `cloudflarestatus.com`), — тогда подождите несколько часов. Переезжайте, если сервер не вернулся за сутки или аккаунта больше нет.

## Переезд на другой хостинг

Делает сессия Штаба по шагам, вы — подтверждаете. Нужен компьютер или сервер (VPS), который работает круглые сутки, и адрес на `https` — сайт по `http` к серверу не ходит.

1. **Запасной сервер.** На новой машине — Node 24, клон репо `Torg_Sin`, `npm ci`, затем `npm run server:node` с переменными: `ROOM_PASSWORD` — **тот же** пароль компании, `ROOMS_DB` — файл комнат, `PORT` — порт. Ещё `DATA_TOKEN` и `DATA_REPO` — тогда и новый сервер будет класть копию каждую ночь.
2. **Копия.** Скачать `rooms.json` из `Torg_Sin_Data` — последний коммит (или день до беды из истории коммитов).
3. **Загрузить каждую комнату** — `POST /rooms/<номер>/import` с паролем компании; тело — одна копия из массива. Для сессии — так (`jq` и `curl`):

   ```sh
   NEW=https://новый-адрес
   AUTH="Password $(printf %s "$ROOM_PASSWORD" | base64)"
   jq -c '.[]' rooms.json | while read -r room; do
     id=$(printf %s "$room" | jq -r .roomId)
     printf %s "$room" | curl -sS -X POST "$NEW/rooms/$id/import" -H "Authorization: $AUTH" -H 'Content-Type: application/json' --data-binary @-
     echo
   done
   ```

   Каждая комната отвечает `{ roomId, entries }` — сколько записей загружено. «Комната уже есть» — она уже загружена, повтор безопасен. Комната больше 1 МБ запасной сервер не примет — сказать сессии.
4. **Проверить:** `https://новый-адрес/health` отвечает; `GET /export` с паролем — столько же комнат, сколько в `rooms.json`.
5. **Новый адрес — у всех:** «Настройки» → «Сервер комнат» → новый адрес → «Сохранить» → «Проверить связь». Ключи телефонов в копии есть — на новом сервере они те же.

   **Важно:** «Настройки» меняют адрес только для **новых** комнат; уже открытые на телефоне комнаты помнят свой старый адрес, и перенести их на новый адрес сайт пока не умеет. Это нужно сделать отдельной задачей заранее, пока сервер жив, — попросите сессию Штаба её завести.

## Что сказать друзьям

> Сервер ТоргСина переехал. Все споры и ставки на месте — ничего не пропало. Откройте ТоргСин → «Настройки» → «Сервер комнат», вставьте новый адрес: <адрес>, нажмите «Сохранить» и «Проверить связь». Если что-то не открывается — напишите мне.

Пока сервер лежал, новых ставок и отметок не было: всё, что сделано до беды, — в копии за последнюю ночь. Сделанное в последний день до беды может не попасть в копию — сверьте с друзьями.

## Проба раз в месяц

Сессия Штаба раз в месяц проверяет, что копия годится: скачивает `rooms.json`, поднимает запасной сервер у себя на пустом файле, загружает все комнаты (шаг 3) и сверяет число комнат и одну комнату на выбор; заодно смотрит, что коммиты «Копия …» идут и до конца срока токена больше месяца. Что-то не так — задача на починку.
