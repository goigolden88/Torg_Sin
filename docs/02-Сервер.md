# Архитектура — сервер: адреса и хранилище

Часть документа устройства (`docs/02-Архитектура.md`, Р-28): запросы и ответы сервера комнат и его хранилище. Читать, когда задача трогает `server/`, `src/api.ts` или протокол; описание изменённого адреса — сюда (шаг 5 исполнителя). Модель, правила и крайние случаи — в `02-Архитектура.md`; экраны — в `02-Сайт.md`.

**Адреса сервера.** Ответ — JSON с `v` (версия протокола); отказ — `{ v, error }` с текстом для человека.

- `POST /rooms` — `{ password, name, currency, hostName, settleMode?, pace?, times?, requestId? }` → `{ roomId, invite, memberId, key }`. Пароль на сервере не задан — 503 «Создание комнат выключено»; пароль неверный или пустой — 403 «Неверный пароль компании»; форма с ошибкой — 400. `settleMode` — режим «кто кому» (Р-32, Р-33): `stakes` (по ставкам) / `fewest` (меньше переводов); не задан — «по ставкам», в записи `room.created` поля нет; другое — 400 «Режим — «по ставкам» или «меньше переводов»». `pace` и `times` — темп комнаты (Р-35; ниже — «Темп комнаты»): нет обоих — обычный, в записи `room.created` полей нет; иначе — `checkPace` (кривой темп, чужой срок, сроки у обычного или быстрого, неполные сроки у «своего» — 400 с текстом правил), в записи — `pace`, у «своего» и `times`. `requestId` — номер запроса (ULID) от телефона: повтор с тем же номером — та же комната и тот же ответ; с другой формой (и другим режимом или темпом; обычный явно и без поля — одно и то же) — 409.
- `GET /rooms/<номер>` с заголовком `Authorization: Bearer <ключ>` → `{ room: { id, name, currency, hostId, createdAt, pace, times }, members: [{ id, name }], me, events, offers, settlement, now }`; `pace` и `times` — нынешний темп комнаты и его сроки (`logPace`, Р-35; ниже — «Темп комнаты»); `events` — события-пул по порядку создания (ниже), `offers` — пари по порядку создания (ниже, Р-22), `settlement` — свод расчёта (ниже, «Расчёт», Р-33), `now` — время сервера в ответе (UTC, мс): по нему сайт считает отсчёт до закрытия приёма, а не по часам телефона. Нет ключа или ключ не участника — 403; нет комнаты — 404. Ключ заявки, которую ещё не впустили, — 403 «Ждём, пока ведущий впустит» с `join: "waiting"`; отклонённой — 403 «Ведущий отклонил заявку» с `join: "rejected"` (экран ожидания спрашивает раз в несколько секунд).

**Вход по ссылке** (Р-03). Ссылка-приглашение несёт номер комнаты и токен `invite`; токены — в теле запроса, не в адресе. Связь — запрос-ответ, ожидание — опросом раз в 5 секунд; WebSocket в этапе 2 не делаем (Р-18).

- `POST /rooms/<номер>/preview` — `{ invite }` → `{ name, hostName }`, больше ничего. Токен неверный, сменённый, нет комнаты — 403 «Ссылка недействительна — попросите новую у ведущего».
- `POST /rooms/<номер>/join` — `{ invite, name, requestId? }` → `{ memberId, key, join: "waiting" }`: ключ телефона, который откроет комнату, когда ведущий впустит; `memberId` — номер заявки, он же номер участника. Имя уже у участника или ждущей заявки (без учёта регистра) — 409 «Такое имя уже есть — добавьте букву»; имя пустое или длиннее 30 — 400. Повтор с тем же `requestId` — та же заявка и тот же ключ (`join` — её нынешнее состояние); тот же номер с другим именем — 409.
- `GET /rooms/<номер>/requests` — ведущему: ждущие заявки `{ requests: [{ id, name, at }] }`.
- `POST /rooms/<номер>/admit` и `/reject` — `{ request }`, ведущему → `{ member: { id, name } }` и `{ request }`. Повтор того же решения — тот же ответ без записи; обратное — 409 («Участник уже впущен», «Заявка уже отклонена»); нет заявки — 404.
- `POST /rooms/<номер>/invite` — ведущему: новая ссылка `{ invite }`; старая перестаёт работать, впущенные и поданные заявки не страдают.
- `POST /rooms/<номер>/device` — `{ member?, unlink? }` → `{ token, member, expiresAt }`: «ссылка для другого устройства», одноразовая, на 24 часа. Себе — любой участник; за другого — только ведущий. `unlink: true` — когда ссылкой воспользуются, прежние ключи участника и его неиспользованные ссылки гаснут (потерял телефон).
- `POST /rooms/<номер>/device/claim` — `{ token }` → `{ memberId, key }`: новый ключ того же участника. Второй раз, через сутки или чужой токен — 403 «Ссылка для другого устройства недействительна — попросите новую».
- Действия по ключу: нет ключа или ключ не участника — 403; не ведущий там, где нужен ведущий, — 403 «Это может только ведущий».

**События-пул** (этап 2; экраны — «События на сайте» ниже). Все адреса — по ключу участника (нет ключа или ключ не участника — 403); номер события — `id` его записи `event.created`; нет события — 404 «Нет такого события».

- `POST /rooms/<номер>/events` — `{ condition, check, outcomes?, closesAt, expectedAt, subject?, requestId? }` → `{ event: EventInfo }` (`id`, `at`, `authorId`, `condition`, `check`, `outcomes: [{ id, title }]`, `closesAt`, `expectedAt`, `subjectId`, `subjectRule` — действует ли правило предмета, Р-26: у нового события с предметом — `true`). Заводит любой участник. `outcomes` не задан или пуст — «Да» и «Нет»; свои — 2–6, каждый ≤ 40 знаков, и сервер добавляет последним «Другое (ничего из перечисленного)» (Р-16); номер исхода — «1», «2», … по порядку. Одинаковые варианты (без учёта регистра и пробелов по краям, «Другое» тоже) — 400. Условие и «как проверяем» — не пустые, ≤ 300 знаков. `closesAt` — «приём ставок до» (не включая), уже прошёл по времени сервера — 400; `expectedAt` — «исход ожидается к», раньше `closesAt` — 400. `subject` — предмет спора, участник комнаты (не участник — 400). В записи `event.created` — `times`: сроки нынешнего темпа комнаты (Р-35), у каждого нового события, и у обычного; в ответе на создание их нет. Повтор с тем же `requestId` — то же событие и тот же ответ, даже после срока; тот же номер с другой формой или от другого — 409.
- `POST /rooms/<номер>/events/<событие>/bets` — `{ outcome, amount, requestId? }` → `{ bet: { id, event, memberId, outcome, amount, at } }`. Любой участник, и автор, и предмет спора; несколько раз и на разные исходы; отменить нельзя. Предмет спора у события с `subjectRule` (Р-26) — только на «Да» (403 «Вы — предмет спора: ставить можно только на „Да“»), в событии со своими исходами — никак (403 «Вы — предмет спора: в событии со своими исходами вы не ставите»); у старых событий без признака — как прежде. `amount` — целое > 0 в минимальных единицах (иначе 400), банк события не выходит за безопасное целое (400). Ставка в момент или после `closesAt` по времени сервера в момент запроса — 409 «Приём ставок закрыт» (будильника нет: срок проверяется при каждом запросе, сервер лежал — всё равно закрыто); после досрочного предложения исхода (`propose` до `closesAt`, Р-27) — навсегда 409 «Приём закрыт: исход уже предложен», и после снятия предложения; свёртка журнала ставку после предложения не считает; отменённое событие — 409 «Событие отменено»; нет исхода — 400. Повтор с тем же `requestId` — та же ставка и тот же ответ (и после срока); тот же номер с другой суммой, исходом или от другого — 409.
- `POST /rooms/<номер>/events/<событие>/clarify` — `{ text }` (≤ 300 знаков) → `{ clarification: { id, at, text } }`. Только автор события (403 «Это может только автор события»); условие, «как проверяем» и исходы не меняются никогда.
- `POST /rooms/<номер>/events/<событие>/cancel` — `{ reason? }` → `{ cancelled: { at, by, reason } }`. Кто и когда — по `checkCancel` (Р-29; «Отменить событие» в «Крайних случаях» Архитектуры), исход — с делом суда (`eventOutcome`): «не вам» — 403 («Отменить может только автор события или ведущий», «Есть ставки других участников — отменить может только ведущий, с причиной», «Вы ставили в этом событии (или вы — предмет спора): …»); окончательный исход или суд — 409 («Исход окончательный — событие не отменить», «Решает суд — отменить может только суд», «Суд уже отменил событие — ставки возвращаются»); причина нужна (есть чужие ставки) и не дана — 400 «Нужна причина отмены»; причина ≤ 300 знаков. Уже отменено — та же отмена без новой записи. Отменённое ставок не принимает; ставки возвращаются.
- Событие в `GET /rooms/<номер>` (`EventView`): поля `EventInfo`, `times` — сроки события, закреплённые при создании (Р-35; у событий до темпа — обычный набор, `timesOf`), и `status` (`open` — приём идёт, `closed` — закрыт в срок или досрочным предложением, `cancelled` — отменено; на `now`), `closedAt` — миг досрочного закрытия приёма (первое предложение исхода до `closesAt`, Р-27; у прочих событий поля нет), `clarifications: [{ id, at, text }]`, `bets: [{ id, memberId, outcome, amount, at }]` по порядку журнала, `cancelled` (`{ at, by, reason }` или `null`), `refunds: [{ memberId, amount }]` — у отменённого каждому его сумма (`settlePool` «без игры»), иначе пусто, `outcome` — исход (ниже; не предложен — `null`). Номера запросов (`requestId`) — только в журнале сервера, сайту не отдаются.

**Исход события** (этап 2, Р-05, Р-17, Р-21; на сайте — «Исход» в «Событиях на сайте» ниже). Адреса — `POST /rooms/<номер>/events/<событие>/propose | object | agree | decide | vote`, по ключу участника, с `requestId?`: повтор с тем же номером — тот же ответ без второй записи (и после сроков); тот же номер с другим содержимым, от другого или к другому событию — 409 «Этот номер запроса уже занят другим действием». Нет события — 404; отменённое — 409 «Событие отменено». Сроки считаются в момент запроса по времени сервера — будильника нет.

- `propose` — `{ outcome }` → `{ proposal: { id, at, by, outcome } }`. Пока приём идёт — тоже можно, досрочно («Исход уже известен», Р-27): приём закрывается в миг предложения навсегда (`closedAt`), дальше — обычный путь. Предлагает автор события; предмет спора — никогда (403 «Предмет спора не объявляет исход»): если автор — предмет, предлагает ведущий; автор молчит срок молчания события после `expectedAt` (3 дня у обычного темпа, Р-35) — может и ведущий; ведущий завёл событие о себе (он и автор, и предмет) — любой участник, кроме него, первый предложивший (Р-19); остальным — 403 «Исход предлагает автор события, а если он молчит <срок> после «исход ожидается к» — ведущий» (срок — события, `proposerOnly`: «3 дня», в быстрой комнате — «12 ч»). Исход — один из исходов события (иначе 400). Второе предложение — 409 «Исход уже предложен»; предложение снято «ещё не известно» (ниже) — можно снова, по тем же правилам (первое после снятия — единственное).
- `object` — `{ reason }` (не пустая, ≤ 300 знаков, иначе 400) → `{ objection: { id, at, by, reason } }`. Только ставивший на событие (403), не предложивший (403 «Свой исход не оспаривают»), до `proposal.at` + срок возражения события (24 часа у обычного темпа, Р-35; не включая; позже — 409 «Срок возражения — <срок> — прошёл», срок — события, `objectionOver`: «сутки», в быстрой комнате — «2 ч»); от участника — одно (второе — 409 «Вы уже возразили»); согласившийся — 409 «Вы уже согласились»; исход уже утверждён (ведущим или согласием всех) — 409; предложение снято — 409 «Предложение снято: исход ещё не известен…». Нет предложения — 409.
- `agree` — `{}` → `{ agreement: { id, at, by } }` (Р-21). Только ставивший на событие (403 «Согласиться может только тот, кто ставил»), не предложивший (403 «Своё предложение не подтверждают»), до `proposal.at` + срок возражения события (позже — 409 «Срок возражения — <срок> — прошёл», как у `object`); от участника — одно (второе — 409 «Вы уже согласились»), не отзывается; возразивший — 409 «Вы уже возразили»; есть хоть одно возражение — 409 «Есть возражение — согласия больше не принимаются»; исход уже утверждён — 409. Нет предложения — 409.
- `decide` — `{ outcome }` → `{ decision: { id, at, by, outcome } }`. Только ведущий (403), только после возражения (409 «Возражений нет…»), только если ведущий не ставил и не предмет спора (иначе 403 — решает голосование); любой исход события, а по досрочному предложению (сделано до `closesAt`) — ещё и `"not-yet"` — «ещё не известно» (Р-27; у прочих — 400 «Нет такого исхода»): предложение снимается, приём остаётся закрытым; одно решение на предложение (второе — 409).
- `vote` — `{ outcome }` → `{ vote: { id, at, by, outcome } }`. Когда ведущий ставил или он предмет спора и есть возражение (иначе 409). Голосуют участники на миг первого возражения, кто не ставил и не предмет спора (остальным 403); один голос (второй — 409); голосование кончилось — 409 «Голосование закончено». По досрочному предложению можно голосовать и за `"not-yet"`: большинство за него — предложение снято.
- В `EventView.outcome` (`OutcomeView`): `status` — `proposed` (сутки на возражение), `disputed` (ждёт решения ведущего), `voting`, `court` (ждёт суда, этап 4; исход не утверждён), `approved`, `final`, `withdrawn` (досрочное предложение снято «ещё не известно» решением ведущего или большинством голосов: не утверждён, выплат нет, приём закрыт, исход предлагают снова — тогда `outcome` — уже о новом предложении; Р-27), `cancelled` (событие отменено на любом шаге, и после утверждения: выплат нет, `finalAt` — `null`, окончательным не станет и в «Расчёт» не идёт; `approved` остаётся тем, что было утверждено до отмены, или `null`; возврат — `refunds`, Р-19); `proposal`, `objectionUntil`, `objections`, `agreements` (`[{ id, at, by }]` — согласия ставивших, кроме предложившего, поданные до конца суток), `awaiting` (чьего согласия ещё ждём, пока статус `proposed`; иначе пусто), `decision`, `voters`, `votingUntil` (первое возражение + 72 часа; голосования нет — `null`), `votes`; `approved` — `{ outcome, at, how, by }`: `unopposed` — сам через сутки без возражения (`at` — конец суток, `by` — `null`), `host` — ведущим (`by` — ведущий), `vote` — голосованием (`at` — последний голос, если проголосовали все, или конец 72 часов), `agreed` — согласием всех ставивших до возражения (`at` — последнее согласие; кроме предложившего, никто не ставил — миг предложения; `by` — `null`; Р-21); `finalAt` — `approved.at` + 7 дней (апелляции — этап 4), у `agreed` — сам `approved.at`: окончательный сразу; с него статус `final` (событие отменено — `null`); `void` и `payouts: [{ memberId, staked, payout, net }]` — `settlePool` по утверждённому исходу (не утверждён или событие отменено — пусто). Голосование: побеждает исход с большинством поданных голосов; ничья, ни одного голоса за 72 часа или некому голосовать — `court`.

**Пари** (этап 3, Р-04, Р-22; правила — «Правила пари в коде» ниже; исход пари — ниже, Р-23; экраны — «Пари на сайте» ниже). Все адреса — `POST`, по ключу участника (нет ключа или ключ не участника — 403), с `requestId?`: повтор с тем же номером — тот же ответ без второй записи (и после сроков); тот же номер с другим содержимым, от другого или у другого действия — 409 «Этот номер запроса уже занят другим действием». Номер пари — `id` его записи `offer.created`; нет пари (или кривой номер) — 404 «Нет такого пари». Сроки — по времени сервера в момент запроса, будильника нет: «истекло» считается, не записывается. Отказы правил: «не вам» (своё, гарант, не адресат, не автор) — 403, «уже не то состояние» (принято, отозвано, закрыто встречным) — 409, срок «приём до» прошёл — 409 «Приём закрыт — срок «приём до» прошёл».

- `POST /rooms/<номер>/offers` — `{ condition, check, side?, odds: { a, b }, amount, to?, closesAt, expectedAt, guarantor?, noGuarantor?, subject?, requestId? }` → `{ offer: OfferInfo }` (`id`, `at`, `authorId`, `condition`, `check`, `side`, `odds`, `amount` — сумма автора, `takerAmount` — сумма соперника по кэфу, `to`, `closesAt`, `expectedAt`, `guarantorId`, `counterTo: null`, `subjectId` — о ком спор или `null`, Р-26; `guarantorRule` — правило гаранта, Р-31: у новых пари и встречных `true`, в записи `offer.created` — `guarantorRule: 1`; у пари до выкатки — `false`; в записи `offer.created` — `times`, сроки нынешнего темпа комнаты, Р-35: у всех новых пари, встречных тоже, и у обычного; в ответе на создание их нет). `subject` — о ком спор (`checkOfferSubject`, 400): участник; автор-предмет — только `side: yes`; адресат-предмет — только `side: no`; не гарант. Предлагает любой участник; форма — `checkOfferInput` (400 с текстом правил: кэф, сумма соперника меньше единицы, условие, сроки, сторона); адресат и гарант — `offerGuarantor` (400); `side` не задана — `yes`, `to` не задан — открытое, `guarantor` не задан — ведущий (ведущий — автор или адресат — 400 «Ведущий — сторона пари: выберите гаранта»). «Приём до» уже прошёл — 409; «исход к» раньше него — 400. **Без гаранта** (Р-36) — `noGuarantor: true` (без `guarantor`; вместе — 400 «„Без гаранта“ — тогда гаранта не выбирают»; не `true`/`false` — 400 «Гарант — участник комнаты, не автор и не адресат»): только если судить есть кому (`offerGuarantor`: адресное — хотя бы один участник, кроме автора, адресата и предмета; открытое — хотя бы двое, кроме автора и предмета), иначе 400 «Без гаранта судить некому — выберите гаранта». В записи `offer.created` — `guarantor: null`, в ответе — `guarantorId: null`; повтор с тем же `requestId` сверяет и это. **«Торг до …»** (Р-37; правила — «Торг» в «Правилах пари в коде» `02-Архитектура.md`) — `auction: { start, step? }` вместо `odds`: старт — наименьшая сумма соперника, шаг не задан — 10 % старта; `closesAt` — конец торга, `expectedAt` — не раньше конца + 30 минут. Форма и сроки — `checkOfferInput`, `checkOfferTimes` (400 с текстом правил: старт, шаг, адресат — «Торг — только открытое пари…», торг короче 10 минут или дольше 3 дней, «исход к» раньше конца + 30 минут); гарант и предмет — как у открытого. В записи `offer.created` — `auction: { start, step }` и `odds: { a: amount, b: start }`; у обычного пари поля нет. Ответ — `OfferInfo` с `auction: { start, step, latestEnd }`, `takerAmount` — старт. Повтор с тем же `requestId` сверяет и старт с шагом.
- `POST …/offers/<пари>/accept` — `{}` → `{ accepted: { id, at, by, offer }, offer: OfferInfo }` (суммы обеих сторон — в `offer`). `checkAccept`: адресное — только адресат (иначе 403 «Пари предложено другому участнику»), открытое — любой, кроме автора (403 «Своё пари не принимают») и гаранта (403); предмет спора — только если автор за «не сбудется» (403, Р-26; встречное — так же); второй принявший — 409 «Пари уже принято»; отозванное, закрытое встречным — 409; после «приём до» — 409 «Приём закрыт…».
- `POST …/offers/<пари>/revoke` — `{}` → `{ revoked: { id, at, by, offer } }`. Только автор (403 «Отозвать может только автор пари»), пока не принято (409 «Принятое пари не отзывают») и не закрыто встречным; уже отозвано — 409 «Пари отозвано».
- `POST …/offers/<пари>/counter` — `{ odds?, amount?, closesAt, guarantor?, noGuarantor?, requestId? }` → `{ offer: OfferInfo }` — новое пари с `counterTo` (`counterInput`): свои кэф и/или сумма (не заданы — исходного) и «приём до» (нет — 400 «Нужен срок «приём до»»); условие, «как проверяем», «исход к» — исходного; сторона — обратная; адресат — автор исходного; гарант — выбор автора встречного (Р-36): `guarantor` — участник, `noGuarantor: true` — без гаранта, те же проверки и отказы, что у предложения (`offerGuarantor`, 400); ни того ни другого — гарант исходного (у исходного без гаранта — тоже без). Делает тот, кто мог бы принять исходное (`checkCounter`: своё, гарант, не адресат — 403; принятое, отозванное, закрытое — 409; после «приём до» — 409 «Приём закрыт…»); форма встречного — `checkOfferInput` (400); его «приём до» прошёл — 409, позже «исход к» исходного — 400. Автор исходного принял встречное — исходное закрыто встречным (`roomOffers`).
- **Торг** (Р-37) — к пари в торге `accept` и `counter` — 409 («Пари в торге не принимают — перебейте лучшее встречное», «К пари в торге встречных пари нет…»), `revoke` — только пока нет встречных (409 «Встречные уже есть — торг не отозвать»). Конец торга записи не даёт: по времени сервера в момент запроса торг кончился со встречным — пари принято лучшим в миг конца (`offerAt`), без встречных — «не состоялось». Сервер берёт пари «на сейчас» (`offerAt`) и для отметок, отзыва, суда по «ждёт суда» и апелляции: соперник торга — сторона, в суд он не попадает.
  - `POST …/offers/<пари>/bid` — `{ amount, requestId? }` → `{ bid: { id, at, by, offer, amount }, offer: OfferInfo }` (в `offer` — условия после встречного: `takerAmount` — лучшее). `amount` — сколько ставит против суммы автора: целое > 0 (иначе 400 «Встречное — сумма: целое число больше нуля»), банк — точное целое (400). `checkBid`: автор (403 «Против своего пари не торгуются»), гарант (403 «Гарант не торгуется»), предмет спора при стороне автора «сбудется» (403) — нет; первое меньше старта — 409 «Первое встречное — не меньше старта», следующее меньше лучшего + шаг — 409 «Встречное — больше лучшего хотя бы на шаг» (409: лучшее могли перебить, пока телефон отправлял); свою перебить можно; торг кончился (конец с продлениями, принят, «не состоялось») — 409 «Торг закончен»; отозван — 409; не торг — 409 «Это пари не в торге». Запись `offer.bid`; продление — свёрткой: встречное за 2 минуты до конца переносит конец на 2 минуты после себя, не дальше исходного конца + 30 минут. Повтор — то же встречное (`offer` — нынешние условия); тот же номер с другой суммой или от другого — 409.
  - `POST …/offers/<пари>/bid/accept` — `{}` или пусто → `{ taken: { id, at, by, offer, bid }, offer: OfferInfo }` — «принять сейчас»: `bid` — какое встречное принято. `checkTakeBid`: только автор (403 «Принять лучшее может только автор пари»), пока торг идёт (409 «Торг закончен»), есть встречные (409 «Встречных ещё нет — принимать нечего»). Запись `offer.bid-accepted`; пари принято лучшим, дальше — обычный путь: отметки, гарант, суд.
- Пари в `GET /rooms/<номер>` (`offers`, `OfferView`): поля `OfferInfo`, `times` — сроки пари, закреплённые при создании (Р-35; у пари до темпа — обычный набор), и `status` на `now` — `open` (открыто), `accepted` (принято), `withdrawn` (отозвано), `expired` (истекло), `countered` (закрыто встречным), `failed` (торг «не состоялся», Р-37); `accepted` (`{ by, at }` — кто принял, или `null`), `withdrawnAt` (или `null`), `closedBy` (`{ offer, at }` — каким встречным закрыто, или `null`), `outcome` — исход (ниже; не принято — `null`). У пари в торге — ещё `auction: { start, step, latestEnd }` и `bidding` (`biddingView` на `now`): `bids` (`{ id, at, by, amount }` по порядку), `best`, `endsAt` — конец с продлениями, `result` — `{ how: "now" | "end", at, bid }` (принято «принять сейчас» или к концу), `{ how: "failed", at }` или `null` (идёт или отозван); `takerAmount` — принятое, лучшее или старт; после конца торга — обычное пари с этими суммами. Видят все участники, адресные тоже — тайных пари нет. Номера запросов сайту не отдаются.

**Исход пари** (этап 3, Р-05, Р-06, Р-23; правила — «Исход» в «Правилах пари в коде» ниже; экран — «Исход пари» в «Пари на сайте»). Адреса — `POST /rooms/<номер>/offers/<пари>/mark | decide | decline | nominate`, по ключу участника, с `requestId?` — повтор и отказы как у пари выше: «не вам» — 403, «уже не то состояние» — 409, кривое тело — 400, нет пари — 404. Фазы считаются в момент запроса по времени сервера — будильника нет.

- `mark` — `{ winner: "author" | "taker" }` (иначе 400 «Отметка — «прав автор» или «прав соперник»») → `{ marked: { id, at, by, offer, winner } }`. `checkMark`: только сторона принятого пари (гарант — 403 «Гарант не отмечает исход как сторона…», не сторона — 403 «Это могут только стороны пари»); не принято — 409; утверждён согласием или гарант решил — 409. Поменять можно до решения гаранта; та же отметка, что действует, — ответ прежней записью, новой нет. Отметки совпали — исход утверждён согласием и окончательный сразу.
- `decide` — `{ winner }` → `{ decided: { id, at, by, offer, winner } }`. `checkDecide`: только нынешний гарант (403 «Это может только гарант пари»); стороны ещё отмечают (не разошлись и 3 дня после первой отметки — а не отметил никто, после «исход к» — не прошли; Р-27; с правилом гаранта, Р-31, — до «исход к» и при расхождении, молчание — 3 дня с первой отметки или «исход к», что позже) — 409; 3 дня гаранта прошли или он отказался — 409 «Гарант не решил в срок или отказался…». Окончательный через 7 дней.
- `decline` — `{}` → `{ declined: { id, at, by, offer } }`. `checkDecline`: только нынешний гарант (403), пока исход не утверждён (409) и другой гарант ещё не нужен (409). Дальше — «нужен другой гарант».
- `nominate` — `{ guarantor }` → `{ nominated: { id, at, by, offer, guarantor } }`. `checkNominate`: только сторона (403), только когда нужен другой гарант (иначе 409 «Гарант на месте…»); кандидат — участник комнаты, не сторона (иначе 400) и не предмет спора (Р-26, иначе 400 «Предмет спора не бывает гарантом…»). Обе стороны назвали одного — он гарант, его 3 дня — с назначения.
- Суд по пари собран (Р-31, Р-36; ниже — «Суд по «ждёт суда»») — `mark`, `decide`, `decline`, `nominate` — 409 «Пари решает суд — назвать гаранта и отметить исход уже нельзя». Суд не собран (судить некому) — назвать гаранта можно, как раньше.
- Пари без гаранта (Р-36): `decide` и `decline` — 409 «У пари нет гаранта» (пока стороны его не назвали). Отметки совпали — окончательно сразу; разошлись или вторая сторона молчит срок молчания пари — с этого мига (`turnAt`) суд собирается сам при первом запросе (ниже); суд не собрать — `need-guarantor`, стороны называют гаранта через `nominate`, назвали одного — обычный путь с гарантом.
- В `OfferView.outcome` (`OfferOutcomeView`, `offerOutcome` на `now`): `phase` — `marking` (отмечают), `guarantor` (решает гарант), `need-guarantor` (нужен другой гарант), `court` (ждёт суда: суд по пари собран, Р-31), `approved` (утверждён гарантом), `final` (окончательный); `marks` — `{ author, taker }`, последняя отметка каждой стороны или `null`; `guarantorId` — нынешний гарант (без гаранта — `null`, Р-36); `turnAt` — с какого мига решает гарант (без гаранта — с какого мига дело у суда); `guarantorUntil` — до какого мига он решает (утверждено или гаранта нет — `null`); `needSince` — с какого мига нужен другой гарант (без гаранта — `turnAt`; или `null`); `nominations` — кого называют стороны (`{ author?, taker? }`); `approved` — `{ winner, at, how: "agreement" | "guarantor", by }` (согласием — `by: null`) или `null`; `finalAt` — с какого мига окончательный (или `null`).

**Апелляция и суд** (этап 4, Р-05, Р-24, Р-25; правила — «Правила апелляции в коде» ниже; экраны — «Апелляция и суд на сайте» ниже). Адреса — `POST /rooms/<номер>/events/<событие>/…` и `POST /rooms/<номер>/offers/<пари>/…` + `appeal | appeal/join | judge | replace`, по ключу участника, с `requestId?`: повтор с тем же номером — тот же ответ без второй записи (и после сроков и решения суда); тот же номер у другого действия, спора, содержимого или от другого — 409 «Этот номер запроса уже занят другим действием». Нет события — 404 «Нет такого события», нет пари (и номер события по адресу пари) — 404 «Нет такого пари». Отказы — тексты правил: «не вам» (не ставивший, согласившийся, не сторона, своя апелляция, не член суда, не ведущий, ведущий заинтересован, себя) — 403; кривое тело (причина, голос, кого заменить) — 400; «уже не то состояние» — 409. Сроки — по времени сервера в момент запроса, будильника нет.

- `appeal` — `{ reason }` (не пустая, ≤ 300 знаков, иначе 400) → `{ appeal: { id, at, by, target, reason, seed, candidates } }`. `checkAppeal`: у пула — ставивший, кроме согласившихся (403), у пари — сторона (403); исход утверждён (иначе 409 «Исход ещё не утверждён…»), не согласием (409) и не окончательный (7 дней прошли — 409); событие отменено — 409; одна на спор (вторая — 409 «Апелляция уже подана — присоединитесь к ней»); судить некому — 409. Суд собран в этот миг: зерно — 16 случайных байт сервера (`crypto.getRandomValues`, hex), `candidates` — `courtCandidates` на этот миг (без подавшего), оба — в той же записи журнала.
- `appeal/join` — `{}` → `{ joined: { id, at, by, target } }`. `checkJoin`: апелляции нет — 409; тот, кто мог бы подать (403), не подавший (403); второй раз и после решения суда — 409.
- `judge` — `{ verdict: "keep" | "change" | "cancel", outcome? | winner? }` → `{ voted: { id, at, by, target, verdict, outcome? | winner? } }`. У пула «изменить» — с `outcome` (исход события), у пари — с `winner` (`author` / `taker`); иначе 400. `checkCourtVote`: только член суда на своём месте (403), в его 72 часа (позже — 409), один раз (409 «Вы уже проголосовали…»); «оставить» без апелляции и «изменить» на тот же исход — 400; суд решил — 409. Суда нет — 409 «Суда по этому спору нет».
- `replace` — `{ member, reason }` (кого — не строка — 400 «Такого члена суда нет»; причина — не пустая, ≤ 300 знаков) → `{ replaced: { id, at, by, target, member, reason } }`. `checkReplace`: только ведущий (403), если сам не заинтересован (403); не себя (403); только член суда на месте (400), не проголосовавший (409), одна замена на место (409), до решения (409). Суда нет — 409.
- **Суд по «ждёт суда»** собирается сам: при первом запросе к комнате (`GET /rooms/<номер>` и любое действие, ещё до самого действия) после того, как исход пула перешёл в «ждёт суда» или стороны пари (с правилом гаранта, Р-31) срок молчания пари не сошлись на новом гаранте, а у пари без гаранта (Р-36) — разошлись или вторая сторона молчит (`drawDueCourts` перебирает события и пари; `checkCourtDraw`), сервер один раз дописывает `court.drawn` (`target` — событие или пари) — зерно, кандидаты на этот миг (у пари — без сторон и нынешнего гаранта); второй запрос второй записи не даёт. Кандидатов нет — записи нет: у пула исход остаётся «ждёт суда» (выход — отмена ведущим с причиной, Р-19), у пари — «нужен другой гарант» (стороны по-прежнему называют гаранта).
- В `GET /rooms/<номер>` у исхода пула (`OutcomeView`) и пари (`OfferOutcomeView`) — `appeal` и `court` по правилам на время сервера (`eventView` / `offerView` с делом суда из `logAppeals`): места, сроки, замены, голоса, решение; окончательность, выплаты пула и итог пари — с учётом суда. Суда нет — полей нет. Версия протокола — 3: старый сайт видит «обновите страницу», а не падает. С предметом спора (Р-26: `subjectRule` у события, `subjectId` у пари, `subject` в форме пари) — 4. С правилом гаранта (Р-31: `guarantorRule` у пари, фаза `court` у исхода пари) — 6. С пари без гаранта (Р-36: `guarantorId: null` у пари и исхода, `noGuarantor` в предложении и встречном, `guarantor` во встречном) — 7: сайт версии 6 на втором телефоне видит «обновите страницу». С торгом (Р-37: статус `failed`, `auction` и `bidding` у пари, `auction` в предложении, адреса `…/bid`, `…/bid/accept`) — 8: список статусов пари закрытый — старая копия сайта (версии 7) на втором телефоне видит «обновите страницу», а не падает.

**Расчёт** (этап 5, Р-32, Р-33; правила — «Правила расчёта в коде» в `02-Архитектура.md`; экраны «Расчёт» и «История» — следующие задачи этапа). Все адреса — `POST`, по ключу участника (нет ключа — 403 «Нет доступа: нужен ключ телефона», ключ не участника — 403, заявка — 403 с `join`), с `requestId?`: повтор с тем же номером — тот же ответ без второй записи; тот же номер у другого действия (любой записи журнала комнаты), перевода, содержимого или от другого — 409 «Этот номер запроса уже занят другим действием». Номер перевода — `id` записи, которой он заведён; нет перевода (или кривой номер) — 404 «Такого перевода нет». Отказы — тексты правил `settle.ts`: «не вам» (не получатель, чужая отметка, не ведущий) — 403; кривое тело (кому, сумма, сам себе, режим) — 400; «уже не то состояние» и комната на очки — 409 («В комнате на очки переводов нет»).

- `POST /rooms/<номер>/transfers` — `{ to, amount }` — «Перевёл» (должник), или `{ from, amount }` — «Получил» сам, без «Перевёл» (получатель) → `{ transfer: TransferView }`. Одно из `to` / `from` — иначе 400 «Укажите одно: кому перевели или от кого получили»; сумма — целое > 0 (400), долгом не ограничена; `checkSend` / `checkReceive`: другой участник комнаты (400 «Перевод — только между участниками комнаты»), не сам себе (400 «Себе не переводят»). Запись `transfer.sent` / `transfer.received` с `from`; перевод — «ждёт подтверждения» / «получен».
- `POST …/transfers/<перевод>/receive` — «Получил» на «Перевёл», `…/reject` — «Не получал» (`checkAnswer`: только получатель — 403, только пока ждёт подтверждения — 409); `…/cancel` — отмена своей отметки (`checkRevoke`: должник — своё «Перевёл», пока не подтверждено, подтверждённое — 409; получатель — своё «Получил»: подтверждённый «Перевёл» снова ждёт, прямое — отменено; отметить «Получил» не успел — 409; чужая — 403). Тело — `{ requestId? }` или пусто → `{ transfer: TransferView }`. Записи `transfer.received` с `transfer`, `transfer.rejected`, `transfer.revoked`.
- `TransferView` (в ответе — перевод, каким он стал; повтор — каким он сейчас): `{ id, at, from, to, amount, by: "sender" | "receiver", status: "pending" | "received" | "rejected" | "cancelled", changedAt }`.
- `POST /rooms/<номер>/settle-mode` — `{ mode: "stakes" | "fewest", requestId? }` → `{ settleMode: { id, at, by, mode } }`. Режим — иначе 400; `checkSettleMode` на свод в нынешнем режиме: только ведущий (403 «Режим «кто кому» меняет только ведущий»), тот же режим — 409, есть переводы «ждёт подтверждения» / «получен» и не все балансы ноль или перевод ждёт подтверждения — 409, комната на очки — 409. Запись `room.settle-mode`; режим комнаты из журнала — `logSettleMode`: при создании, дальше — смены, каждая проверена на своё место в журнале.
- Свод в `GET /rooms/<номер>` (`settlement`, `SettlementView`; `roomSettlement` на `now` ответа, в режиме комнаты; видят все участники): `mode`; `members` — по порядку входа: `memberId`, три числа `total` / `pending` / `inPlay` (каждое `{ amount, events, offers }`), `sent`, `received`, `balance`; `transfers` — по порядку заведения (`TransferView`); `suggestions` — «кто кому» `[{ from, to, amount }]`. В комнате на очки три числа есть, переводов и подсказки нет. Не хранится — считается из журнала при каждом ответе. Поле необязательное: сайт до этапа 5 его не читает, сайт этапа 5 без него (сервер до выкатки) не ломается — версия протокола та же, 6.

**Темп комнаты** (Р-35; правила — `pace.ts`, «Темп комнаты» в `02-Архитектура.md`). Темп — при создании (`POST /rooms` выше), дальше — смены ведущим; нынешний темп из журнала — `logPace` (смена действует, если её разрешает `checkPaceChange` на её место в журнале). Новый темп — только для новых событий и пари: их сроки закрепляются при создании полем `times` записи и потом не меняются.

- `POST /rooms/<номер>/pace` — `{ pace: "normal" | "fast" | "custom", times?, requestId? }`, по ключу участника → `{ pace: { id, at, by, pace, times } }` (`times` в ответе — всегда, сроки темпа). Форма — `checkPace`, до комнаты: кривой темп, чужой срок, сроки у обычного или быстрого, неполные у «своего» — 400 с текстом правил. `checkPaceChange`: только ведущий (403 «Темп комнаты меняет только ведущий»), в любой момент; тот же темп с теми же сроками — 409 «Этот темп уже выбран». Запись `room.pace` (`pace`, у «своего» — `times`, `requestId`). Повтор с тем же `requestId` — тот же ответ без второй записи; тот же номер у другого действия, темпа или от другого — 409 «Этот номер запроса уже занят другим действием».
- Темп и сроки в `GET /rooms/<номер>` — `room.pace`, `room.times`; у каждого события и пари — его `times`. Поля только добавлены: старый сайт их не читает, сайт с темпом без них (сервер до выкатки) не ломается — версия протокола та же, 6.

**Копия комнаты** (этап 6, Р-02, Р-34; формат и `checkBackup` — «Резерв сервера» в `02-Архитектура.md`). Пароль компании — в заголовке `Authorization: Password <пароль в base64 из UTF-8>` (кириллицу заголовок как есть не несёт; `printf %s "$ROOM_PASSWORD" | base64`); ключ участника — `Authorization: Bearer <ключ>`, как у чтения. Пароль на сервере не задан — 503 «Выгрузка и загрузка комнат выключены» (как у создания); неверный, пустой, кривой base64 или его нет — 403 «Неверный пароль компании». Пароль проверяется до всего остального. Версия протокола не поднята: существующие ответы не меняются, адреса только добавлены.

- `GET /export` с паролем → `{ v, exportedAt, backups: [полная копия…] }` — все комнаты сервера: на Cloudflare — по реестру комнат, на Node — по своей базе; номер без комнаты пропускается. Копии собирает `collectBackups` (`server/src/backup.ts`) — та же, что у суточной копии в репо данных: та кладёт массив `backups` файлом `rooms.json` (`02-Архитектура.md`, «Резерв сервера», п. 2); новых адресов у суточной копии нет.
- `GET /rooms/<номер>/export` — с паролем → полная копия `{ v, format, roomId, exportedAt, log, store }`; с ключом участника → копия участника `{ v, format, roomId, exportedAt, log }` (без `store`). Тело ответа годится для загрузки как есть. Ключ не участника — 403, заявки — 403 с `join`, без ключа — 403 «Нет доступа: нужен ключ телефона»; нет комнаты (и кривой номер) — 404. Выгрузка ничего не пишет: суд по «ждёт суда» не собирает.
- `POST /rooms/<номер>/import` с паролем, тело — полная копия → `{ v, roomId, entries }` (сколько записей журнала загружено). Копия — `checkBackup`: битая — 400 с текстом правила, комната не тронута; копия участника — 400 «Это копия участника — для загрузки нужна полная копия»; номер в адресе и в копии разный — 400 «Копия другой комнаты…»; кривой номер — 404. Только в пустую комнату: в хранилище есть хоть одна запись — 409 «Комната уже есть — загрузка только в пустую». Служебные записи пишутся как есть, потом журнал по порядку (Р-11) — та же комната отвечает тем же ключам тем же. Версию протокола тела (`v`) не сверяет: копию старого сервера тоже грузит. Будильников у комнат пока нет — ставить после загрузки нечего. На Cloudflare загруженная комната сразу встаёт в реестр.

**Хранилище комнаты** (`RoomStorage`): `log:00000001…` — журнал, запись по ключу не меняется; `key:<SHA-256 ключа>` → номер участника или заявки (ключа в открытом виде нет; отвязанный помечен `unlinkedAt`); `invite` — токен приглашения; `secret` — секрет комнаты, заводится при первой заявке; `device:<SHA-256 токена>` → чья ссылка, `unlink`, `expiresAt`, `usedAt` / `revokedAt`; `registry` → `{ at }` — комната отмечена в реестре комнат (только Cloudflare; в копию не идёт). **Реестр комнат** (Cloudflare, объект `Registry`): `room:<номер>` → `{ roomId, createdAt }`, пишется один раз. Номер комнаты и ключ ведущего выводятся из `requestId` и пароля компании (HMAC-SHA-256): повтор создания отдаёт тот же ключ, не храня его; `requestId` на сервере не хранится (Р-13). Так же ключ по заявке — HMAC секретом комнаты из `requestId` заявки: повтор заявки отдаёт тот же ключ.
