# Архитектура — сервер: адреса и хранилище

Часть документа устройства (`docs/02-Архитектура.md`, Р-28): запросы и ответы сервера комнат и его хранилище. Читать, когда задача трогает `server/`, `src/api.ts` или протокол; описание изменённого адреса — сюда (шаг 5 исполнителя). Модель, правила и крайние случаи — в `02-Архитектура.md`; экраны — в `02-Сайт.md`.

**Адреса сервера.** Ответ — JSON с `v` (версия протокола); отказ — `{ v, error }` с текстом для человека.

- `POST /rooms` — `{ password, name, currency, hostName, requestId? }` → `{ roomId, invite, memberId, key }`. Пароль на сервере не задан — 503 «Создание комнат выключено»; пароль неверный или пустой — 403 «Неверный пароль компании»; форма с ошибкой — 400. `requestId` — номер запроса (ULID) от телефона: повтор с тем же номером — та же комната и тот же ответ; с другой формой — 409.
- `GET /rooms/<номер>` с заголовком `Authorization: Bearer <ключ>` → `{ room: { id, name, currency, hostId, createdAt }, members: [{ id, name }], me, events, offers, now }`; `events` — события-пул по порядку создания (ниже), `offers` — пари по порядку создания (ниже, Р-22), `now` — время сервера в ответе (UTC, мс): по нему сайт считает отсчёт до закрытия приёма, а не по часам телефона. Нет ключа или ключ не участника — 403; нет комнаты — 404. Ключ заявки, которую ещё не впустили, — 403 «Ждём, пока ведущий впустит» с `join: "waiting"`; отклонённой — 403 «Ведущий отклонил заявку» с `join: "rejected"` (экран ожидания спрашивает раз в несколько секунд).

**Вход по ссылке** (Р-03). Ссылка-приглашение несёт номер комнаты и токен `invite`; токены — в теле запроса, не в адресе. Связь — запрос-ответ, ожидание — опросом раз в 5 секунд; WebSocket в этапе 2 не делаем (Р-18).

- `POST /rooms/<номер>/preview` — `{ invite }` → `{ name, hostName }`, больше ничего. Токен неверный, сменённый, нет комнаты — 403 «Ссылка недействительна — попросите новую у ведущего».
- `POST /rooms/<номер>/join` — `{ invite, name, requestId? }` → `{ memberId, key, join: "waiting" }`: ключ телефона, который откроет комнату, когда ведущий впустит; `memberId` — номер заявки, он же номер участника. Имя уже у участника или ждущей заявки (без учёта регистра) — 409 «Такое имя уже есть — добавьте букву»; имя пустое или длиннее 30 — 400. Повтор с тем же `requestId` — та же заявка и тот же ключ (`join` — её нынешнее состояние); тот же номер с другим именем — 409.
- `GET /rooms/<номер>/requests` — ведущему: ждущие заявки `{ requests: [{ id, name, at }] }`.
- `POST /rooms/<номер>/admit` и `/reject` — `{ request }`, ведущему → `{ member: { id, name } }` и `{ request }`. Повтор того же решения — тот же ответ без записи; обратное — 409 («Участник уже впущен», «Заявка уже отклонена»); нет заявки — 404.
- `POST /rooms/<номер>/invite` — ведущему: новая ссылка `{ invite }`; старая перестаёт работать, впущенные и поданные заявки не страдают.
- `POST /rooms/<номер>/device` — `{ member?, unlink? }` → `{ token, member, expiresAt }`: «ссылка для другого устройства», одноразовая, на 24 часа. Себе — любой участник; за другого — только ведущий. `unlink: true` — когда ссылкой воспользуются, прежние ключи участника и его неиспользованные ссылки гаснут (потерял телефон).
- `POST /rooms/<номер>/device/claim` — `{ token }` → `{ memberId, key }`: новый ключ того же участника. Второй раз, через сутки или чужой токен — 403 «Ссылка для другого устройства недействительна — попросите новую».
- Действия по ключу: нет ключа или ключ не участника — 403; не ведущий там, где нужен ведущий, — 403 «Это может только ведущий».

**События-пул** (этап 2; экраны — «События на сайте» ниже). Все адреса — по ключу участника (нет ключа или ключ не участника — 403); номер события — `id` его записи `event.created`; нет события — 404 «Нет такого события».

- `POST /rooms/<номер>/events` — `{ condition, check, outcomes?, closesAt, expectedAt, subject?, requestId? }` → `{ event: EventInfo }` (`id`, `at`, `authorId`, `condition`, `check`, `outcomes: [{ id, title }]`, `closesAt`, `expectedAt`, `subjectId`, `subjectRule` — действует ли правило предмета, Р-26: у нового события с предметом — `true`). Заводит любой участник. `outcomes` не задан или пуст — «Да» и «Нет»; свои — 2–6, каждый ≤ 40 знаков, и сервер добавляет последним «Другое (ничего из перечисленного)» (Р-16); номер исхода — «1», «2», … по порядку. Одинаковые варианты (без учёта регистра и пробелов по краям, «Другое» тоже) — 400. Условие и «как проверяем» — не пустые, ≤ 300 знаков. `closesAt` — «приём ставок до» (не включая), уже прошёл по времени сервера — 400; `expectedAt` — «исход ожидается к», раньше `closesAt` — 400. `subject` — предмет спора, участник комнаты (не участник — 400). Повтор с тем же `requestId` — то же событие и тот же ответ, даже после срока; тот же номер с другой формой или от другого — 409.
- `POST /rooms/<номер>/events/<событие>/bets` — `{ outcome, amount, requestId? }` → `{ bet: { id, event, memberId, outcome, amount, at } }`. Любой участник, и автор, и предмет спора; несколько раз и на разные исходы; отменить нельзя. Предмет спора у события с `subjectRule` (Р-26) — только на «Да» (403 «Вы — предмет спора: ставить можно только на „Да“»), в событии со своими исходами — никак (403 «Вы — предмет спора: в событии со своими исходами вы не ставите»); у старых событий без признака — как прежде. `amount` — целое > 0 в минимальных единицах (иначе 400), банк события не выходит за безопасное целое (400). Ставка в момент или после `closesAt` по времени сервера в момент запроса — 409 «Приём ставок закрыт» (будильника нет: срок проверяется при каждом запросе, сервер лежал — всё равно закрыто); после досрочного предложения исхода (`propose` до `closesAt`, Р-27) — навсегда 409 «Приём закрыт: исход уже предложен», и после снятия предложения; свёртка журнала ставку после предложения не считает; отменённое событие — 409 «Событие отменено»; нет исхода — 400. Повтор с тем же `requestId` — та же ставка и тот же ответ (и после срока); тот же номер с другой суммой, исходом или от другого — 409.
- `POST /rooms/<номер>/events/<событие>/clarify` — `{ text }` (≤ 300 знаков) → `{ clarification: { id, at, text } }`. Только автор события (403 «Это может только автор события»); условие, «как проверяем» и исходы не меняются никогда.
- `POST /rooms/<номер>/events/<событие>/cancel` — `{ reason? }` → `{ cancelled: { at, by, reason } }`. Пока приём идёт — только автор, причина по желанию; после закрытия — только ведущий (403 «Это может только ведущий») и только с причиной ≤ 300 знаков (400 «Нужна причина отмены»). Уже отменено — та же отмена без новой записи. Отменённое ставок не принимает; ставки возвращаются.
- Событие в `GET /rooms/<номер>` (`EventView`): поля `EventInfo` и `status` (`open` — приём идёт, `closed` — закрыт в срок или досрочным предложением, `cancelled` — отменено; на `now`), `closedAt` — миг досрочного закрытия приёма (первое предложение исхода до `closesAt`, Р-27; у прочих событий поля нет), `clarifications: [{ id, at, text }]`, `bets: [{ id, memberId, outcome, amount, at }]` по порядку журнала, `cancelled` (`{ at, by, reason }` или `null`), `refunds: [{ memberId, amount }]` — у отменённого каждому его сумма (`settlePool` «без игры»), иначе пусто, `outcome` — исход (ниже; не предложен — `null`). Номера запросов (`requestId`) — только в журнале сервера, сайту не отдаются.

**Исход события** (этап 2, Р-05, Р-17, Р-21; на сайте — «Исход» в «Событиях на сайте» ниже). Адреса — `POST /rooms/<номер>/events/<событие>/propose | object | agree | decide | vote`, по ключу участника, с `requestId?`: повтор с тем же номером — тот же ответ без второй записи (и после сроков); тот же номер с другим содержимым, от другого или к другому событию — 409 «Этот номер запроса уже занят другим действием». Нет события — 404; отменённое — 409 «Событие отменено». Сроки считаются в момент запроса по времени сервера — будильника нет.

- `propose` — `{ outcome }` → `{ proposal: { id, at, by, outcome } }`. Пока приём идёт — тоже можно, досрочно («Исход уже известен», Р-27): приём закрывается в миг предложения навсегда (`closedAt`), дальше — обычный путь. Предлагает автор события; предмет спора — никогда (403 «Предмет спора не объявляет исход»): если автор — предмет, предлагает ведущий; автор молчит 3 дня после `expectedAt` — может и ведущий; ведущий завёл событие о себе (он и автор, и предмет) — любой участник, кроме него, первый предложивший (Р-19); остальным — 403. Исход — один из исходов события (иначе 400). Второе предложение — 409 «Исход уже предложен»; предложение снято «ещё не известно» (ниже) — можно снова, по тем же правилам (первое после снятия — единственное).
- `object` — `{ reason }` (не пустая, ≤ 300 знаков, иначе 400) → `{ objection: { id, at, by, reason } }`. Только ставивший на событие (403), не предложивший (403 «Свой исход не оспаривают»), до `proposal.at` + 24 часа (не включая; позже — 409 «Сутки на возражение прошли»); от участника — одно (второе — 409 «Вы уже возразили»); согласившийся — 409 «Вы уже согласились»; исход уже утверждён (ведущим или согласием всех) — 409; предложение снято — 409 «Предложение снято: исход ещё не известен…». Нет предложения — 409.
- `agree` — `{}` → `{ agreement: { id, at, by } }` (Р-21). Только ставивший на событие (403 «Согласиться может только тот, кто ставил»), не предложивший (403 «Своё предложение не подтверждают»), до `proposal.at` + 24 часа (позже — 409 «Сутки на возражение прошли»); от участника — одно (второе — 409 «Вы уже согласились»), не отзывается; возразивший — 409 «Вы уже возразили»; есть хоть одно возражение — 409 «Есть возражение — согласия больше не принимаются»; исход уже утверждён — 409. Нет предложения — 409.
- `decide` — `{ outcome }` → `{ decision: { id, at, by, outcome } }`. Только ведущий (403), только после возражения (409 «Возражений нет…»), только если ведущий не ставил и не предмет спора (иначе 403 — решает голосование); любой исход события, а по досрочному предложению (сделано до `closesAt`) — ещё и `"not-yet"` — «ещё не известно» (Р-27; у прочих — 400 «Нет такого исхода»): предложение снимается, приём остаётся закрытым; одно решение на предложение (второе — 409).
- `vote` — `{ outcome }` → `{ vote: { id, at, by, outcome } }`. Когда ведущий ставил или он предмет спора и есть возражение (иначе 409). Голосуют участники на миг первого возражения, кто не ставил и не предмет спора (остальным 403); один голос (второй — 409); голосование кончилось — 409 «Голосование закончено». По досрочному предложению можно голосовать и за `"not-yet"`: большинство за него — предложение снято.
- В `EventView.outcome` (`OutcomeView`): `status` — `proposed` (сутки на возражение), `disputed` (ждёт решения ведущего), `voting`, `court` (ждёт суда, этап 4; исход не утверждён), `approved`, `final`, `withdrawn` (досрочное предложение снято «ещё не известно» решением ведущего или большинством голосов: не утверждён, выплат нет, приём закрыт, исход предлагают снова — тогда `outcome` — уже о новом предложении; Р-27), `cancelled` (событие отменено на любом шаге, и после утверждения: выплат нет, `finalAt` — `null`, окончательным не станет и в «Расчёт» не идёт; `approved` остаётся тем, что было утверждено до отмены, или `null`; возврат — `refunds`, Р-19); `proposal`, `objectionUntil`, `objections`, `agreements` (`[{ id, at, by }]` — согласия ставивших, кроме предложившего, поданные до конца суток), `awaiting` (чьего согласия ещё ждём, пока статус `proposed`; иначе пусто), `decision`, `voters`, `votingUntil` (первое возражение + 72 часа; голосования нет — `null`), `votes`; `approved` — `{ outcome, at, how, by }`: `unopposed` — сам через сутки без возражения (`at` — конец суток, `by` — `null`), `host` — ведущим (`by` — ведущий), `vote` — голосованием (`at` — последний голос, если проголосовали все, или конец 72 часов), `agreed` — согласием всех ставивших до возражения (`at` — последнее согласие; кроме предложившего, никто не ставил — миг предложения; `by` — `null`; Р-21); `finalAt` — `approved.at` + 7 дней (апелляции — этап 4), у `agreed` — сам `approved.at`: окончательный сразу; с него статус `final` (событие отменено — `null`); `void` и `payouts: [{ memberId, staked, payout, net }]` — `settlePool` по утверждённому исходу (не утверждён или событие отменено — пусто). Голосование: побеждает исход с большинством поданных голосов; ничья, ни одного голоса за 72 часа или некому голосовать — `court`.

**Пари** (этап 3, Р-04, Р-22; правила — «Правила пари в коде» ниже; исход пари — ниже, Р-23; экраны — «Пари на сайте» ниже). Все адреса — `POST`, по ключу участника (нет ключа или ключ не участника — 403), с `requestId?`: повтор с тем же номером — тот же ответ без второй записи (и после сроков); тот же номер с другим содержимым, от другого или у другого действия — 409 «Этот номер запроса уже занят другим действием». Номер пари — `id` его записи `offer.created`; нет пари (или кривой номер) — 404 «Нет такого пари». Сроки — по времени сервера в момент запроса, будильника нет: «истекло» считается, не записывается. Отказы правил: «не вам» (своё, гарант, не адресат, не автор) — 403, «уже не то состояние» (принято, отозвано, закрыто встречным) — 409, срок «приём до» прошёл — 409 «Приём закрыт — срок «приём до» прошёл».

- `POST /rooms/<номер>/offers` — `{ condition, check, side?, odds: { a, b }, amount, to?, closesAt, expectedAt, guarantor?, subject?, requestId? }` → `{ offer: OfferInfo }` (`id`, `at`, `authorId`, `condition`, `check`, `side`, `odds`, `amount` — сумма автора, `takerAmount` — сумма соперника по кэфу, `to`, `closesAt`, `expectedAt`, `guarantorId`, `counterTo: null`, `subjectId` — о ком спор или `null`, Р-26). `subject` — о ком спор (`checkOfferSubject`, 400): участник; автор-предмет — только `side: yes`; адресат-предмет — только `side: no`; не гарант. Предлагает любой участник; форма — `checkOfferInput` (400 с текстом правил: кэф, сумма соперника меньше единицы, условие, сроки, сторона); адресат и гарант — `offerGuarantor` (400); `side` не задана — `yes`, `to` не задан — открытое, `guarantor` не задан — ведущий (ведущий — автор или адресат — 400 «Ведущий — сторона пари: выберите гаранта»). «Приём до» уже прошёл — 409; «исход к» раньше него — 400.
- `POST …/offers/<пари>/accept` — `{}` → `{ accepted: { id, at, by, offer }, offer: OfferInfo }` (суммы обеих сторон — в `offer`). `checkAccept`: адресное — только адресат (иначе 403 «Пари предложено другому участнику»), открытое — любой, кроме автора (403 «Своё пари не принимают») и гаранта (403); предмет спора — только если автор за «не сбудется» (403, Р-26; встречное — так же); второй принявший — 409 «Пари уже принято»; отозванное, закрытое встречным — 409; после «приём до» — 409 «Приём закрыт…».
- `POST …/offers/<пари>/revoke` — `{}` → `{ revoked: { id, at, by, offer } }`. Только автор (403 «Отозвать может только автор пари»), пока не принято (409 «Принятое пари не отзывают») и не закрыто встречным; уже отозвано — 409 «Пари отозвано».
- `POST …/offers/<пари>/counter` — `{ odds?, amount?, closesAt, requestId? }` → `{ offer: OfferInfo }` — новое пари с `counterTo` (`counterInput`): свои кэф и/или сумма (не заданы — исходного) и «приём до» (нет — 400 «Нужен срок «приём до»»); условие, «как проверяем», «исход к» — исходного; сторона — обратная; адресат — автор исходного; гарант — тот же. Делает тот, кто мог бы принять исходное (`checkCounter`: своё, гарант, не адресат — 403; принятое, отозванное, закрытое — 409; после «приём до» — 409 «Приём закрыт…»); форма встречного — `checkOfferInput` (400); его «приём до» прошёл — 409, позже «исход к» исходного — 400. Автор исходного принял встречное — исходное закрыто встречным (`roomOffers`).
- Пари в `GET /rooms/<номер>` (`offers`, `OfferView`): поля `OfferInfo` и `status` на `now` — `open` (открыто), `accepted` (принято), `withdrawn` (отозвано), `expired` (истекло), `countered` (закрыто встречным); `accepted` (`{ by, at }` — кто принял, или `null`), `withdrawnAt` (или `null`), `closedBy` (`{ offer, at }` — каким встречным закрыто, или `null`), `outcome` — исход (ниже; не принято — `null`). Видят все участники, адресные тоже — тайных пари нет. Номера запросов сайту не отдаются.

**Исход пари** (этап 3, Р-05, Р-06, Р-23; правила — «Исход» в «Правилах пари в коде» ниже; экран — «Исход пари» в «Пари на сайте»). Адреса — `POST /rooms/<номер>/offers/<пари>/mark | decide | decline | nominate`, по ключу участника, с `requestId?` — повтор и отказы как у пари выше: «не вам» — 403, «уже не то состояние» — 409, кривое тело — 400, нет пари — 404. Фазы считаются в момент запроса по времени сервера — будильника нет.

- `mark` — `{ winner: "author" | "taker" }` (иначе 400 «Отметка — «прав автор» или «прав соперник»») → `{ marked: { id, at, by, offer, winner } }`. `checkMark`: только сторона принятого пари (гарант — 403 «Гарант не отмечает исход как сторона…», не сторона — 403 «Это могут только стороны пари»); не принято — 409; утверждён согласием или гарант решил — 409. Поменять можно до решения гаранта; та же отметка, что действует, — ответ прежней записью, новой нет. Отметки совпали — исход утверждён согласием и окончательный сразу.
- `decide` — `{ winner }` → `{ decided: { id, at, by, offer, winner } }`. `checkDecide`: только нынешний гарант (403 «Это может только гарант пари»); стороны ещё отмечают (не разошлись и 3 дня после первой отметки — а не отметил никто, после «исход к» — не прошли; Р-27) — 409; 3 дня гаранта прошли или он отказался — 409 «Гарант не решил за 3 дня или отказался…». Окончательный через 7 дней.
- `decline` — `{}` → `{ declined: { id, at, by, offer } }`. `checkDecline`: только нынешний гарант (403), пока исход не утверждён (409) и другой гарант ещё не нужен (409). Дальше — «нужен другой гарант».
- `nominate` — `{ guarantor }` → `{ nominated: { id, at, by, offer, guarantor } }`. `checkNominate`: только сторона (403), только когда нужен другой гарант (иначе 409 «Гарант на месте…»); кандидат — участник комнаты, не сторона (иначе 400) и не предмет спора (Р-26, иначе 400 «Предмет спора не бывает гарантом…»). Обе стороны назвали одного — он гарант, его 3 дня — с назначения.
- В `OfferView.outcome` (`OfferOutcomeView`, `offerOutcome` на `now`): `phase` — `marking` (отмечают), `guarantor` (решает гарант), `need-guarantor` (нужен другой гарант), `approved` (утверждён гарантом), `final` (окончательный); `marks` — `{ author, taker }`, последняя отметка каждой стороны или `null`; `guarantorId` — нынешний гарант; `turnAt` — с какого мига решает гарант; `guarantorUntil` — до какого мига он решает (утверждено — `null`); `needSince` — с какого мига нужен другой гарант (или `null`); `nominations` — кого называют стороны (`{ author?, taker? }`); `approved` — `{ winner, at, how: "agreement" | "guarantor", by }` (согласием — `by: null`) или `null`; `finalAt` — с какого мига окончательный (или `null`).

**Апелляция и суд** (этап 4, Р-05, Р-24, Р-25; правила — «Правила апелляции в коде» ниже; экраны — «Апелляция и суд на сайте» ниже). Адреса — `POST /rooms/<номер>/events/<событие>/…` и `POST /rooms/<номер>/offers/<пари>/…` + `appeal | appeal/join | judge | replace`, по ключу участника, с `requestId?`: повтор с тем же номером — тот же ответ без второй записи (и после сроков и решения суда); тот же номер у другого действия, спора, содержимого или от другого — 409 «Этот номер запроса уже занят другим действием». Нет события — 404 «Нет такого события», нет пари (и номер события по адресу пари) — 404 «Нет такого пари». Отказы — тексты правил: «не вам» (не ставивший, согласившийся, не сторона, своя апелляция, не член суда, не ведущий, ведущий заинтересован, себя) — 403; кривое тело (причина, голос, кого заменить) — 400; «уже не то состояние» — 409. Сроки — по времени сервера в момент запроса, будильника нет.

- `appeal` — `{ reason }` (не пустая, ≤ 300 знаков, иначе 400) → `{ appeal: { id, at, by, target, reason, seed, candidates } }`. `checkAppeal`: у пула — ставивший, кроме согласившихся (403), у пари — сторона (403); исход утверждён (иначе 409 «Исход ещё не утверждён…»), не согласием (409) и не окончательный (7 дней прошли — 409); событие отменено — 409; одна на спор (вторая — 409 «Апелляция уже подана — присоединитесь к ней»); судить некому — 409. Суд собран в этот миг: зерно — 16 случайных байт сервера (`crypto.getRandomValues`, hex), `candidates` — `courtCandidates` на этот миг (без подавшего), оба — в той же записи журнала.
- `appeal/join` — `{}` → `{ joined: { id, at, by, target } }`. `checkJoin`: апелляции нет — 409; тот, кто мог бы подать (403), не подавший (403); второй раз и после решения суда — 409.
- `judge` — `{ verdict: "keep" | "change" | "cancel", outcome? | winner? }` → `{ voted: { id, at, by, target, verdict, outcome? | winner? } }`. У пула «изменить» — с `outcome` (исход события), у пари — с `winner` (`author` / `taker`); иначе 400. `checkCourtVote`: только член суда на своём месте (403), в его 72 часа (позже — 409), один раз (409 «Вы уже проголосовали…»); «оставить» без апелляции и «изменить» на тот же исход — 400; суд решил — 409. Суда нет — 409 «Суда по этому спору нет».
- `replace` — `{ member, reason }` (кого — не строка — 400 «Такого члена суда нет»; причина — не пустая, ≤ 300 знаков) → `{ replaced: { id, at, by, target, member, reason } }`. `checkReplace`: только ведущий (403), если сам не заинтересован (403); не себя (403); только член суда на месте (400), не проголосовавший (409), одна замена на место (409), до решения (409). Суда нет — 409.
- **Суд по «ждёт суда»** собирается сам: при первом запросе к комнате (`GET /rooms/<номер>` и любое действие, ещё до самого действия) после того, как исход пула перешёл в «ждёт суда», сервер один раз дописывает `court.drawn` — зерно, кандидаты на этот миг; второй запрос второй записи не даёт. Кандидатов нет — записи нет, исход остаётся «ждёт суда» (выход — отмена ведущим с причиной, Р-19).
- В `GET /rooms/<номер>` у исхода пула (`OutcomeView`) и пари (`OfferOutcomeView`) — `appeal` и `court` по правилам на время сервера (`eventView` / `offerView` с делом суда из `logAppeals`): места, сроки, замены, голоса, решение; окончательность, выплаты пула и итог пари — с учётом суда. Суда нет — полей нет. Версия протокола — 3: старый сайт видит «обновите страницу», а не падает. С предметом спора (Р-26: `subjectRule` у события, `subjectId` у пари, `subject` в форме пари) — 4.

**Хранилище комнаты** (`RoomStorage`): `log:00000001…` — журнал, запись по ключу не меняется; `key:<SHA-256 ключа>` → номер участника или заявки (ключа в открытом виде нет; отвязанный помечен `unlinkedAt`); `invite` — токен приглашения; `secret` — секрет комнаты, заводится при первой заявке; `device:<SHA-256 токена>` → чья ссылка, `unlink`, `expiresAt`, `usedAt` / `revokedAt`. Номер комнаты и ключ ведущего выводятся из `requestId` и пароля компании (HMAC-SHA-256): повтор создания отдаёт тот же ключ, не храня его; `requestId` на сервере не хранится (Р-13). Так же ключ по заявке — HMAC секретом комнаты из `requestId` заявки: повтор заявки отдаёт тот же ключ.
